## วัตถุประสงค์การเรียนรู้

เมื่อจบบทนี้ คุณควรจะ

1. อธิบายว่าทำไมต้องแบ่งเครือข่ายเป็นซับเน็ต (broadcast domain, การจัดการ, ความปลอดภัย, การจัดเส้นทาง)
2. แยกที่อยู่ IPv4 เป็นส่วน **network** กับ **host** ด้วย subnet mask และอธิบายการคำนวณ **IP AND mask** ระดับบิต
3. อธิบายว่าเครื่องใช้ผล AND ตัดสินใจ "ส่งตรงในซับเน็ตเดียวกัน" หรือ "ส่งให้ default gateway" อย่างไร
4. แปลงระหว่าง mask แบบจุด (`255.255.255.192`) กับ **CIDR** (`/26`) ได้ทั้งสองทิศทาง
5. คำนวณ network address, broadcast address, ช่วงใช้งาน และจำนวนโฮสต์ด้วย **2^h − 2** และเหตุผลที่ลบ 2
6. แบ่งบล็อกเป็นซับเน็ตเท่ากัน (FLSM) และขนาดไม่เท่ากัน (**VLSM**) และรวมเส้นทาง (**summarization**) ได้
7. วินิจฉัยปัญหาที่มาจาก mask ผิด และอธิบายประโยชน์ด้าน Security ของการแบ่งส่วนเครือข่าย

## เปรียบเทียบกับชีวิตจริง

| สถานการณ์จริง | ซับเน็ต |
|---|---|
| หมู่บ้านจัดสรรใหญ่แบ่งเป็นซอย (ซอย 1, 2, 3 ...) | ซับเน็ต |
| บ้านเลขที่ 12 ในซอย 3 | host อยู่ในซับเน็ต |
| ตะโกนเรียกเพื่อนบ้านในซอยเดียวกันได้ แต่ซอยอื่นต้องส่งผ่านยามหน้าซอย | broadcast ไม่ข้ามซับเน็ต / ผ่านเกตเวย์ |
| ป้อมยามหน้าซอยจดว่าใครเข้าออก จำกัดได้ว่าใครเข้าซอยไหน | เราเตอร์/ไฟร์วอลล์ระหว่างซับเน็ต |
| บ้านเลขที่แรก (หัวซอย) เป็นป้ายชื่อซอย ท้ายสุดเป็นกระดิ่งประกาศทั้งซอย | network address / broadcast address |
| ซอยใหญ่ที่แบ่งเป็นซอยย่อยตามจำนวนบ้านที่จะสร้าง | VLSM |

## 1. ทำไมต้องแบ่ง: เครือข่ายเดียวขนาดใหญ่มีปัญหาอะไร

> **นึกภาพว่า:** ห้องประชุมใหญ่ห้องเดียวที่คนหมื่นคนอยู่รวมกัน ใครตะโกนถามหาใครทุกคนต้องได้ยินและหยุดฟัง งานไม่เดิน ทางแก้คือแบ่งเป็นห้องย่อยตามแผนก ตะโกนในห้องไหนได้ยินเฉพาะห้องนั้น และมีประตูคุม (เราเตอร์) ระหว่างห้อง
>
> ห้อง = ซับเน็ต (subnet) เสียงตะโกนถึงทุกคนในห้อง = broadcast

ลองนึกถึงเครือข่าย `10.0.0.0/8` แบบก้อนเดียว ไม่แบ่งส่วน มีเครื่องได้ถึงราว 16.7 ล้านเครื่อง ปัญหา:

1. **Broadcast ท่วม:** บริการอย่าง ARP และ DHCP ใช้ broadcast ที่ทุกเครื่องในเซกเมนต์ต้องรับและประมวลผล ยิ่งเครื่องมาก broadcast ยิ่งมาก และสวิตช์ต้อง flood ไปทุกพอร์ต ซับเน็ตจำกัดขอบเขตนี้ (เรียกว่า **broadcast domain**) เพราะเราเตอร์ไม่ส่งต่อ broadcast
2. **ตารางเส้นทางบวม:** ถ้าทุกเครื่องเป็นรายการของตัวเอง เราเตอร์ต้องจำรายเครื่อง การแบ่งเป็นก้อนทำให้เราเตอร์จำแค่ "ก้อนไหนไปทางไหน"
3. **ควบคุมไม่ได้:** กฎความปลอดภัยแบบ "ฝ่ายบัญชีเข้าได้ แขกเข้าไม่ได้" ทำได้ต่อเมื่อสองกลุ่มอยู่คนละซับเน็ต แล้วมีเราเตอร์/ไฟร์วอลล์คั่น
4. **วิเคราะห์ปัญหายาก:** เครือข่ายก้อนเดียวหาจุดเสียยาก ซับเน็ตแยกตามชั้น/แผนกช่วยจำกัดวงปัญหา (ดู divide and conquer ในบทระเบียบวิธีแก้ปัญหา)

## 2. กายวิภาคของที่อยู่: Network + Host

> **นึกภาพว่า:** เบอร์โทร 02-123-4567 แบ่งเป็น "รหัสพื้นที่" (02) กับ "เลขเครื่อง" (1234567) ที่อยู่ IP ก็เป็นสองส่วนเหมือนกัน แต่เส้นแบ่งไม่ได้อยู่ที่ตำแหน่งตายตัว /26 บอกว่า "26 บิตแรกคือรหัสพื้นที่ ที่เหลือคือเลขเครื่อง"
>
> ```
> 11000000.10101000.00001010.01 | 001101
> |<------ network 26 บิต ---->|  |host 6 บิต|
> ```
>
> network = รหัสพื้นที่ host = เลขเครื่อง

ที่อยู่ IPv4 `192.168.10.77` เขียนเป็นไบนารีได้ดังนี้

```
192      .168      .10       .77
11000000 .10101000 .00001010 .01001101
```

ถ้าซับเน็ตนี้ใช้ mask `255.255.255.192` (`/26`) บิต 26 บิตแรกคือ network ส่วน 6 บิตท้ายคือ host

```
11000000.10101000.00001010.01 | 001101
└──────── network (26 bit) ───┘  └ host (6 bit)
```

**ลองเอง:** ปรับ IP และ prefix ในเครื่องมือนี้ ดูบิต network (ตัวหนา) กับ host (ตัวจาง) ว่าเลื่อนอย่างไรเมื่อเปลี่ยน prefix และดูผลการ AND กับ IP ปลายทางว่าไปทางตรงหรือผ่านเกตเวย์

### 2.1 Subnet mask ทำงานอย่างไร: การ AND ระดับบิต

> **นึกภาพว่า:** mask คือแผ่นสติกเกอร์ที่เจาะรู วางทับตัวเลข ช่องที่เป็น 1 คือรูโปร่ง เห็นเลขข้างล่าง ช่องที่เป็น 0 คือทึบ ปิดเป็น 0 หมด ผลที่เห็นคือส่วน network
>
> ```
> IP    ...01001101   (77)
> mask  ...11000000   (192)
> ผล    ...01000000   (64)    <- เห็นแค่ 2 บิตแรก ที่เหลือถูกปิด
> ```
>
> การ AND = วางแผ่นปิดทับ

mask คือเลข 32 บิตที่ **1 เรียงชิดซ้ายต่อกัน ตามด้วย 0 ทั้งหมด** (ไม่มี 1 โผล่หลัง 0) เครื่องนำ IP มาทำ bitwise AND กับ mask ผลคือ network address

```
IP        192.168.10.77   11000000.10101000.00001010.01001101
mask      255.255.255.192 11111111.11111111.11111111.11000000
AND  ───────────────────────────────────────────────────────
network   192.168.10.64   11000000.10101000.00001010.01000000
```

กฎ AND: 1 AND 1 = 1 นอกนั้น = 0 บิตที่ mask เป็น 0 ถูก "ล้าง" เป็น 0 บิตที่ mask เป็น 1 ถูก "คงไว้" ผลจึงเหลือเฉพาะส่วน network

mask ที่เป็นไปได้ต่อ octet มีเพียง 9 ค่า เพราะต้องเป็น 1 ชิดซ้าย: `0, 128, 192, 224, 240, 248, 252, 254, 255` (= 0, 1, 2, ... 8 บิตที่เป็น 1) ค่าอื่นเช่น 255 ตามด้วย 100 เป็น mask ที่ไม่ถูกต้อง

| Mask | ไบนารี | CIDR | ที่อยู่ทั้งหมด | ใช้ได้ |
|---|---|---|---|---|
| `255.0.0.0` | `11111111.00000000.00000000.00000000` | `/8` | 16,777,216 | 16,777,214 |
| `255.255.0.0` | `11111111.11111111.00000000.00000000` | `/16` | 65,536 | 65,534 |
| `255.255.240.0` | `11111111.11111111.11110000.00000000` | `/20` | 4,096 | 4,094 |
| `255.255.255.0` | `11111111.11111111.11111111.00000000` | `/24` | 256 | 254 |
| `255.255.255.128` | `11111111.11111111.11111111.10000000` | `/25` | 128 | 126 |
| `255.255.255.192` | `11111111.11111111.11111111.11000000` | `/26` | 64 | 62 |
| `255.255.255.224` | `11111111.11111111.11111111.11100000` | `/27` | 32 | 30 |
| `255.255.255.252` | `11111111.11111111.11111111.11111100` | `/30` | 4 | 2 |

### 2.2 เครื่องใช้ mask ตัดสินอะไรจริงๆ: ส่งตรงหรือผ่านเกตเวย์

> **นึกภาพว่า:** อยู่ห้อง 64–127 ของตึก อยากส่งของให้ห้องข้างๆ ก็เดินไปให้เอง ถ้าเป็นห้องอื่นก็ฝากพนักงานหน้าลิฟต์ (gateway) วิธีรู้ว่าห้องไหนห้องเรา: เอา mask ปิดทับเลขห้องปลายทาง ถ้าผลเท่ากับห้องเรา แปลว่าห้องเดียวกัน
>
> ```
> เรา .77  -> 64      ปลายทาง .100 -> 64   เท่ากัน   -> ส่งตรง
>                     ปลายทาง .200 -> 192  ต่างกัน  -> ส่งผ่าน gateway
> ```

ทุกครั้งที่ส่งแพ็กเก็ต เครื่องต้องตอบคำถามเดียว: **"ปลายทางอยู่ในซับเน็ตเดียวกับฉันหรือไม่"** โดยคำนวณ

> (IP ปลายทาง AND mask ของฉัน) = (IP ของฉัน AND mask ของฉัน) ?

- **เท่ากัน (on-link):** ปลายทางอยู่บนสายเดียวกัน ถาม ARP ว่า "IP นี้ MAC อะไร" แล้วส่งเฟรมตรงไปหา
- **ไม่เท่ากัน:** ไม่รู้จะไปทางไหน ส่งให้ **default gateway** โดย ARP หา MAC ของ *เกตเวย์* (ไม่ใช่ MAC ของปลายทาง) แล้วให้เราเตอร์ส่งต่อ

**ข้อสังเกตสำคัญ:** การตัดสินนี้เกิดที่ **เครื่องผู้ส่ง** ตาม mask ที่เครื่องนั้นตั้งไว้เอง ถ้า mask ผิด เครื่องจะตัดสินผิด (ดูหัวข้อวินิจฉัย)

## 3. CIDR: ทำไมเลิกใช้คลาส

> **นึกภาพว่า:** สมัยก่อนร้านเช่าที่มีขนาดเดียว 3 ขนาด คือ เล็ก (254 คน) กลาง ใหญ่ (65,534 คน) ต้องเช่าคนเดียว 300 คน ก็ต้องเช่าห้องใหญ่ทั้งชั้นเสียที่ว่างเกือบทั้งหมด CIDR คือเปลี่ยนเป็นพื้นที่ตัดขนาดได้ทุกระดับ เช่น 510 ที่ (/23) พอดีกับ 300 คน

ยุคแรก IPv4 แบ่งคลาสตายตัวตามบิตแรก: Class A `/8`, Class B `/16`, Class C `/24` องค์กรต้องเลือกขนาดสามแบบ ถ้าต้องการ 300 เครื่อง Class C (254) ไม่พอ ต้องขอ Class B (65,534) เสียที่อยู่เกือบทั้งก้อน ขณะที่ตารางเส้นทางบนอินเทอร์เน็ตก็บวมเพราะแต่ละก้อนเป็นหนึ่งรายการ

ปี 1993 จึงเลิกคลาสแล้วใช้ **CIDR (Classless Inter-Domain Routing)** ที่ prefix ยาวเท่าไรก็ได้ 0–32 บิต ทำให้

1. **แจกพอดีความต้องการ:** 300 เครื่องใช้ `/23` (510 เครื่อง) ไม่ต้องเสียทั้ง `/16`
2. **รวมเส้นทางได้ (route aggregation):** หลาย prefix ต่อเนื่องกันรวมเป็นรายการเดียว (หัวข้อ 7)
3. เขียนสั้น: `192.168.10.0/26` แทนที่ต้องเขียน IP กับ mask คู่กัน

**แปลง mask ↔ CIDR:** นับจำนวนบิต 1 ใน mask เช่น `255.255.255.192` = 8+8+8+2 = **/26** ส่วนทางกลับ `/26` → 26 บิตเป็น 1: octet แรกสามตัวเต็ม (255) เหลือ 2 บิตใน octet ที่สี่ = `11000000` = 128 + 64 = **192**

## 4. คำนวณ: broadcast, ช่วงใช้งาน และทำไมลบ 2

> **นึกภาพว่า:** หอพัก 64 ห้อง เลขห้อง 64–127 ห้องแรก (64) เป็นป้ายชื่อตึกเอง ไม่ใช่ห้องพัก ห้องสุดท้าย (127) เป็นลำโพงประกาศถึงทุกห้อง ไม่ใช่ห้องพักเช่นกัน
>
> ```
> 64 (ชื่อตึก)  65 ... 126 (ห้องพัก 62 ห้อง)  127 (ลำโพงประกาศ)
> ```
>
> network address = ป้ายชื่อตึก broadcast = ลำโพง

ทุกซับเน็ตมี 2^h ที่อยู่ (h = จำนวนบิต host) แต่ **สองที่อยู่ใช้ใส่ให้เครื่องไม่ได้**

| ที่อยู่ | host bits | หน้าที่ | ทำไมห้ามใช้กับเครื่อง |
|---|---|---|---|
| **Network address** | ทุกบิต = 0 | ชื่อของซับเน็ตเอง (ใช้ในตารางเส้นทาง) | ถ้าให้เครื่องใช้ จะแยก "ตัวซับเน็ต" ออกจาก "เครื่อง" ไม่ได้ |
| **Broadcast address** | ทุกบิต = 1 | ส่งหาทุกเครื่องในซับเน็ตพร้อมกัน | แพ็กเก็ตที่ส่งมาที่นี่ทุกเครื่องต้องรับ เครื่องเดียวไม่ควรแย่งใช้ |

ดังนั้น **เครื่องที่ใส่ได้ = 2^h − 2** ตัวอย่าง `/26`: h = 6 → 2⁶ = 64 → ใช้ได้ **62**

> **ข้อยกเว้นที่ต้องรู้:** `/31` (2 ที่อยู่) ใช้ได้ทั้งสองในลิงก์จุดต่อจุดตาม RFC 3021 (ไม่มี broadcast) และ `/32` คือเครื่องเดียว (ใช้ระบุ loopback ของเราเตอร์ หรือกฎเฉพาะเครื่อง) บริการคลาวด์บางเจ้าสงวนที่อยู่เพิ่มต่อซับเน็ต (เช่น AWS สงวน 5 ที่อยู่ต่อซับเน็ต: network, router, DNS, สงวนอนาคต, broadcast) จึงต้องอ่านเอกสารของแพลตฟอร์มนั้นด้วย

### 4.1 วิธีคิดด้วยมือ (block size)

> **นึกภาพว่า:** ตัดผ้าเป็นชิ้นยาวเท่ากัน แล้วดูว่าจุดที่สนใจอยู่ในชิ้นไหน
>
> ```
> /26 : ชิ้นละ 256 - 192 = 64
> ชิ้นเริ่มที่  0 | 64 | 128 | 192
> .77 อยู่ระหว่าง 64 กับ 128 -> network = .64
> broadcast = ชิ้นถัดไป (128) - 1 = .127
> ```

ไม่ต้องแปลงไบนารีทุกครั้ง ใช้ "ขนาดบล็อก" ใน octet ที่ mask เปลี่ยนค่า

::step-diagram{:steps='[{"title":"1. หา octet ที่น่าสนใจ","text":"ดู mask ว่า octet ไหนไม่ใช่ 255 หรือ 0 สำหรับ /26 (255.255.255.192) คือ octet ที่ 4 ค่า 192 ส่วน octet ก่อนหน้า (255) ใช้ตามเดิม"},{"title":"2. ขนาดบล็อก = 256 − ค่า mask ใน octet นั้น","text":"256 − 192 = 64 แปลว่า ซับเน็ตเริ่มที่ 0, 64, 128, 192 (ก้าวทีละ 64) นี่คือที่อยู่ network ของแต่ละก้อน"},{"title":"3. หา network ของ IP","text":"ถอยลงมาหาค่า network ที่ใหญ่สุดที่ไม่เกิน octet ของ IP เช่น .77 อยู่ระหว่าง 64 กับ 128 → network = 192.168.10.64"},{"title":"4. **ตัวอย่างตัดใน octet ที่ 3:** `172.16.5.9/20` → mask `255.255.240.0` ขนาดบล็อกใน octet ที่ 3 = 256 − 240 = 16 ซับเน็ตเริ่มที่ 0, 16, 32, ... octet ที่ 3 ของ IP = 5 → network = `172.16.0.0` broadcast = ถัดไป (16) − 1 → `172.16.15.255` ใช้ได้ 2¹² − 2 = **4,094** (ตรวจด้วยการคำนวณจริง)

## 5. แบ่งบล็อกเป็นซับเน็ต: ยืมบิตจาก host

> **นึกภาพว่า:** ที่ดินแปลงเดียว 256 ที่ ต้องการแบ่งให้ 4 แผนก ก็ปักเสาแบ่ง 3 เส้น ได้ 4 แปลง แปลงละ 64 ทุกครั้งที่ยืม 1 บิต ที่ดินแต่ละแปลงเหลือครึ่ง
>
> ```
> ยืม 0 บิต: 1 แปลง x 256
> ยืม 1 บิต: 2 แปลง x 128
> ยืม 2 บิต: 4 แปลง x  64   <- ใช้ /26
> ```

เมื่อต้องการแบ่งก้อนใหญ่เป็นหลายซับเน็ต เรา **ยืมบิตจากส่วน host มาเป็นบิต subnet** ยืม b บิต → ได้ 2^b ซับเน็ต และบิต host ที่เหลือลด b บิต ที่อยู่ต่อซับเน็ตจึงลดลง 2^b เท่า

**ลองเอง:** เลื่อนจำนวนบิตที่ยืม ดูจำนวนซับเน็ต ขนาดต่อก้อน และสัดส่วนที่อยู่ที่เสียไปกับ network/broadcast

::subnet-split
::

**ตัวอย่างจากต้นฉบับ:** แบ่ง `192.168.10.0/24` ให้ 4 แผนก

1. ต้องการ 4 ซับเน็ต: 2^b ≥ 4 → b = 2 → prefix ใหม่ `/24 + 2 = /26` (`255.255.255.192`)
2. ขนาดบล็อก = 256 − 192 = 64
3. ช่วงที่ได้

| แผนก | Network/prefix | Broadcast | ใส่ให้เครื่องได้ |
|---|---|---|---|
| Sales | `192.168.10.0/26` | `.63` | `.1` – `.62` |
| Engineering | `192.168.10.64/26` | `.127` | `.65` – `.126` |
| Support | `192.168.10.128/26` | `.191` | `.129` – `.190` |
| Finance | `192.168.10.192/26` | `.255` | `.193` – `.254` |

**ที่อยู่ที่เสีย:** 4 ซับเน็ต × 2 = 8 ที่อยู่ เมื่อเทียบ /24 เดียวที่เสีย 2 ที่อยู่ ใช้ได้ 254 → รวมเหลือ 4 × 62 = **248** เครื่อง (เสียราว 6 ตัว หรือ 3.1% เพิ่มจากเดิม) นี่คือราคาของการแยกส่วน

### 5.1 ปัญหาของการแบ่งเท่ากัน และ VLSM

> **นึกภาพว่า:** จัดห้องในออฟฟิศ ทีม 100 คน 50 คน 20 คน กับห้องเล็กสำหรับสายตรง 2 คน ถ้าทุกห้องกว้างเท่ากับห้อง 100 คน ห้องเล็กเสียที่เปล่า VLSM คือตัดห้องตามขนาดจริง เริ่มจากห้องใหญ่สุดก่อน เพื่อให้ขอบห้องวางลงล็อก
>
> ```
> .0   - .127   ขาย 100  (/25)
> .128 - .191   วิศวะ 50  (/26)
> .192 - .223   ซัพพอร์ต 20 (/27)
> .224 - .227   ลิงก์ 2   (/30)
> ```

การแบ่งแบบเท่ากันหมด (**FLSM**) เสียที่อยู่ถ้าความต้องการไม่เท่ากัน เช่น ฝ่ายขาย 100 เครื่อง วิศวกรรม 50 เครื่อง ซัพพอร์ต 20 เครื่อง และลิงก์เราเตอร์สองตัว (2 ที่อยู่) ถ้าแบ่งเท่ากันต้องใช้ /25 (126) ทั้งหมด จะกินพื้นที่มหาศาล

**VLSM (Variable Length Subnet Mask)** ให้แต่ละส่วนมี prefix ต่างกันตามขนาดจริง **วิธี:** เรียงจากต้องการมากไปน้อย แล้วจัดสรรต่อเนื่องกัน (ไม่ทับกัน)

| ส่วน | ต้องการ | เลือก prefix | (ใช้ได้) | Network | ช่วงเต็ม |
|---|---|---|---|---|---|
| ฝ่ายขาย | 100 | `/25` | 126 | `192.168.10.0/25` | .0 – .127 |
| วิศวกรรม | 50 | `/26` | 62 | `192.168.10.128/26` | .128 – .191 |
| ซัพพอร์ต | 20 | `/27` | 30 | `192.168.10.192/27` | .192 – .223 |
| ลิงก์เราเตอร์ | 2 | `/30` | 2 | `192.168.10.224/30` | .224 – .227 |

เหลือ `.228 – .255` (28 ที่อยู่) ไว้ขยายต่อ เทียบกับ FLSM แบบ /25 ทั้งหมดที่ใส่ 4 ส่วนไม่ได้ในก้อน /24 เดียวด้วยซ้ำ ข้อควรระวังคือการจัดสรร VLSM ต้อง **เริ่มจากก้อนใหญ่สุด** และจัดให้ network address ลงตามขอบของขนาดบล็อกเสมอ (เช่น /25 ต้องเริ่มที่ .0 หรือ .128 เท่านั้น)

## 6. ตัวอย่างที่ต้นฉบับถาม: ใส่ IP ไหนให้เครื่องพิมพ์ได้

> **นึกภาพว่า:** ซับเน็ต 10.0.0.64/26 คือตึกเลข 64–127 ก่อนตอบ ให้วาดเส้นตัวเลขแล้วขีดฆ่าสองปลาย (64 ป้ายตึก, 127 ลำโพง) และดูว่าเลขไหนตกนอกตึก (63 ของตึกก่อนหน้า)
>
> ```
> 63 | 64 [ป้าย] 65 ... 126 127 [ลำโพง] | 128
> ```

ซับเน็ต `10.0.0.64/26` ใช้กับเครื่องพิมพ์ ใส่ IP ใดได้

::reveal{question="เฉลย: 10.0.0.127, 10.0.0.64, 10.0.0.65 หรือ 10.0.0.63"}
**ตอบ `10.0.0.65`** เหตุผล: `/26` ขนาดบล็อก 64 ซับเน็ตนี้เริ่มที่ .64 สิ้นสุดที่ .127 · `10.0.0.64` คือ **network address** (host bits ทั้งหมด = 0) ใช้กับเครื่องไม่ได้ · `10.0.0.127` คือ **broadcast** (host bits ทั้งหมด = 1) ใช้ไม่ได้ · `10.0.0.63` ไม่ได้อยู่ในซับเน็ตนี้เลย แต่เป็น broadcast ของซับเน็ตก่อนหน้า (`10.0.0.0/26`) ถ้าใส่จะอยู่นอกซับเน็ตของเครื่องพิมพ์ ช่วงที่ใส่ได้คือ `.65` ถึง `.126` (ตรวจด้วยการคำนวณจริงแล้ว)
::

## 7. รวมเส้นทาง (Summarization) และทำไม CIDR ช่วยอินเทอร์เน็ต

> **นึกภาพว่า:** แทนที่จะบอกคนขับรถ "ถนนซอย 0 ซอย 1 ซอย 2 ซอย 3 ไปทางซ้าย" บอกว่า "ถนนซอย 0–3 ไปทางซ้าย" รายการเดียวแทนสี่รายการ
>
> ```
> 192.168.0.0/24 = 000000 00
> 192.168.1.0/24 = 000000 01      6 บิตแรกเหมือนกัน
> 192.168.2.0/24 = 000000 10      -> 16 + 6 = 22 บิตตรึง
> 192.168.3.0/24 = 000000 11      = 192.168.0.0/22 (1,024 ที่อยู่)
> ```
>
> เงื่อนไข: ต้องเรียงต่อกัน ไม่มีช่องว่าง และเริ่มตรงขอบ

เมื่อซับเน็ตต่อเนื่องกันและขอบตรงกับกำลังสอง เราเตอร์รวมประกาศเป็นรายการเดียวได้

| ซับเน็ต | ไบนารีของ octet ที่ 3 |
|---|---|
| `192.168.0.0/24` | `000000`**`00`** |
| `192.168.1.0/24` | `000000`**`01`** |
| `192.168.2.0/24` | `000000`**`10`** |
| `192.168.3.0/24` | `000000`**`11`** |

6 บิตแรกของ octet ที่ 3 เหมือนกันหมด (ค่าที่เปลี่ยนมีแค่ 2 บิตท้าย) → ตรึงได้ 16 + 6 = 22 บิต จึงรวมเป็น **`192.168.0.0/22`** (`255.255.252.0`) ครอบ 192.168.0.0 – 192.168.3.255 พอดี 1,024 ที่อยู่ (4 × 256) เราเตอร์ปลายทางจำ 1 รายการแทน 4

กฎ: รวมได้เมื่อ (1) จำนวนซับเน็ตเป็นกำลังสอง (2) เริ่มที่ขอบที่หารขนาดรวมลงตัว (3) ต่อเนื่องไม่มีช่องว่าง ถ้าไม่ตรงเงื่อนไขจะได้ก้อนใหญ่ที่ครอบที่อยู่ที่ไม่ใช่ของเรา ซึ่งอาจเกิดการส่งผิดทางได้

สำหรับอินเทอร์เน็ต ผลคือผู้ให้บริการประกาศก้อนใหญ่ก้อนเดียวให้ลูกค้าจำนวนมากแทนการประกาศทีละราย ลดขนาดตารางเส้นทางทั่วโลก

## 9. มุมมองด้าน Security

> **นึกภาพว่า:** ตึกที่ไม่มีผนังกั้นห้อง โจรเข้ามาได้ที่เดียวก็เดินทั่วตึก ซับเน็ตคือผนังกั้นห้อง ประตูแต่ละบาน (ไฟร์วอลล์) ตรวจก่อนเข้า ผลที่ได้: ความเสียหายจำกัดวง ไม่ใช่ว่าโจรเข้าไม่ได้เลย

| ประเด็น | กลไก | การป้องกัน |
|---|---|---|
| **เครือข่ายแบนราบ (flat network)** | ทุกเครื่องในซับเน็ตเดียวกันคุยกันตรงได้โดยไม่ผ่านจุดควบคุม ผู้โจมตีที่ยึดเครื่องหนึ่งสแกนและโจมตีเครื่องข้างเคียงต่อได้ (lateral movement) | แบ่งซับเน็ต/VLAN ตามหน้าที่ (ผู้ใช้, เซิร์ฟเวอร์, IoT, แขก, การจัดการ) แล้วใช้ ACL/ไฟร์วอลล์ระหว่างกัน แบบ default deny |
| **ขนาดซับเน็ตกับเวลาสแกน** | `/24` มี 254 โฮสต์ สแกนได้เร็วมาก `/16` มี 65,534 โฮสต์: ที่อัตราสมมติ 1,000 โฮสต์/วินาที ≈ 65.5 วินาที ต่างจาก /24 ที่ใช้เสี้ยววินาที แต่ผู้โจมตีที่มีเวลาก็สแกนได้ทั้งหมด (ค่าประมาณ) | ซับเน็ตเล็กลดพื้นที่ค้นหา แต่ไม่ใช่การป้องกันหลัก ต้องมีการเฝ้าดูและตรวจจับการสแกนภายใน |
| **ARP/DHCP spoofing จำกัดอยู่ในซับเน็ต** | โจมตีแบบ ARP spoofing และ rogue DHCP ใช้ broadcast ซึ่งไม่ข้ามเราเตอร์ ผลกระทบจึงจำกัดที่ซับเน็ตเดียว | ซับเน็ตเล็กลง จำกัดวงความเสียหาย; เปิด DHCP snooping, Dynamic ARP Inspection บนสวิตช์ |
| **IoT/แขกอยู่ซับเน็ตเดียวกับงานจริง** | อุปกรณ์ที่อัปเดตยากหรือไม่ไว้ใจเข้าถึงเครื่องสำคัญได้ตรงๆ | ซับเน็ต/VLAN แยกสำหรับ IoT และ guest, ให้ออกอินเทอร์เน็ตได้แต่เข้า LAN หลักไม่ได้ |
| **mask ผิดทำให้กฎความปลอดภัยเพี้ยน** | กฎไฟร์วอลล์ที่เขียนเป็น `192.168.10.0/24` จะอนุญาตทั้ง /24 ถ้าตั้งใจให้เป็น /26 กฎจะกว้างเกินที่ตั้งใจ และกฎที่เขียน /32 ผิดอาจปล่อยทั้งก้อน | ตรวจกฎด้วยการคำนวณช่วงจริง ใช้ prefix ที่แคบที่สุดที่จำเป็น (least privilege) ทบทวนกฎเป็นระยะ |
| **ลิงก์จุดต่อจุดใช้ /30 หรือ /31** | ใช้ /24 กับลิงก์ระหว่างเราเตอร์ 2 ตัว เปิดช่องให้อุปกรณ์อื่นเสียบเข้ามาแล้วใช้ที่อยู่ที่เหลือได้ | ใช้ /30 หรือ /31 ตามจำนวนอุปกรณ์จริง ปิดพอร์ตสวิตช์ที่ไม่ใช้ |
| **ที่อยู่ซ้อนกันเมื่อรวมเครือข่าย** | หลังควบรวมกิจการหรือต่อ VPN ช่วงซ้ำ ทำให้เส้นทางผิดหรือกฎไฟร์วอลล์ตรงผิดฝั่ง | วางแผนผังที่อยู่ (IPAM) ตั้งแต่ต้น ใช้บล็อกกว้างที่ไม่ใช่ค่าเริ่มต้นของเราเตอร์บ้าน |

**หลักคิด:** ซับเน็ตให้ "ขอบเขต" แต่การบังคับใช้ต้องมาจากอุปกรณ์ที่ควบคุมการข้ามขอบเขต (เราเตอร์/ไฟร์วอลล์ที่มีกฎ) ถ้าเราเตอร์ส่งผ่านทุกอย่างโดยไม่กรอง การแยกซับเน็ตก็ได้เพียงลด broadcast ไม่ได้ลดความเสี่ยง

## 12. ตรวจความเข้าใจ

::reveal{question="ข้อ 1: ทำไมที่อยู่แรกของทุกซับเน็ตจึงใส่ให้เครื่องไม่ได้"}
ที่อยู่แรก (host bits ทั้งหมดเป็น 0) คือ **network address** ที่ใช้เป็นชื่อของซับเน็ตเองในตารางเส้นทาง เช่น `192.168.10.64/26` หมายถึง "ก้อนนี้" ไม่ได้หมายถึงเครื่องใดเครื่องหนึ่ง ถ้าใช้กับเครื่อง จะแยกความหมาย "ทั้งซับเน็ต" ออกจาก "เครื่องนี้" ไม่ได้ เช่นกัน ที่อยู่สุดท้ายคือ broadcast
::

::reveal{question="ข้อ 2: เครื่องใช้ subnet mask ตัดสินว่าปลายทางอยู่ในเครือข่ายเดียวกันได้อย่างไร"}
เครื่องนำ IP ปลายทางมา AND กับ mask ของตัวเอง แล้วเทียบกับ (IP ตัวเอง AND mask) ถ้าเท่ากัน ปลายทางอยู่ซับเน็ตเดียวกัน ส่งตรงด้วย ARP หา MAC ปลายทาง ถ้าไม่เท่ากัน ส่งไปที่ default gateway โดยใช้ MAC ของเกตเวย์ (แต่ IP ปลายทางในแพ็กเก็ตยังเป็นของปลายทางจริง)
::

::reveal{question="ข้อ 3: /24 กับ /25 ต่างกันเรื่องจำนวนเครื่องอย่างไร"}
/24 มี 2⁸ = 256 ที่อยู่ ใช้ได้ 254 ส่วน /25 มี 2⁷ = 128 ที่อยู่ ใช้ได้ 126 เมื่อ prefix เพิ่มขึ้น 1 บิต ที่อยู่ลดลงครึ่งหนึ่ง และเสียสัดส่วนที่อยู่ให้ network/broadcast มากขึ้น (2/256 เทียบ 2/128)
::

::reveal{question="ข้อ 4: ทำไมวงการเลิกคลาสแล้วใช้ CIDR"}
คลาสตายตัวมีขนาดแค่ /8, /16, /24 ทำให้แจกที่อยู่ไม่พอดีความต้องการ (ต้องการ 300 เครื่องต้องขอ Class B ทั้งก้อน เสียหลายหมื่นที่อยู่) เร่งให้ IPv4 หมดเร็วขึ้น และทำให้ตารางเส้นทางบนอินเทอร์เน็ตบวม CIDR ให้ prefix ยาวได้ตามต้องการ (แจกพอดี) และรวมเส้นทางได้ (summarization) ลดทั้งการสูญเปล่าและขนาดตาราง
::

::reveal{question="ข้อ 5: เครื่อง 192.168.1.130/25 มีเกตเวย์ตั้งเป็น 192.168.1.1 จะเกิดอะไร"}
เครื่องอยู่ซับเน็ต `192.168.1.128/25` (.128 – .255) เกตเวย์ `.1` อยู่ในซับเน็ตอื่น (`192.168.1.0/25`) เครื่องจึงถือว่าเกตเวย์ "ไม่ on-link" และจะไม่ ARP หา ทำให้ส่งออกนอกซับเน็ตไม่ได้ ระบบมักปฏิเสธการตั้งค่านี้ หรือใช้งานไม่ได้ วิธีแก้คือตั้งเกตเวย์ให้อยู่ในซับเน็ตเดียวกัน เช่น `192.168.1.129` หรือแก้ mask
::

::reveal{question="ข้อ 6: ทำไมการแบ่งซับเน็ตจึงไม่ใช่การป้องกันด้วยตัวมันเอง"}
ซับเน็ตเพียงแยกขอบเขต broadcast และสร้างจุดที่ทราฟฟิกต้องข้าม ถ้าเราเตอร์ส่งผ่านทุกอย่างโดยไม่มีกฎ ผู้โจมตีข้ามซับเน็ตได้ปกติ การป้องกันมาจาก ACL/ไฟร์วอลล์ที่ขอบระหว่างซับเน็ต การเฝ้าดู และสิทธิ์น้อยที่สุด ซับเน็ตเป็นฐานให้กฎเหล่านั้นทำงานได้
::

::reveal{question="โจทย์ 1: 10.0.0.64/26 มี network, broadcast, ช่วงใช้งาน และจำนวนโฮสต์เท่าไร"}
ขนาดบล็อก = 256 − 192 = 64 · network = **10.0.0.64** · broadcast = 64 + 64 − 1 = **10.0.0.127** · ช่วงใช้งาน **10.0.0.65 – 10.0.0.126** · จำนวน 2⁶ − 2 = **62** (ตรวจด้วยการคำนวณจริง)
::

::reveal{question="โจทย์ 2: ต้องการ 50 เครื่องในซับเน็ตเดียว ควรเลือก prefix ใด และเหลือที่อยู่ว่างเท่าไร"}
ต้อง 2^h − 2 ≥ 50 → h = 6 ให้ 62 (h = 5 ให้แค่ 30 ไม่พอ) h = 6 แปลว่า prefix = 32 − 6 = **/26** เหลือว่าง 62 − 50 = **12 เครื่อง** สำหรับขยายตัว
::

::reveal{question="โจทย์ 3: 172.16.5.9/20 ได้ mask, network, broadcast และจำนวนเครื่องเท่าไร และ 172.16.17.1 อยู่ซับเน็ตเดียวกันหรือไม่"}
/20 → mask 255.255.240.0 · ขนาดบล็อกใน octet ที่ 3 = 16 · octet ที่ 3 = 5 อยู่ในบล็อก 0–15 → network **172.16.0.0** · broadcast **172.16.15.255** · จำนวนเครื่อง 2¹² − 2 = **4,094** · 172.16.17.1: octet ที่ 3 = 17 อยู่ในบล็อก 16–31 ซึ่งเป็นอีกซับเน็ต (172.16.16.0/20) จึง **ไม่อยู่ซับเน็ตเดียวกัน** ต้องผ่านเกตเวย์
::

::reveal{question="โจทย์ 4 (VLSM): จาก 192.168.20.0/24 ต้องการ ก) 60 เครื่อง ข) 25 เครื่อง ค) 10 เครื่อง ง) ลิงก์จุดต่อจุด 2 อัน จัดสรรอย่างไร"}
เรียงจากใหญ่ไปเล็ก · ก) 60 → 2⁶ − 2 = 62 → **/26** `192.168.20.0/26` (.0–.63) · ข) 25 → 2⁵ − 2 = 30 → **/27** `192.168.20.64/27` (.64–.95) · ค) 10 → 2⁴ − 2 = 14 → **/28** `192.168.20.96/28` (.96–.111) · ง) ลิงก์ละ 2 → **/30** `192.168.20.112/30` (.112–.115) และ `192.168.20.116/30` (.116–.119) · เหลือ .120–.255 ไว้ขยาย ขอบทุกก้อนอยู่ที่ขอบของขนาดบล็อกตัวเอง
::

::reveal{question="โจทย์ 5 (รวมเส้นทาง): 10.4.0.0/24, 10.4.1.0/24, 10.4.2.0/24, 10.4.3.0/24 รวมเป็น prefix เดียวได้หรือไม่ และ 10.4.1.0/24 ถึง 10.4.4.0/24 ล่ะ"}
ชุดแรก: octet ที่ 3 คือ 0–3 (`000000xx`) บิตที่เหมือนกันมี 6 บิต → 16 + 6 = 22 → รวมได้เป็น **10.4.0.0/22** ครอบ 10.4.0.0–10.4.3.255 พอดี · ชุดที่สอง: octet ที่ 3 คือ 1–4 ไม่เริ่มที่ขอบกำลังสอง (1 ไม่หารลงตัวด้วย 4) ค่า 1 (`001`) กับ 4 (`100`) ต่างกันตั้งแต่บิตสูงสุด รวมเป็นก้อนเดียวไม่ได้โดยไม่ครอบเกิน ต้องประกาศแยก เช่น 10.4.1.0/24, 10.4.2.0/23 (2–3), 10.4.4.0/24
::

## 13. แบบฝึกหัด (ลงมือทำจริง)

ใช้กับเครื่องของคุณเอง คำสั่งอ่านอย่างเดียว

1. **อ่าน mask ของเครื่องคุณ:** `ipconfig` (Windows) หรือ `ip -4 addr` (Linux) จด IP และ mask แปลงเป็น CIDR (นับบิต 1) แล้วคำนวณ network, broadcast และช่วงใช้งานด้วยมือ ตรวจกับ `subnet-calc` ด้านบน
2. **ตรวจว่าเกตเวย์อยู่ในซับเน็ตเดียวกัน:** คำนวณ (IP AND mask) ของเครื่องกับของ default gateway ต้องเท่ากัน
3. **ดูเส้นทางในเครื่อง:** `route print -4` (Windows) หรือ `ip route` (Linux) ชี้แถวที่เป็น on-link (ซับเน็ตของคุณ), default route และ loopback
4. **ตรวจด้วยเครื่องมือ:** ติดตั้ง/ใช้ `ipcalc IP/PREFIX` (Linux) หรือโมดูล `ipaddress` ของ Python เปลี่ยนค่าลองเทียบกับการคำนวณมือ
5. **ออกแบบผังที่อยู่:** สมมติสำนักงาน 4 ส่วน (ผู้ใช้ 80 เครื่อง, เซิร์ฟเวอร์ 20, Wi-Fi แขก 40, IoT 12) ใช้บล็อก `10.10.0.0/24` จัดแบบ VLSM แล้วคำนวณ prefix, ช่วง และที่อยู่ที่เหลือ
6. **ตรวจ ARP ใน on-link:** `arp -a` (Windows) หรือ `ip neigh` (Linux) ดูว่ามี IP ใดบ้างที่ถูก ARP ตรงๆ จะเป็นเครื่องในซับเน็ตเดียวกันและเกตเวย์เท่านั้น ไม่เห็นเครื่องบนอินเทอร์เน็ต

::reveal{question="แนวคำตอบข้อ 5"}
ลำดับใหญ่ไปเล็ก: ผู้ใช้ 80 → 2⁷ − 2 = 126 → `/25` `10.10.0.0/25` (.0–.127) · แขก 40 → 2⁶ − 2 = 62 → `/26` `10.10.0.128/26` (.128–.191) · เซิร์ฟเวอร์ 20 → 30 → `/27` `10.10.0.192/27` (.192–.223) · IoT 12 → 2⁴ − 2 = 14 → `/28` `10.10.0.224/28` (.224–.239) · เหลือ .240–.255 (16 ที่อยู่) สำหรับขยายหรือลิงก์ และผังนี้ยังแยก IoT/แขกออกจากผู้ใช้ตามหลัก Security
::

## 14. สรุป

- ซับเน็ตคือก้อนที่อยู่ติดกันที่ใช้ prefix เดียวกัน เป็น **broadcast domain** เดียว ช่วยลด broadcast, ลดขนาดตารางเส้นทาง และเป็นฐานของการควบคุมความปลอดภัย
- **Subnet mask** (1 ชิดซ้าย) แยก network ออกจาก host และ **IP AND mask = network address** เขียนสั้นเป็น **CIDR `/n`**
- เครื่องตัดสิน **ส่งตรง (ARP หา MAC ปลายทาง)** หรือ **ส่งให้ default gateway (ARP หา MAC เกตเวย์)** จากผล AND ของตัวเอง mask ผิด = ตัดสินผิด
- มี 2^(32 − n) ที่อยู่ ใช้ได้ **2^h − 2** (ลบ network กับ broadcast) ข้อยกเว้น /31 และ /32 และบางคลาวด์สงวนเพิ่ม
- คำนวณมือด้วย **ขนาดบล็อก = 256 − ค่า mask** ใน octet ที่ตัด แบ่งโดย **ยืมบิตจาก host** (2^b ซับเน็ต), **VLSM** แบ่งตามความต้องการจริงโดยจัดจากก้อนใหญ่ก่อน, **summarization** รวมก้อนต่อเนื่องที่ลงตัวกำลังสองเป็น prefix เดียว
- CIDR แทนที่ระบบคลาสเพื่อแจกพอดีและรวมเส้นทางได้
- Security: แบ่งส่วน (segmentation) จำกัด lateral movement และขอบเขต ARP/DHCP attack แต่ต้องมี ACL/ไฟร์วอลล์ระหว่างซับเน็ตจริง ตรวจ mask และกฎด้วยการคำนวณช่วงจริง
- ต่อไปในโมดูลถัดไปจะนำความรู้เรื่องที่อยู่ไปใช้กับการตั้งค่าและวิเคราะห์เครือข่ายขั้นสูง (DHCP, DNS, VLAN, การดักจับแพ็กเก็ต)
