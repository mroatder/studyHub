## วัตถุประสงค์การเรียนรู้

เมื่อจบบทนี้ คุณควรจะ

1. เลือกวิธีติดตั้งที่เหมาะกับสถานการณ์ ระหว่างติดตั้งใหม่ (clean install), อัปเกรด (in-place upgrade) และติดตั้งอัตโนมัติ (imaging)
2. อธิบายความต่างของ **GPT กับ MBR** และ **NTFS กับ FAT32/exFAT** พร้อมบอกได้ว่าทำไมสมัยใหม่ใช้ GPT + NTFS
3. เล่าลำดับเหตุการณ์ตั้งแต่บูตจาก USB จนถึงหน้าจอ OOBE ว่าใครทำอะไรตามลำดับ
4. บอกสิ่งที่ต้องทำหลังติดตั้งเสร็จ และเรียงลำดับให้ถูกพร้อมเหตุผล
5. มองการติดตั้งในมุม Security: สื่อติดตั้งที่เชื่อถือได้, Secure Boot, การเข้ารหัสดิสก์, สิทธิ์ผู้ดูแล

## สรุปสั้น (TL;DR)

การติดตั้ง Windows คือการเปลี่ยน "ฮาร์ดแวร์เปล่า" ให้เป็น "เครื่องที่ใช้งานได้" เริ่มจากเลือกวิธี (ล้างใหม่ / อัปเกรด / อัตโนมัติ) จัดดิสก์ด้วย **GPT** และฟอร์แมตเป็น **NTFS** คัดลอกอิมเมจระบบจาก WinPE ลงดิสก์ แล้วรีบูตเข้า **OOBE** เพื่อตั้งค่าเครือข่าย บัญชี และความเป็นส่วนตัว จากนั้นต้องติดตั้งไดรเวอร์ อัปเดต และเปิดการป้องกันก่อนใช้งานจริง

## เปรียบเทียบกับชีวิตจริง

นึกถึง **การสร้างและส่งมอบห้องพักในคอนโด**

| ในคอนโด | ใน Windows | ข้อสังเกต |
|---|---|---|
| ที่ดินเปล่า / ตึกเปล่า | ฮาร์ดแวร์ที่ยังไม่มี OS | มีทุกอย่างแต่ยังอยู่อาศัยไม่ได้ |
| ผังแบ่งห้อง | ตารางพาร์ทิชัน (GPT/MBR) | ผังที่ดีรองรับห้องมากและมีสำเนาไว้ |
| ระบบเก็บของและกุญแจห้อง | ระบบไฟล์ (NTFS) | ใครเข้าห้องไหนได้ และถ้าไฟดับระหว่างขนของก็ไม่เละ |
| ทีมก่อสร้างทำตามแบบ | WinPE + install.wim | ทีมชั่วคราวมาสร้างแล้วกลับไป |
| ตรวจรับห้อง/ลงชื่อผู้เช่า | OOBE | ตั้งค่าให้เจาะจงกับเจ้าของห้อง |
| ติดตั้งแอร์ ล็อกประตู ดับเพลิง | ไดรเวอร์ อัปเดต ซอฟต์แวร์ป้องกัน | ห้องที่ส่งมอบแล้วแต่ไม่มีระบบความปลอดภัยยังไม่พร้อมอยู่ |

## ภาพรวม

ต้นฉบับแบ่งบทนี้เป็น 4 ช่วง คือ **วางกลยุทธ์การติดตั้ง**, **พาร์ทิชันและระบบไฟล์**, **ขั้นตอนติดตั้งและ OOBE**, และ **งานหลังติดตั้ง** เราจะเดินตามลำดับเดียวกัน และเติมคำอธิบายกลไกภายในที่ต้นฉบับกล่าวไว้สั้นๆ

## 1. วางกลยุทธ์ก่อนติดตั้ง

ก่อนใส่แฟลชไดรฟ์ ต้องตัดสินใจก่อนว่าจะใช้ **เส้นทางไหน**

- **Clean installation:** ล้างไดรฟ์เป้าหมายทั้งหมด ลบข้อมูล การตั้งค่าเก่า และมัลแวร์หรือไฟล์ระบบที่เสียหาย ได้ระบบที่สะอาดที่สุด
- **In-place upgrade:** อัปเกรดจากภายใน Windows เดิม เก็บไฟล์ โปรแกรม และการตั้งค่าไว้ แต่ปัญหาเดิมอาจตามมาด้วย
- **Automated imaging:** ในองค์กรที่ต้องลงเครื่องจำนวนมาก ใช้เครื่องมือเช่น **MDT** (Microsoft Deployment Toolkit) หรือ **WDS** (Windows Deployment Services) ร่วมกับไฟล์ตอบ **unattend.xml** ที่กำหนดภาษา การแบ่งดิสก์ ชื่อเครื่อง และบัญชีแรกล่วงหน้า ไม่ต้องมีคนนั่งกดระหว่างติดตั้ง

ลองตอบเงื่อนไขของสถานการณ์ต่างๆ เพื่อดูว่าควรเลือกวิธีไหน

::install-planner
::

> ข้อสังเกตของผู้เขียน: ต้นฉบับกล่าวถึงการ "บูตผ่านเครือข่าย" ด้วยคำว่า PXE ซึ่งคือการที่เครื่องไม่ต้องมี USB แต่ขอไฟล์บูตจากเซิร์ฟเวอร์ผ่านเครือข่ายตอนเปิดเครื่อง เป็นกลไกพื้นฐานของการติดตั้งจำนวนมาก

## 2. พาร์ทิชันและระบบไฟล์

ดิสก์ใหม่ยังเป็นพื้นที่ดิบ Windows Setup ต้องทำสองอย่างก่อนวางระบบ คือ **แบ่งพื้นที่** (พาร์ทิชัน) และ **ตั้งกฎการเก็บข้อมูล** (ระบบไฟล์)

### 2.1 ตารางพาร์ทิชัน: MBR กับ GPT

**MBR** เป็นมาตรฐานเก่าตั้งแต่ยุค BIOS เก็บตารางพาร์ทิชันไว้ในเซกเตอร์แรก 512 ไบต์ ส่วน **GPT** เป็นมาตรฐานของยุค UEFI ที่ออกแบบใหม่ ทดลองสลับสองแบบ และเลื่อนขนาดดิสก์ให้เกิน 2 TB ดู

::disk-layout
::

ประเด็นสำคัญที่ต้นฉบับเน้น

- **ขนาดดิสก์:** GPT รองรับดิสก์ใหญ่กว่า 2 TB ส่วน MBR ไม่ได้
- **ผูกกับ UEFI:** GPT ทำงานคู่กับ UEFI ให้บูตเร็วกว่าและมีฟีเจอร์ **Secure Boot**

ส่วนที่ผู้เขียนเสริมให้เข้าใจกลไก: ที่ MBR จำกัดราว 2 TB เพราะระบุตำแหน่งเป็นเลข 32 บิต คูณกับขนาดเซกเตอร์ 512 ไบต์ (2^32 × 512 ไบต์ ≈ 2.2 TB) ส่วน GPT ใช้เลขตำแหน่ง 64 บิต ใหญ่เกินกว่าดิสก์จริงจะถึง และ GPT เก็บตารางสำรองไว้ท้ายดิสก์พร้อมค่า CRC สำหรับตรวจว่าตารางเสียหายหรือไม่

### 2.2 ระบบไฟล์: NTFS เทียบกับ FAT32 / exFAT

พาร์ทิชันต้องถูกฟอร์แมตด้วยระบบไฟล์ที่กำหนดวิธีเก็บและค้นหาข้อมูล Windows ใช้ **NTFS** เป็นหลัก มีสามจุดเด่นที่ต้นฉบับกล่าวถึง

- **ACL (Access Control List):** กำหนดสิทธิ์รายไฟล์รายผู้ใช้ได้
- **Journaling:** จดบันทึกการเปลี่ยนแปลงก่อนทำจริง ทำให้ไฟดับกลางคันก็กู้โครงสร้างได้
- **Volume Shadow Copy:** สร้างภาพสำเนา ณ เวลาหนึ่งของไดรฟ์ ใช้ในการสำรองข้อมูลและกู้ไฟล์เวอร์ชันเก่า

ส่วน **FAT32** และ **exFAT** ใช้กับสื่อพกพาเพราะเปิดอ่านได้ข้ามระบบ แต่ไม่มีสิทธิ์ระดับไฟล์และไม่มี journal ลองทดสอบเองว่าแต่ละระบบไฟล์ตอบสนองอย่างไร

::fs-lab
::

| | NTFS | exFAT | FAT32 |
|---|---|---|---|
| ใช้กับ | ดิสก์ระบบ Windows | แฟลชไดรฟ์/การ์ดความจุสูง | อุปกรณ์เก่า, พาร์ทิชัน EFI |
| สิทธิ์ระดับไฟล์ (ACL) | มี | ไม่มี | ไม่มี |
| Journal | มี | ไม่มี | ไม่มี |
| ไฟล์เดียวใหญ่สุด | ใหญ่มาก | ใหญ่มาก | ไม่เกิน 4 GB |
| ข้ามระบบ (Windows/macOS/Linux) | อ่านได้ทั่วไป เขียนต้องมีตัวช่วย | ได้ดี | ได้ดีที่สุด |

## 3. ขั้นตอนติดตั้งและ OOBE

ต้นฉบับอธิบายลำดับสั้นๆ ว่า เครื่องบูตจากสื่อติดตั้ง โหลด **WinPE** แล้วรัน **setup.exe** ซึ่งรับค่าภาษา รุ่นของ Windows และพาร์ทิชันเป้าหมาย จากนั้นแตกอิมเมจ (`install.wim` หรือ `install.esd`) ลงพาร์ทิชันหลักและคัดลอกไฟล์บูตให้ UEFI แล้วรีบูตเข้า **OOBE**

กดเดินทีละขั้น ดูว่าแต่ละขั้นเป็นหน้าที่ของใครและส่งอะไรให้ใคร

::install-flow
::

**WinPE คืออะไร** เป็น Windows ย่อส่วนที่ทำงานจากหน่วยความจำ ไม่ต้องมีระบบบนดิสก์ จึงใช้จัดดิสก์และติดตั้งได้แม้ดิสก์ยังว่าง ใช้ในงานกู้ระบบได้ด้วย

**ไฟล์ WIM คืออะไร** เป็นไฟล์อิมเมจของ Windows ที่บีบอัดและรวมหลายรุ่นไว้ในไฟล์เดียว ตัวติดตั้งเลือกแตกเฉพาะรุ่นที่ซื้อมา

### 3.1 งานที่ทำใน OOBE

ต้นฉบับแบ่งงานใน OOBE เป็น 3 ข้อ

1. **Network:** เชื่อมต่อ Wi-Fi หรือ Ethernet เพื่อตรวจหาอัปเดตความปลอดภัยที่สำคัญ
2. **Account:** สร้างบัญชีในเครื่อง (local) หรือยืนยันตัวตนกับ Microsoft Entra ID (เดิมคือ Azure AD) หรือโดเมน Active Directory
3. **Privacy:** เลือกระดับ telemetry (ข้อมูลวินิจฉัยที่ส่งให้ Microsoft) และบริการตำแหน่งที่ตั้ง

## 4. งานหลังติดตั้ง และการจัดการไดรเวอร์

ระบบที่เพิ่งติดตั้งเสร็จมีแต่ไดรเวอร์ทั่วไป พอให้ภาพและเครือข่ายใช้ได้ แต่ฟังก์ชันและประสิทธิภาพของชิ้นส่วนเฉพาะทาง (การ์ดจอแยก ชิปเซ็ต การ์ดเครือข่ายเฉพาะรุ่น) ยังไม่เต็มที่ จึงต้องติดตั้ง **ไดรเวอร์จากผู้ผลิต** แล้วจึง

- รัน **Windows Update** เพื่อรับแพตช์ความปลอดภัยสะสมล่าสุด
- ตั้งค่า **Windows Defender** หรือซอฟต์แวร์ป้องกัน endpoint ของบริษัทอื่น
- ปรับ **Power plan** ให้ตรงบทบาทของเครื่อง เซิร์ฟเวอร์เปิดตลอดเวลา แล้วแล็ปท็อปที่ใช้แบตเตอรี่ต้องประหยัดไฟ

ลองเรียงงานเหล่านี้ให้ถูกลำดับ (ผู้เขียนเพิ่มข้อบัญชีผู้ใช้ปกติ การเข้ารหัสดิสก์ และการสำรองเพื่อให้ครบแบบมืออาชีพ)

::post-install-order
::

**ไดรเวอร์คืออะไร** คือซอฟต์แวร์ที่เป็นล่ามระหว่างระบบปฏิบัติการกับฮาร์ดแวร์ ทำให้ OS สั่งงานชิ้นส่วนที่ผู้ผลิตแต่ละรายออกแบบต่างกันด้วยคำสั่งชุดเดียวกัน ไดรเวอร์รันในระดับสิทธิ์สูง (kernel) จึงมีผลต่อทั้งเสถียรภาพและความปลอดภัย

## มุมมองด้าน Security

- **เชื่อถือเฉพาะสื่อติดตั้งทางการ:** ดาวน์โหลดจากเว็บ Microsoft และตรวจ hash (เช่น SHA-256) ISO ที่มาจากที่อื่นอาจฝัง backdoor ตั้งแต่ก่อนติดตั้ง
- **Secure Boot:** เมื่อใช้ GPT + UEFI จะตรวจลายเซ็นของบูตโหลดเดอร์ก่อนให้ทำงาน ป้องกันมัลแวร์ที่แอบฝังตัวก่อนระบบปฏิบัติการ (bootkit)
- **เข้ารหัสดิสก์ (BitLocker):** ถ้าเครื่องหาย ผู้ที่ถอดดิสก์ไปอ่านจะไม่เห็นข้อมูล ต้องสำรอง recovery key ไว้ในที่ปลอดภัย
- **ACL ของ NTFS:** ใช้ควบคุมใครอ่านเขียนไฟล์ได้ตามหลัก least privilege การใช้ FAT32/exFAT กับข้อมูลลับจึงไม่ปลอดภัย
- **บัญชีผู้ดูแล:** ใช้บัญชีปกติในชีวิตประจำวัน บัญชีแอดมินเฉพาะเวลาที่จำเป็น ปิดบัญชี Administrator ที่ไม่ใช้ และตั้งรหัสผ่านแข็งแรง
- **ไฟล์ unattend.xml:** อาจมีรหัสผ่านบัญชีแรกหรือรหัสเข้าโดเมนอยู่ในไฟล์ ต้องเก็บเป็นความลับและลบหลังใช้เสร็จ ไม่ปล่อยให้เครื่องที่ติดตั้งแล้วยังมีไฟล์นี้อยู่
- **ติดตั้งใหม่หลังโดนโจมตี:** การ clean install เป็นวิธีที่แน่ที่สุดในการกำจัดการฝังตัว (persistence) แต่ต้องมั่นใจว่ากู้ไฟล์กลับมาโดยไม่พามัลแวร์มาด้วย

## ตัวอย่างการวิเคราะห์ปัญหาในงาน IT Support

| อาการ | สิ่งที่ควรสงสัยก่อน | วิธีตรวจเบื้องต้น |
|---|---|---|
| ตัวติดตั้งไม่เห็นดิสก์ในขั้นเลือกพาร์ทิชัน | ไม่มีไดรเวอร์ควบคุมดิสก์ (เช่น RAID/NVMe ของบางผู้ผลิต) | โหลดไดรเวอร์จากผู้ผลิตลง USB แล้วกด "Load driver" ในตัวติดตั้ง |
| ข้อความ "Windows cannot be installed to this disk" (GPT/MBR) | โหมดบูต (UEFI/Legacy) ไม่ตรงกับรูปแบบพาร์ทิชันของดิสก์ | ตรวจโหมดบูตใน UEFI ให้ตรงกับ GPT หรือแปลงดิสก์ให้ตรงกัน |
| ดิสก์ 4 TB แต่เห็นแค่ 2 TB | ดิสก์ถูกกำหนดเป็น MBR | แปลงเป็น GPT (สำรองข้อมูลก่อนเสมอ) |
| ติดตั้งเสร็จแล้วบูตวนเข้าตัวติดตั้งอีก | ลำดับบูตยังให้ USB ก่อนดิสก์ | ถอด USB หรือปรับ boot order |
| ติดตั้งเสร็จแต่ไม่มีอินเทอร์เน็ต | ไดรเวอร์การ์ดเครือข่ายยังไม่มี | โหลดไดรเวอร์ผ่านเครื่องอื่นลง USB แล้วติดตั้ง |
| คัดลอกไฟล์ใหญ่ลงแฟลชไดรฟ์ไม่ได้ | แฟลชไดรฟ์เป็น FAT32 (ไฟล์เดียวเกิน 4 GB ไม่ได้) | ฟอร์แมตเป็น exFAT หรือ NTFS (สำรองข้อมูลก่อน) |
| เครื่องใหม่ทั้งล็อตต้องมีการตั้งค่าเหมือนกัน | ติดตั้งมือทีละเครื่อง | ใช้ image มาตรฐานพร้อม unattend.xml |

| unattend.xml | อันแอตเทนด์ | ไฟล์ตอบคำถามให้ตัวติดตั้งทำเองโดยไม่ต้องมีคนกด |
| PXE | พีเอ็กซ์อี | การบูตเครื่องจากเครือข่าย |

## ตรวจความเข้าใจ

คิดคำตอบในใจก่อน แล้วกดดูเฉลย (สี่ข้อแรกตรงกับคำถามท้ายบทต้นฉบับ)

::reveal{question="ข้อได้เปรียบหลักของ GPT เหนือ MBR ในการติดตั้ง Windows คืออะไร"}
GPT รองรับดิสก์ใหญ่กว่า 2 TB (MBR จำกัดราวนั้นจากเลขตำแหน่ง 32 บิต) รองรับพาร์ทิชันได้มากกว่า มีตารางสำรองและ CRC ตรวจความเสียหาย และทำงานคู่กับ UEFI ให้บูตเร็วขึ้นพร้อม Secure Boot
::

::reveal{question="ทำไม NTFS จึงเหมาะกว่า FAT32 สำหรับพาร์ทิชันระบบของ Windows สมัยใหม่"}
NTFS มี ACL กำหนดสิทธิ์รายไฟล์ มี journal ป้องกันความเสียหายเมื่อไฟดับ และมี Volume Shadow Copy สำหรับสำรองและกู้ไฟล์ FAT32 ไม่มีทั้งสามอย่าง และยังจำกัดไฟล์เดียวไม่เกิน 4 GB
::

::reveal{question="ไฟล์ unattend.xml ทำหน้าที่อะไรในการติดตั้ง Windows ระดับองค์กร"}
เป็นไฟล์ตอบคำถามล่วงหน้า กำหนดภาษา การแบ่งพาร์ทิชัน ชื่อเครื่อง และบัญชีแรก เพื่อให้ติดตั้งโดยไม่ต้องมีคนโต้ตอบ ใช้ร่วมกับ MDT/WDS ได้ผลลัพธ์เหมือนกันทุกเครื่อง แต่ต้องระวังเรื่องรหัสผ่านที่อาจอยู่ในไฟล์
::

::reveal{question="ช่วง Out-of-Box Experience (OOBE) มีจุดประสงค์อะไร"}
เป็นขั้นตั้งค่าสุดท้ายที่ทำให้ระบบ "ของผู้ใช้คนนี้" ตั้งค่าเครือข่าย สร้างหรือยืนยันบัญชี (local, Entra ID หรือโดเมน) และเลือกความเป็นส่วนตัว เช่น telemetry และตำแหน่งที่ตั้ง
::

::reveal{question="เมื่อไหร่ควรเลือก clean install แทน in-place upgrade"}
เมื่อเครื่องไม่มี OS, ระบบเดิมเสียหายหรือสงสัยมัลแวร์ หรือไม่ต้องเก็บข้อมูลเดิม เพราะ clean install ล้างปัญหาเดิมทั้งหมด ส่วน upgrade เหมาะเมื่อระบบเดิมปกติและต้องเก็บไฟล์กับโปรแกรม
::

::reveal{question="ทำไมควรติดตั้งไดรเวอร์และอัปเดตก่อนติดตั้งโปรแกรมทั่วไปและเริ่มใช้งานจริง"}
เพราะไดรเวอร์ทั่วไปทำให้ฮาร์ดแวร์ทำงานไม่เต็มที่ และระบบที่ยังไม่อัปเดตมีช่องโหว่ที่รู้แล้ว ถ้าเปิดเว็บหรือเปิดไฟล์ก่อนปิดช่องโหว่จะเสี่ยงถูกโจมตี ลำดับที่ถูกคือเชื่อมต่อ ไดรเวอร์ อัปเดต เปิดการป้องกัน แล้วจึงใช้งาน
::

## สรุป

- เลือกวิธีติดตั้งให้เหมาะ: **clean** (สะอาด), **upgrade** (เก็บข้อมูล), **imaging + unattend.xml** (จำนวนมาก)
- สมัยใหม่ใช้ **GPT + UEFI** (ดิสก์ใหญ่ Secure Boot) และ **NTFS** (ACL journal shadow copy) สำหรับดิสก์ระบบ
- ลำดับติดตั้ง: บูตสื่อ → WinPE → แบ่งดิสก์ → แตก install.wim → รีบูต → OOBE
- หลังติดตั้งต้องทำไดรเวอร์ อัปเดต ป้องกัน ลดสิทธิ์ เข้ารหัส และสำรอง ก่อนใช้งานจริง
- บทถัดไปคือการติดตั้งและตั้งค่า Linux เพื่อเทียบกับ Windows
