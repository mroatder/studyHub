## วัตถุประสงค์การเรียนรู้

เมื่อจบบทนี้ คุณควรจะ

1. อธิบายความต่างของ **GUI** กับ **CLI** และเลือกใช้ให้เหมาะกับงานได้
2. อธิบายโครงสร้างต้นไม้ของระบบไฟล์ และความต่างของ Windows (ตัวอักษรไดรฟ์) กับ Linux (รากเดียว `/`)
3. แยก **absolute path** กับ **relative path** และเขียน path ที่ใช้ `.` กับ `..` ได้ถูก
4. ใช้ `pwd`, `dir` / `ls`, `cd` ใน PowerShell และ Bash เพื่อรู้ว่าอยู่ตรงไหน ดูของในโฟลเดอร์ และเดินขึ้นลงได้
5. อ่าน prompt ของ PowerShell และ Bash ออกว่าบอกอะไรบ้าง
6. ใช้ **Tab completion** และ **command history** เพื่อพิมพ์น้อยลง ผิดน้อยลง
7. จัดการชื่อโฟลเดอร์ที่มีช่องว่างได้ และรู้ว่าทำไมต้องจัดการ

## สรุปสั้น (TL;DR)

ระบบปฏิบัติการให้เราสั่งงานได้ 2 ทาง คือ **GUI** (คลิกบนหน้าจอ) และ **CLI** (พิมพ์คำสั่ง) ทั้งสองทางเข้าถึงไฟล์ชุดเดียวกัน ระบบไฟล์เป็น **ต้นไม้ของโฟลเดอร์** ตำแหน่งของไฟล์เขียนเป็น **path** ถ้าเขียนจากรากสุดคือ **absolute** ถ้าเขียนนับจากโฟลเดอร์ที่ยืนอยู่คือ **relative** (`.` = ที่นี่, `..` = ชั้นบน) เครื่องมือหลักคือ `pwd` (อยู่ไหน), `dir`/`ls` (มีอะไรบ้าง), `cd` (ไปที่อื่น) ตัวช่วยคือ Tab (เติมให้), ลูกศรขึ้น (เรียกคำสั่งเก่า) และเครื่องหมายคำพูดครอบชื่อที่มีช่องว่าง

## เปรียบเทียบกับชีวิตจริง

นึกถึง **การไปหาห้องในห้างสรรพสินค้า**

| ในห้าง | ในคอมพิวเตอร์ | ข้อสังเกต |
|---|---|---|
| เดินดูป้ายและแผนที่ เห็นร้านเป็นภาพ | GUI | หาง่ายเมื่อไม่รู้ว่าอะไรอยู่ตรงไหน แต่ช้าถ้าต้องไปหลายร้านซ้ำๆ |
| บอกคนขับแท็กซี่ว่า ไปชั้น 3 โซน B ร้านที่ 12 | CLI | เร็วและแม่นยำถ้ารู้ที่อยู่ แต่ถ้าพิมพ์ผิดก็ไปผิดที่ |
| ที่อยู่เต็มตั้งแต่ชื่อห้างถึงเลขร้าน | absolute path | ใช้ได้ไม่ว่าตอนนี้ยืนอยู่ตรงไหน |
| ขึ้นบันไดเลื่อน 1 ชั้นแล้วเลี้ยวซ้าย | relative path | ถูกเฉพาะเมื่อยืนอยู่จุดเดิมเท่านั้น |
| ป้าย "คุณอยู่ที่นี่" | `pwd` / prompt | ก่อนเดินต่อควรเช็กว่าอยู่ตรงไหน |

## ภาพรวม

ต้นฉบับแบ่งบทนี้เป็น 4 ช่วง คือ **การเดินด้วยหน้าจอกราฟิกบน Windows/Linux**, **path และต้นไม้ไดเรกทอรี**, **CLI ของ Windows (Command Prompt/PowerShell)** กับ **CLI ของ Linux (Bash)**, และ **เทคนิคใช้เชลล์** (Tab, ช่องว่าง, ประวัติ) แล้วจบด้วยการเทียบ GUI/CLI และแบบฝึกหัด เราจะเดินตามนี้ แล้วเสริมกลไกที่ต้นฉบับพูดสั้นๆ

## 1. GUI กับ CLI: สองทางเข้าสู่ระบบเดียวกัน

**GUI (Graphical User Interface)** แสดงเครื่องเป็นหน้าต่าง ไอคอน แถบงาน และตัวชี้เมาส์ **CLI (Command-Line Interface)** รับข้อความที่เราพิมพ์ แล้วตอบกลับเป็นข้อความ ทั้งคู่เป็น "หน้าต่างบานต่างกัน" ที่มองเข้าไปในระบบไฟล์ชุดเดียวกัน ไม่ใช่ระบบคนละอัน โฟลเดอร์ที่สร้างด้วยเมาส์ก็เห็นใน CLI ทันที และกลับกัน

ภายในแล้ว ทั้งสองแบบเป็น **โปรแกรมธรรมดา** ที่เรียกใช้บริการของระบบปฏิบัติการ (system call) เหมือนกัน คือ File Explorer ก็ขอให้ระบบ "แสดงรายการไฟล์ในโฟลเดอร์นี้" และ `dir` ก็ขอเรื่องเดียวกัน ต่างกันแค่หน้าตาของคนที่มาขอ

## 2. เดินผ่านหน้าจอกราฟิก (GUI)

**Windows** ใช้ **File Explorer** เปิดมาจะเห็นหน้า Home หรือ This PC มีไดรฟ์เป็นตัวอักษร (`C:`, `D:`) **Linux** เดสก์ท็อป (เช่น Ubuntu) ใช้โปรแกรมจัดการไฟล์ที่ชื่อ Files เปิดมาที่โฟลเดอร์ Home และมีรากเดียวคือ `/`

| หัวข้อ | Windows File Explorer | Linux Files |
|---|---|---|
| จุดเริ่มต้น | Home หรือ This PC | โฟลเดอร์ Home |
| ราก (root) | ไดรฟ์ตามตัวอักษร `C:⧵`, `D:⧵` | รากเดียว `/` |
| รูปแบบใน address bar | ตัวคั่น `⧵` เช่น `C:⧵Users⧵Name` | ตัวคั่น `/` เช่น `/home/name` |
| แสดงไฟล์ที่ซ่อน | แถบ View → Show → Hidden items | กด Ctrl + H |

**ไฟล์ที่ซ่อน (hidden)** ใน Windows คือไฟล์ที่ติดแอตทริบิวต์ซ่อน ส่วนใน Linux คือไฟล์ที่ **ชื่อขึ้นต้นด้วยจุด** (เรียก **dotfile**) เช่น `.bashrc` ซึ่งเป็นไฟล์ตั้งค่าของ Bash

GUI เก่งตอนเรียกดูไฟล์ทั่วไปหรือดูภาพ แต่ข้อจำกัดคือ **ต้องใช้ RAM และ CPU ไปวาดหน้าจอ** ซึ่งเป็นเหตุให้เซิร์ฟเวอร์มักไม่ติดตั้ง และต้องมีคนนั่งหน้าจอหรือใช้รีโมตเดสก์ท็อป ซึ่งช้ากว่าการพิมพ์ข้อความผ่านเครือข่ายมาก

## 3. Path และต้นไม้ไดเรกทอรี

ระบบปฏิบัติการจัดเก็บไฟล์เป็น **ต้นไม้ (directory tree)** มีโฟลเดอร์รากอยู่บนสุด และโฟลเดอร์ย่อยแตกกิ่งลงมา **path** คือเส้นทางจากจุดหนึ่งไปหาไฟล์หรือโฟลเดอร์

| | Windows | Linux |
|---|---|---|
| ราก | ไดรฟ์ เช่น `C:⧵` (ไดรฟ์หลักมักเป็น C) | `/` เดียว ดิสก์และ USB ทุกตัวถูก "ต่อ" เข้ามาใต้ต้นไม้นี้ (บทที่ 4) |
| ตัวคั่น | `⧵` | `/` |
| ตัวอย่าง | `C:⧵Users⧵Alex⧵Documents⧵report.txt` | `/home/alex/documents/report.txt` |
| ตัวพิมพ์เล็ก/ใหญ่ | ไม่สนใจ (`Report.txt` = `report.txt`) | **สนใจ** (`Report.txt` ≠ `report.txt`) |

เรื่องตัวคั่นมีที่มา: ระบบ MS-DOS ในอดีตใช้ `/` นำหน้าตัวเลือกของคำสั่งอยู่แล้ว (เช่น `dir /w`) จึงเลือก `⧵` มาคั่นโฟลเดอร์แทน ขณะที่ Unix ใช้ `/` คั่นโฟลเดอร์มาแต่แรก ปัจจุบัน Windows หลายส่วนรับ `/` ได้ด้วย แต่ธรรมเนียมที่แสดงยังเป็น `⧵`

### 3.1 Absolute path กับ Relative path

- **Absolute path** เขียนครบตั้งแต่รากลงมา Windows ขึ้นต้นด้วยไดรฟ์ (`C:⧵...`) Linux ขึ้นต้นด้วย `/` ใช้ได้ผลเหมือนกันเสมอไม่ว่ากำลังอยู่ที่ไหน
- **Relative path** นับจาก **โฟลเดอร์ปัจจุบัน (current working directory)** เช่น ถ้าอยู่ที่ `C:⧵Users⧵Alex` แล้วเขียน `Documents⧵report.txt` ก็คือไฟล์เดียวกับ `C:⧵Users⧵Alex⧵Documents⧵report.txt`

สัญลักษณ์พิเศษที่ใช้ได้ทั้งสองระบบ

- `.` (จุดเดียว) = โฟลเดอร์ปัจจุบัน
- `..` (สองจุด) = โฟลเดอร์แม่ (ขึ้นไป 1 ชั้น)

เช่น `Documents/../Downloads` อ่านว่า เข้า Documents → ถอยขึ้นมา 1 ชั้น → เข้า Downloads สุดท้ายอยู่ใน Downloads ซึ่งเป็นพี่น้องของ Documents ลองกำหนดตำแหน่งปัจจุบันกับปลายทางเอง ดูว่า relative path เปลี่ยนไปอย่างไร ขณะที่ absolute path ของปลายทางไม่เปลี่ยน

**กลไกภายใน:** ระบบปฏิบัติการจำ "ตำแหน่งปัจจุบัน" ไว้ให้แต่ละโปรเซส เมื่อคุณส่ง relative path โปรแกรมจะนำตำแหน่งปัจจุบันมาต่อหน้า path นั้นแล้วคำนวณ `.` และ `..` ออกเป็น absolute path ก่อนค่อยไปหาไฟล์จริง นี่คือเหตุที่คำสั่งเดียวกันให้ผลต่างกันเมื่อรันคนละโฟลเดอร์

## 4. CLI บน Windows: Command Prompt และ PowerShell

Windows มีเชลล์สองตัว **Command Prompt** (`cmd.exe`) เป็นรุ่นเก่าที่ยังเก็บไว้เพื่อความเข้ากันได้ และ **PowerShell** (`powershell.exe`) เป็นรุ่นใหม่ ทำงานกับ "ออบเจ็กต์" แทนข้อความเปล่า เหมาะกับงานจัดการระบบและเขียนสคริปต์ ต้นฉบับใช้ PowerShell เป็นหลัก เราก็เช่นกัน

เปิด PowerShell แล้ว **prompt** จะแสดงตำแหน่งปัจจุบันตามด้วย `>`

```powershell
PS C:⧵Users⧵Alex>
```

คำสั่งของ PowerShell เรียกว่า **cmdlet** ชื่อมีรูปแบบ กริยา-นาม เช่น `Get-Location` แต่มี **alias** (ชื่อย่อ) ให้พิมพ์สั้นๆ:

| ทำอะไร | cmdlet เต็ม | alias ที่ใช้บ่อย |
|---|---|---|
| ดูว่าอยู่ที่ไหน | `Get-Location` | `pwd` |
| ดูรายการในโฟลเดอร์ | `Get-ChildItem` | `dir`, `ls` |
| เปลี่ยนโฟลเดอร์ | `Set-Location` | `cd` |

**ข้อควรระวัง cmd.exe:** ใน Command Prompt พิมพ์ `cd D:` **ไม่ได้ย้ายไดรฟ์** (แค่แสดงโฟลเดอร์ปัจจุบันของไดรฟ์ D) ต้องพิมพ์ `D:` เดี่ยวๆ หรือใช้ `cd /d D:⧵` นี่เป็นต้นเหตุคำถามที่ช่วยเหลือผู้ใช้เจอบ่อย

## 5. CLI บน Linux: Terminal และ Bash

Linux ส่วนใหญ่ใช้เชลล์ **Bash (Bourne Again Shell)** เราเข้าถึงผ่านโปรแกรม **terminal** (หน้าต่างพิมพ์คำสั่ง) ตัว terminal คือหน้าต่าง ส่วนเชลล์คือโปรแกรมที่อยู่ข้างในและแปลคำสั่งของเรา

### 5.1 อ่าน prompt ให้ออก

```bash
alex@workstation:~$
```

### 5.2 คำสั่งพื้นฐาน

## 6. เทคนิคใช้เชลล์ให้เร็วและผิดน้อย

### 6.1 Tab completion

พิมพ์ตัวอักษรต้นๆ ของชื่อโฟลเดอร์หรือไฟล์แล้วกด **Tab** เชลล์จะเติมให้จนจบ ถ้ามีชื่อที่ขึ้นต้นเหมือนกันหลายชื่อ (เช่น `Documents` กับ `Downloads` ที่ขึ้นต้นด้วย `Do`) Bash จะเติมได้แค่ส่วนที่เหมือนกัน กด Tab **สองครั้ง** จะแสดงตัวเลือกทั้งหมด ส่วน PowerShell ใช้กด Tab ซ้ำเพื่อวนผ่านตัวเลือก

```bash
alex@workstation:~$ cd Doc[กด Tab]
alex@workstation:~$ cd Documents/
```

ข้อดีเกินกว่าแค่พิมพ์น้อย: ถ้า Tab ไม่เติมให้ มักแปลว่า **ชื่อนั้นไม่มีอยู่จริง หรือพิมพ์ผิด หรือยืนอยู่ผิดโฟลเดอร์** จึงใช้เป็นตัวเช็กเบื้องต้นได้

### 6.2 ชื่อที่มีช่องว่าง

ในไฟล์ระบบ ชื่ออาจมีช่องว่างได้ แต่ในเชลล์ **ช่องว่างคือตัวแบ่งคำ** เมื่อเราพิมพ์ `cd My Documents` เชลล์จะแยกเป็น 3 ชิ้น กดดูทีละขั้น

::

สองวิธีแก้ที่ต้นฉบับแนะนำ (PowerShell ใช้ได้เฉพาะแบบที่ 1 ในตารางนี้ ส่วน Bash ใช้ได้ทั้งสองแบบ)

```powershell
# PowerShell: ใช้เครื่องหมายคำพูด
PS C:⧵Users⧵Alex> cd "My Documents"
```

```bash
# Bash แบบที่ 1: ใช้เครื่องหมายคำพูด
alex@workstation:~$ cd "My Documents"

# Bash แบบที่ 2: ใช้ ⧵ นำหน้าช่องว่าง (escape)
alex@workstation:~$ cd My⧵ Documents
```

กดทีละคำสั่งดู error ที่พบเมื่อลืมใส่เครื่องหมายคำพูด

เหตุผลด้านความปลอดภัย: ลืมครอบเครื่องหมายคำพูดไม่ได้แค่ทำให้ error แต่ถ้าคำสั่งที่ใช้เป็น **คำสั่งลบ** อาจกลายเป็นลบ "ผิดชิ้น" เช่น ตั้งใจลบ `My Old Files` กลับถูกแยกเป็น `My`, `Old`, `Files` ลบสามชื่อที่อาจมีอยู่จริง จึงควรทำให้เป็นนิสัยครอบชื่อที่ไม่แน่ใจด้วยเครื่องหมายคำพูดเสมอ

### 6.3 ประวัติคำสั่ง (command history)

เชลล์จดคำสั่งที่เราเคยรันไว้ กด **ลูกศรขึ้น** เพื่อย้อนไปคำสั่งก่อนหน้า **ลูกศรลง** เพื่อไปข้างหน้า แล้วกด **Enter** เพื่อรันซ้ำ หรือแก้ไขก่อนรันก็ได้ คำสั่ง `history` ใช้ได้ทั้ง PowerShell และ Bash เพื่อดูรายการ

เพิ่มเติมจากผู้เขียน (ไม่ได้อยู่ในต้นฉบับ): บน Bash กด **Ctrl + R** แล้วพิมพ์ส่วนหนึ่งของคำสั่งเก่า เพื่อค้นย้อนหลังได้เร็วมาก

**ประเด็น Security:** ประวัติคำสั่งถูกบันทึกลงไฟล์ (Bash เก็บใน `~/.bash_history`) ถ้าเคยพิมพ์รหัสผ่านหรือโทเค็นไว้ในคำสั่ง ข้อมูลนั้นจะค้างอยู่ในไฟล์ ผู้โจมตีที่เข้าเครื่องได้มักเปิดไฟล์นี้ดูเป็นอย่างแรกๆ จึงไม่ควรใส่ความลับเป็นอาร์กิวเมนต์ของคำสั่ง

## 7. เลือก GUI หรือ CLI ดี

ต้นฉบับสรุปเป็นผังการตัดสินใจ โดยดูที่ "งานเป็นแบบไหน" และ "ใช้ระบบอะไร" กดตามเงื่อนไขเพื่อดูผล

::layer-stack{:layers='[{"title":"งานภาพ/ทำครั้งเดียว/ไม่รู้ว่าอยู่ไหน","text":"ถ้าต้องดูรูป ลากไฟล์ หรือกำลังหาของที่ยังไม่รู้ว่าอยู่ที่ใด ใช้ GUI (File Explorer หรือ Files)","example":"เลือกรูปไปแนบอีเมล"},{"title":"งานจำนวนมาก/ทำซ้ำ/ระยะไกล","text":"ถ้าต้องทำกับไฟล์หลายร้อยไฟล์ ทำซ้ำเป็นประจำ หรือเข้าเครื่องผ่านเครือข่าย ใช้ CLI","example":"เปลี่ยนชื่อไฟล์ 500 ไฟล์, ตรวจเซิร์ฟเวอร์ผ่าน SSH"},{"title":"ถ้าเป็น Windows","text":"ใช้ PowerShell (cd, dir, Get-Location)","example":"PS> dir"},{"title":"ถ้าเป็น Linux","text":"ใช้ Bash (cd, ls, pwd)","example":"$ ls -la"}]'}

จุดสำคัญคือ **GUI ให้การค้นพบ (discoverability)** เมื่อไม่รู้ว่าเมนูหรือไฟล์อยู่ที่ไหน ดูเมนูก็หาเจอ ขณะที่ **CLI ให้ความเร็ว ความแม่นยำ และการทำซ้ำได้** ช่างเทคนิคเดินเข้าไดเรกทอรีลึกๆ บนเซิร์ฟเวอร์ได้ในบรรทัดเดียว ผู้ใช้งานจริงใช้ปนกันทั้งสองแบบ

## มุมมองด้าน Security

- **ตรวจก่อนลบ:** ก่อนรันคำสั่งที่ลบหรือเปลี่ยนแปลงไฟล์ ให้ใช้ `pwd` และ `ls` / `dir` เช็กว่ายืนอยู่ถูกโฟลเดอร์ ผู้ดูแลระบบหลายคนทำข้อมูลหายเพราะรัน `rm` ในโฟลเดอร์ผิด และ `rm` บน Linux **ไม่ผ่านถังขยะ**
- **อย่าลอกคำสั่งมาวางโดยไม่อ่าน:** คำสั่งจากเว็บอาจซ่อนส่วนที่ทำอันตราย เช่น `rm -rf` กับ path กว้างเกินไป ต้องอ่านและเข้าใจก่อนกด Enter
- **Path Traversal:** โปรแกรมที่รับชื่อไฟล์จากผู้ใช้แล้วนำไปต่อ path ต้องกัน `../` ไม่เช่นนั้นผู้โจมตีใส่ `../../etc/passwd` เพื่อหลุดออกนอกโฟลเดอร์ที่อนุญาตได้ นี่เป็นช่องโหว่คลาสสิกของเว็บแอป ซึ่งเข้าใจได้ทันทีเมื่อรู้ว่า `..` คือชั้นบน
- **ประวัติคำสั่งเก็บความลับ:** ไม่พิมพ์รหัสผ่านเป็นอาร์กิวเมนต์ และตรวจ/ล้างประวัติบนเครื่องที่ใช้ร่วมกัน
- **ระวังสิทธิ์สูง:** prompt ที่เป็น `#` (root) คือสิทธิ์สูงสุด พิมพ์ผิดหนึ่งตัวอักษรอาจทำลายระบบ ควรใช้ผู้ใช้ปกติ + `sudo` เฉพาะตอนจำเป็น

## ตรวจความเข้าใจ

::reveal{question="ถ้าตอนนี้อยู่ที่ /var/log/nginx ในฐานะผู้ใช้ sam และต้องการเข้าโฟลเดอร์ Music ในโฮมของ sam ควรใช้คำสั่งไหนระหว่าง cd Music, cd ~/Music, cd /Music, cd ../Music"}
คือ `cd ~/Music` เพราะ `~` แปลว่าโฮมของ sam (`/home/sam`) ตัวเลือกอื่นผิดหมด: `cd Music` ไปหา Music ใต้ `/var/log/nginx`, `cd /Music` ไปหาที่ราก, และ `cd ../Music` ไปหา `/var/log/Music`
::

::reveal{question="ทำไม Linux ใช้ / แต่ Windows ใช้ ⧵ เป็นตัวคั่น path"}
เป็นเรื่องประวัติศาสตร์ Unix ใช้ `/` คั่นโฟลเดอร์มาตั้งแต่แรก ส่วน MS-DOS ใช้ `/` นำหน้าตัวเลือกของคำสั่ง (เช่น `dir /w`) อยู่แล้ว จึงเลือก `⧵` มาคั่นโฟลเดอร์ เพื่อไม่ให้สับสน Windows ยุคใหม่หลายส่วนรับ `/` ได้ แต่ธรรมเนียมการแสดงผลยังเป็น `⧵`
::

::reveal{question="พิมพ์ cd เฉยๆ ไม่ใส่ path ใน Windows กับ Linux ต่างกันอย่างไร"}
บน Linux (Bash) จะกลับไปโฟลเดอร์โฮมของผู้ใช้ ส่วนใน Command Prompt จะแสดงโฟลเดอร์ปัจจุบัน และใน Windows PowerShell 5.1 จะไม่เปลี่ยนอะไร (PowerShell 7 กลับโฮม) จึงควรทราบว่าอยู่เชลล์ไหนก่อน
::

::reveal{question="ดูจากรายการในเทอร์มินัลอย่างไรว่ารายการหนึ่งเป็นโฟลเดอร์หรือไฟล์"}
ใน PowerShell ดูคอลัมน์ Mode ถ้าตัวแรกเป็น `d` คือโฟลเดอร์ ถ้าเป็น `-` คือไฟล์ ใน Bash ใช้ `ls -l` ดูอักษรแรกของคอลัมน์ซ้ายสุด `d` คือโฟลเดอร์ `-` คือไฟล์ปกติ
::

::reveal{question="รันโปรแกรมแบบกราฟิกจาก CLI ได้ไหม"}
ได้ถ้าเครื่องนั้นมี **เซสชันกราฟิก** อยู่ เช่น พิมพ์ `notepad` หรือ `explorer .` ใน Windows, `xdg-open .` ใน Linux เดสก์ท็อป แต่ถ้าเข้าผ่าน SSH ไปเซิร์ฟเวอร์ที่ไม่มีเดสก์ท็อป จะเปิดหน้าต่างกราฟิกไม่ได้ (นอกจากตั้งค่าส่งภาพกลับมาเพิ่มเติม ซึ่งอยู่นอกเนื้อหาบทนี้)
::

::reveal{question="ทำไม cd My Documents ใน Bash ถึง error และแก้อย่างไร"}
เพราะ Bash แยกคำที่ช่องว่าง `My` กับ `Documents` กลายเป็นสองอาร์กิวเมนต์ ทั้งที่ `cd` ต้องการหนึ่งตัว แก้ด้วย `cd "My Documents"` หรือ `cd My⧵ Documents` หรือพิมพ์ `cd My` แล้วกด Tab ให้เชลล์ใส่ให้
::

## แบบฝึกหัด

ลองทำในเครื่องของคุณ (PowerShell หรือ Bash ก็ได้)

1. **ดูตำแหน่ง:** เปิด terminal แล้วพิมพ์ `pwd` ดูว่าตอนนี้อยู่ที่ไหน
2. **ดูของในโฟลเดอร์:** พิมพ์ `dir` (PowerShell) หรือ `ls` (Linux) และบน Linux ลอง `ls -la` เพื่อดูไฟล์ซ่อน
3. **เดินลง:** เลือกโฟลเดอร์ที่เห็นในรายการ เช่น `Documents` แล้ว `cd Documents` และสังเกตว่า prompt เปลี่ยน
4. **เดินขึ้น:** พิมพ์ `cd ..` แล้ว `pwd` ยืนยันว่ากลับมาจุดเริ่มต้น
5. **ลอง Tab:** พิมพ์ `cd` ตามด้วยช่องว่าง และตัวอักษร 2 ตัวแรกของโฟลเดอร์ แล้วกด Tab
6. **(เสริม)** ลองสร้างสถานการณ์ชื่อมีช่องว่าง: สร้างโฟลเดอร์ชื่อ `my test` แล้วลอง `cd my test` ก่อนและหลังใส่เครื่องหมายคำพูด

## สรุป

- GUI กับ CLI เป็นสองหน้าต่างสู่ระบบเดียวกัน GUI ดีเมื่อต้องการเห็นภาพ CLI ดีเมื่อต้องการความเร็ว ความแม่น ระยะไกล และการทำซ้ำ
- ระบบไฟล์เป็นต้นไม้ Windows แยกตามตัวอักษรไดรฟ์ Linux มีรากเดียว `/`
- **absolute path** ใช้ได้จากทุกที่ **relative path** ขึ้นอยู่กับโฟลเดอร์ปัจจุบัน และใช้ `.` (ที่นี่), `..` (ชั้นบน)
- เครื่องมือหลัก: `pwd` (อยู่ไหน), `dir`/`ls` (มีอะไร), `cd` (ไป)
- Linux แยกตัวพิมพ์เล็ก/ใหญ่ Windows ไม่แยก
- Tab ช่วยเติมและตรวจชื่อ ลูกศรขึ้นเรียกคำสั่งเก่า ชื่อที่มีช่องว่างต้องครอบด้วยเครื่องหมายคำพูด
- ก่อนสั่งที่เปลี่ยนแปลงข้อมูล ให้เช็กด้วย `pwd` เสมอ
