## วัตถุประสงค์การเรียนรู้

เมื่อจบบทนี้ คุณควรจะ

1. อธิบายความต่างของ **kernel กับ distribution** และเลือกตระกูล (Debian / Red Hat) ได้อย่างมีเหตุผล
2. เล่า **ลำดับบูตของ Linux** ทีละขั้น และอธิบายได้ว่าทำไมต้องมี **initramfs**
3. อธิบายว่า Linux ไม่มี C: D: แต่ใช้ **ต้นไม้เดียว + mount** อย่างไร อ่าน **/etc/fstab** ได้ และรู้ว่าทำไมใช้ **UUID** แทนชื่อ `/dev/sda1`
4. คำนวณ **inode, พื้นที่สำรองของ ext4 และขนาด swap** และวินิจฉัยอาการ "ดิสก์เต็มทั้งที่พื้นที่เหลือ"
5. อธิบายบัญชีผู้ใช้ (UID, `/etc/passwd`, `/etc/shadow`) และ **sudo** ตามหลักสิทธิ์น้อยที่สุด
6. ตั้งเครือข่ายด้วย `ip` และ Netplan โดยคำนวณ CIDR ได้ และไล่วินิจฉัยเครือข่ายทีละชั้น
7. อธิบายว่า `apt` ตรวจสอบความถูกต้องของแพ็กเกจด้วย **ห่วงโซ่ลายเซ็นและแฮช** อย่างไร
8. ควบคุมบริการด้วย **systemd** อ่านสถานะ active/enabled ได้ถูก และเข้าใจ unit file
9. ตั้งไฟร์วอลล์ `ufw` และเสริมความแข็งแรงของ SSH โดย **ไม่ล็อกตัวเองออก**

## เปรียบเทียบกับชีวิตจริง

นึกถึง **การเปิดร้านอาหารตั้งแต่ศูนย์**

| ร้านอาหาร | Linux | ข้อสังเกต |
|---|---|---|
| แกนครัว (เตา ระบบน้ำ ไฟ) | kernel | ทำให้ครัวทำงานได้ แต่ยังไม่มีเมนูหรือพนักงาน |
| ร้านครบชุดจากแฟรนไชส์ต่างเจ้า | distribution (Ubuntu, Rocky) | ใช้แกนครัวเดียวกัน แต่ต่างกันที่เมนู ระบบสั่งของ และนโยบาย |
| ผู้จัดการร้านคนแรกที่มาเปิดร้านตอนเช้า | systemd (PID 1) | คนแรกที่ตื่น ปลุกคนอื่นตามลำดับ (เตรียมน้ำก่อนเตรียมซุป) |
| ผังชั้น/ห้องและป้ายบอกที่เก็บของ | ต้นไม้ไดเรกทอรี + mount | ห้องเย็นหลายใบ แต่ลูกค้าเห็นเป็นร้านเดียว |
| ผู้ส่งวัตถุดิบที่มีใบรับรอง | package repository + ลายเซ็น GPG | รับของเฉพาะจากผู้ขายที่ตรวจสอบได้ |
| รปภ. หน้าร้าน | ไฟร์วอลล์ | ถ้าสั่งให้ปิดทุกประตูก่อนบอกให้เปิดประตูให้ตัวเอง คุณจะเข้าร้านไม่ได้ |

## ภาพรวม

บทนี้เดินตาม "ชีวิตของเครื่อง Linux" ตั้งแต่ **เลือกระบบ → บูต → โครงสร้างไฟล์ → ติดตั้ง → ตัวตน → เครือข่าย → ซอฟต์แวร์ → บริการ → ป้องกัน** ทุกหัวข้อเริ่มจากเหตุผลที่ต้องมีก่อน แล้วจึงถึงคำสั่ง บทนี้เทียบกับบทที่ 3 (Windows) ไปด้วย เพราะปัญหาเดียวกัน (ใครบูตก่อน ไฟล์อยู่ตรงไหน) ถูกแก้ต่างวิธี

## 1. Linux คืออะไร: Kernel และ Distribution

### 1.1 ทำไมต้องแยก kernel ออกจาก distribution

**Kernel** คือโปรแกรมแกนกลางที่คุมฮาร์ดแวร์ (CPU, หน่วยความจำ, ดิสก์, เครือข่าย) และให้โปรแกรมอื่นขอใช้ทรัพยากรผ่าน **system call** แต่ kernel อย่างเดียวไม่มีเชลล์ ไม่มีตัวติดตั้ง ไม่มีเครื่องมือจัดการ เพราะ Linux เป็นโอเพนซอร์ส ใครก็นำ kernel มาประกอบกับเครื่องมืออื่นเป็นระบบที่ใช้งานได้ นั่นคือ **distribution (distro)** จึงมีให้เลือกหลายร้อยแบบ ทั้งที่ใช้ kernel ตัวเดียวกัน

## 2. จากกดปุ่มเปิดเครื่องถึงหน้าล็อกอิน

ข้อเท็จจริง: ตอนเปิดเครื่อง ยังไม่มีอะไรรันอยู่เลย ทุกอย่างต้อง **ดึงตัวเองขึ้นมาทีละชั้น (bootstrap)** แต่ละชั้นรู้เพียงพอที่จะเรียกชั้นถัดไป

### 2.1 ปัญหาไก่กับไข่ และทางออก (initramfs)

kernel ต้องเมาท์ระบบไฟล์ root (`/`) เพื่ออ่านโปรแกรมที่เหลือ แต่การอ่านดิสก์ต้องใช้ **ไดรเวอร์** (เช่น NVMe, RAID, LVM, ระบบเข้ารหัส) ซึ่งเก็บอยู่ใน `/lib/modules` ซึ่งอยู่บน root นั่นเอง จึงเกิดวงวน ทางออกคือ **initramfs** ไฟล์ระบบไฟล์ขนาดเล็กที่ GRUB โหลดลง RAM มาพร้อม kernel มีไดรเวอร์และสคริปต์เท่าที่จำเป็นเพื่อค้นหาและเมาท์ root จริง (ถ้าดิสก์เข้ารหัส จะถามรหัสผ่านตรงนี้) แล้วส่งต่อการทำงานไปให้ root จริง

## 3. ต้นไม้ไดเรกทอรีและการ mount

### 3.1 ทำไมไม่มี C: D:

Windows ผูกตัวอักษรไดรฟ์กับแต่ละพาร์ทิชัน แต่ Linux ออกแบบตามปรัชญา Unix: **ทุกอย่างอยู่ในต้นไม้เดียวที่ราก `/`** พาร์ทิชันหรือดิสก์ไหนจะแสดงในที่ใด ผู้ดูแลเลือกเองโดยการ **mount (ต่อ)** เข้ากับโฟลเดอร์ที่มีอยู่ เรียกว่า **mount point** ข้อดีสำคัญ: **โปรแกรมไม่ต้องรู้ว่าไฟล์อยู่ดิสก์ไหน** ถ้า `/var/log` โตเกินก็ย้ายไปดิสก์ใหม่ได้โดยแค่เปลี่ยนที่ mount โปรแกรมไม่ต้องแก้

กลไกภายใน: เมื่อ mount อุปกรณ์เข้า `/home` โฟลเดอร์ `/home` เดิม "ถูกบัง" แล้ว kernel จะเปลี่ยนเส้นทางทุกการเข้าถึงใต้ `/home` ไปยังระบบไฟล์ของอุปกรณ์นั้นแทน (ไฟล์เดิมที่อยู่ใน `/home` ก่อน mount ไม่หาย แต่เข้าถึงไม่ได้ชั่วคราว)

### 3.2 โครงสร้างมาตรฐาน (FHS)

| โฟลเดอร์ | เก็บอะไร | ข้อสังเกต |
|---|---|---|
| `/boot` | kernel, initramfs, ไฟล์ GRUB (EFI อยู่ที่ `/boot/efi`) | ถ้าเต็ม อัปเดต kernel ไม่ได้ |
| `/etc` | ไฟล์ตั้งค่าของระบบและบริการ (ข้อความล้วน) | แก้ผิดพลาดมักทำให้บริการไม่ขึ้น |
| `/home` | ข้อมูลส่วนตัวของผู้ใช้ | มักแยกพาร์ทิชันเพื่อติดตั้งระบบใหม่โดยไม่แตะข้อมูล |
| `/var` | ข้อมูลที่เปลี่ยนตลอด เช่น log, ฐานข้อมูล, คิวเมล | พาร์ทิชันที่ชอบเต็มที่สุดบนเซิร์ฟเวอร์ |
| `/usr` | โปรแกรมและไลบรารีส่วนใหญ่ | |
| `/dev` | ไฟล์แทนอุปกรณ์ (`sda`, `nvme0n1`) | ไฟล์พิเศษที่ kernel สร้าง |
| `/proc`, `/sys` | หน้าต่างดูสถานะ kernel (ไม่ใช่ไฟล์จริงบนดิสก์) | มีแต่ใน RAM |
| `/tmp` | ไฟล์ชั่วคราว | |

### 3.3 พาร์ทิชันหลัก ชื่ออุปกรณ์ และ fstab

::linux-mounts
::

ชื่ออุปกรณ์: SATA เป็น `/dev/sda`, `/dev/sda1` ส่วน NVMe เป็น `/dev/nvme0n1`, `/dev/nvme0n1p1` (มี `p` คั่นเพราะชื่อดิสก์ลงท้ายด้วยตัวเลข)

**ทำไมต้องใช้ UUID แทนชื่ออย่าง `/dev/sdb1`** ชื่อ `sdX` ถูกตั้งตามลำดับที่ kernel พบอุปกรณ์ ซึ่งเปลี่ยนได้ เช่น เสียบ USB เพิ่ม หรือสลับสาย ดิสก์ที่เคยเป็น `sdb` อาจกลายเป็น `sdc` แล้วระบบเมาท์ผิดดิสก์ **UUID** คือหมายเลขประจำตัวที่เขียนอยู่ในระบบไฟล์ ไม่เปลี่ยนตามลำดับ จึงเป็นข้อมูลที่ `/etc/fstab` ควรใช้อ้างอิง

ไฟล์ `/etc/fstab` คือแผนที่บอก systemd ว่าบูตแล้วต้องเมาท์อะไรที่ไหน บรรทัดละ 6 ช่อง

```text
# อุปกรณ์                                   จุดเมาท์    ระบบไฟล์ ตัวเลือก           dump pass
UUID=3f2a...-9c1d                          /           ext4     errors=remount-ro  0    1
UUID=A1B2-C3D4                             /boot/efi   vfat     umask=0077         0    1
UUID=77de...-0b42                          none        swap     sw                 0    0
```

| ช่อง | ความหมาย |
|---|---|
| 1 อุปกรณ์ | ใช้ `UUID=...` เป็นหลัก |
| 2 จุดเมาท์ | โฟลเดอร์ที่จะต่อเข้า |
| 3 ระบบไฟล์ | ext4, xfs, vfat, swap |
| 4 ตัวเลือก | เช่น `noexec` (ห้ามรันโปรแกรม), `ro` (อ่านอย่างเดียว) |
| 5 dump | เลิกใช้ส่วนใหญ่ ตั้ง 0 |
| 6 pass | ลำดับตรวจดิสก์ตอนบูต: 1 สำหรับ root, 2 สำหรับอื่น, 0 ไม่ตรวจ |

> **ผลของ fstab ผิด:** ถ้าบรรทัดหนึ่งอ้าง UUID ที่ไม่มีอยู่ บูตอาจค้างรอแล้วตกลง emergency mode ตัวเลือก `nofail` ช่วยให้ระบบบูตต่อได้ถ้าดิสก์ที่ไม่สำคัญหายไป

### 3.4 ระบบไฟล์ ext4 / xfs กลไกและตัวเลขที่ควรคำนวณเป็น

**inode:** ไฟล์แต่ละไฟล์ใน ext4 มี **inode** เก็บ metadata (เจ้าของ สิทธิ์ ขนาด เวลา ตำแหน่งบล็อก) แต่ **ไม่เก็บชื่อไฟล์** ชื่อเก็บอยู่ในไดเรกทอรีซึ่งชี้ไปหา inode จำนวน inode **ถูกกำหนดตอน format** ค่าตั้งต้นประมาณ 1 inode ต่อ 16 KiB ของพื้นที่ (ค่าประมาณ ปรับได้ตอน mkfs)

> พาร์ทิชัน 100 GiB → 100 × 2³⁰ ÷ 16,384 = **6,553,600 inode** แปลว่าสร้างไฟล์ได้ไม่เกิน 6.55 ล้านไฟล์ ไม่ว่าไฟล์จะเล็กแค่ไหน

อาการที่ตามมา: `No space left on device` ทั้งที่ `df -h` ยังเหลือพื้นที่ ให้ลอง `df -i` ถ้า `IUse%` เต็ม 100% คือ inode หมด (เจอบ่อยเมื่อมีไฟล์เล็กนับล้านใน `/var/spool` หรือไฟล์ session)

**พื้นที่สำรองของ root:** ext4 ค่าตั้งต้นกัน **5% ของพื้นที่** ไว้ให้ root เท่านั้น เพื่อให้ระบบยังทำงานได้แม้ผู้ใช้ทำดิสก์เต็ม ดิสก์ 1 TB จึงมี ~50 GB ที่ผู้ใช้ทั่วไปใช้ไม่ได้ (ค่าประมาณ ปรับด้วย `tune2fs -m`)

**Journaling:** ext4 มี journal เหมือน NTFS (บท 3) โหมดตั้งต้นจดเฉพาะ **metadata** ก่อนแก้จริง ดังนั้นปกป้องความสอดคล้องของโครงสร้างไฟล์ ไม่ได้รับประกันเนื้อหาที่แอปกำลังเขียน **xfs** เด่นที่ไฟล์ใหญ่และไฟล์จำนวนมากที่ทำงานขนานกัน แต่ **ย่อพาร์ทิชันไม่ได้** (ext4 ย่อได้ตอนที่ unmount แล้ว)

**Swap:** พื้นที่ดิสก์รับข้อมูลที่ไม่ค่อยใช้จาก RAM เมื่อ RAM ตึง ประโยชน์คือกันโปรแกรมถูกฆ่าด้วย OOM killer และใช้ตอน hibernate (ต้องมี swap อย่างน้อยใกล้เคียง RAM ที่ใช้อยู่ ค่าประมาณ) แต่ถ้าระบบต้องสลับบ่อย จะช้าลงมาก เพราะดิสก์ช้ากว่า RAM หลายระดับ (ดูบทที่ 1)

### 4.2 ตัวตนบน Linux: UID, `/etc/passwd`, `/etc/shadow` และ sudo

ทำไมต้องรู้: บทนี้เปิดทางให้บทสิทธิ์ไฟล์ (บทที่ 7) และเป็นฐานของ Security

- **ผู้ใช้ถูกระบุด้วยตัวเลข UID** ไม่ใช่ชื่อ root คือ UID **0** ผู้ใช้ปกติเริ่มที่ 1000 ขึ้นไป (ตามธรรมเนียม) ระบบเทียบ UID กับสิทธิ์ของไฟล์ (เทียบได้กับ SID ของ Windows ในบทที่ 3)
- `/etc/passwd` เก็บรายชื่อ (อ่านได้ทุกคน เพราะโปรแกรมต้องแปลง UID เป็นชื่อ) แต่ **แฮชรหัสผ่านอยู่ใน `/etc/shadow`** ซึ่งอ่านได้เฉพาะ root
- รหัสผ่านไม่ได้ถูกเก็บตรงๆ แต่เก็บ **แฮชแบบช้าโดยตั้งใจ** (เช่น yescrypt ใน Ubuntu รุ่นใหม่ หรือ SHA-512 crypt รุ่นเก่า) พร้อม **salt** แบบสุ่ม เพื่อไม่ให้รหัสเดียวกันได้แฮชเดียวกัน และเพื่อให้การเดาทีละตัวแพงขึ้นมาก

**sudo** ให้ผู้ใช้ปกติรันคำสั่งเดียวด้วยสิทธิ์ root ชั่วคราวโดย **ใส่รหัสผ่านของตัวเอง** ระบบจดบันทึกว่าใครรันอะไรเมื่อไร (ที่ `/var/log/auth.log` หรือ journal) ข้อดีเทียบกับการล็อกอินเป็น root ตรงๆ: มีหลักฐานรายบุคคล, สิทธิ์สูงอยู่ชั่วขณะ, และไม่มีรหัสผ่าน root ที่ต้องแชร์

**คำนวณ: รหัสผ่านต้องยาวเท่าใด** รหัสผ่านที่สุ่มจากอักขระที่พิมพ์ได้ 95 ตัว ความยาว 8 ตัวมี 95⁸ ≈ 6.6 × 10¹⁵ แบบ (≈ 52.6 บิต) ส่วนความยาว 12 ตัวมี 95¹² ≈ 78.8 บิต เพิ่ม 4 ตัวอักษร ทำให้เดายากขึ้นราว 2²⁶ ≈ 67 ล้านเท่า (ใช้ได้กับรหัสที่สุ่มจริงเท่านั้น รหัสที่คนคิดเองมีรูปแบบ ทำให้เดาง่ายกว่ามาก)

## 5. เครือข่ายหลังติดตั้ง

### 5.1 ที่อยู่ IP และ CIDR

เครื่องต้องรู้ 3 อย่างเพื่อคุยออกนอกวง: **IP ของตัวเอง, ขนาดวงเครือข่าย (CIDR), และ gateway** `192.168.1.50/24` แปลว่า 24 บิตแรกเป็น "หมายเลขเครือข่าย" ที่เหลือ 32 − 24 = 8 บิตเป็น "หมายเลขเครื่อง"

| ตัวเลข | ผลคำนวณ |
|---|---|
| จำนวนที่อยู่ในวง | 2⁸ = 256 |
| ใช้เป็นเครื่องได้ | 256 − 2 = **254** (ลบที่อยู่เครือข่ายและที่อยู่ broadcast) |
| ถ้าเป็น /26 | 2⁶ − 2 = 62 เครื่อง |

เครื่องตัดสินใจว่า "ปลายทางอยู่ในวงเดียวกันไหม": ถ้าใช่ ส่งตรง ถ้าไม่ ส่งให้ **gateway** ส่งต่อ (หลักการเดียวกันกับตารางเส้นทางที่จะเรียนในโมดูลเครือข่าย)

### 5.3 ตั้ง IP คงที่ด้วย Netplan

DHCP แจก IP ให้ แต่ **เซิร์ฟเวอร์ควรมี IP คงที่** เพื่อให้คนและระบบอื่นหาเจอเสมอ Ubuntu รุ่นใหม่ใช้ **Netplan** อ่านไฟล์ YAML ใน `/etc/netplan/` แล้วสร้างค่าให้ตัวทำงานจริง (renderer)

```yaml
# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp3s0:
      dhcp4: no
      addresses:
        - 192.168.1.50/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [1.1.1.1, 8.8.8.8]
```

| บรรทัด | ความหมาย |
|---|---|
| `renderer: networkd` | ใช้ systemd-networkd เป็นตัวปรับค่าจริง |
| `dhcp4: no` | ปิดการรับ IP อัตโนมัติ |
| `addresses` | IP และ CIDR ของเครื่องนี้ |
| `routes … via` | gateway ที่ใช้ออกนอกวง |
| `nameservers` | DNS สำหรับแปลงชื่อ |

> **กับดัก YAML:** ใช้ **ช่องว่างเท่านั้น ห้าม Tab** และการเยื้องคือโครงสร้าง ถ้าผิดไฟล์จะถูกปฏิเสธ ใช้ `sudo netplan try` ซึ่งใช้ค่าใหม่ชั่วคราวแล้ว **ย้อนกลับเองถ้าไม่กดยืนยันในเวลาที่กำหนด** (ประมาณ 2 นาที ปรับได้) เหมาะกับเครื่องที่เข้าทางไกลอยู่ เพราะถ้าแก้ผิดจนขาดการเชื่อมต่อ ระบบจะกลับค่าเดิมให้เอง ต่างจาก `netplan apply` ที่มีผลทันทีและไม่ย้อน

## 6. อัปเดตและจัดการซอฟต์แวร์

### 6.1 ทำไมต้องอัปเดตทันทีหลังติดตั้ง

ISO ที่ใช้ติดตั้งอาจเก่าเป็นสัปดาห์หรือเดือน ช่วงนั้นมีช่องโหว่ที่เปิดเผยแล้ว เครื่องที่เพิ่งติดตั้งแล้วออนไลน์โดยไม่อัปเดตจึงเป็นเป้าที่ง่ายที่สุด

### 6.2 `update` ต่างกับ `upgrade`

| คำสั่ง | ทำอะไร | เปลี่ยนโปรแกรมในเครื่องไหม |
|---|---|---|
| `apt update` | ดาวน์โหลด **รายการ** แพ็กเกจและเวอร์ชันล่าสุดจากคลัง | ไม่ |
| `apt upgrade` | ติดตั้งแพ็กเกจรุ่นใหม่ตามรายการนั้น | ใช่ |
| `apt install X` | ติดตั้ง X พร้อมแพ็กเกจที่ต้องพึ่ง (dependency) | ใช่ |

## 7. บริการด้วย systemd

### 7.1 ทำไมต้องมีตัวจัดการบริการ

เซิร์ฟเวอร์ต้องรันโปรแกรมเบื้องหลัง (daemon/service) เช่น SSH, เว็บ, ฐานข้อมูล ต้องเริ่มตามลำดับที่ขึ้นต่อกัน (ฐานข้อมูลก่อนเว็บ) ต้องเริ่มใหม่เมื่อมันตาย และต้องจดบันทึกว่าเกิดอะไรขึ้น **systemd** คือ PID 1 ที่ทำทั้งหมดนี้ และเริ่มบริการที่ไม่ขึ้นต่อกันแบบ **ขนาน** จึงบูตเร็วกว่าแบบเรียงทีละตัว

### 7.2 Unit file และสถานะสองมิติ

บริการหนึ่งนิยามด้วย **unit file** (ข้อความธรรมดา) เช่น

```ini
# /etc/systemd/system/myapp.service
[Unit]
Description=My Application
After=network-online.target      # เริ่มหลังเครือข่ายพร้อม
Wants=network-online.target

[Service]
ExecStart=/usr/local/bin/myapp
Restart=on-failure               # ตายผิดปกติให้เริ่มใหม่เอง
User=myapp                       # รันด้วยผู้ใช้สิทธิ์ต่ำ ไม่ใช่ root

[Install]
WantedBy=multi-user.target       # enable = ผูกเข้ากับ target นี้
```

สถานะมี **สองมิติที่ไม่เหมือนกัน** นี่คือจุดที่คนสับสนมากที่สุด

| มิติ | คำถาม | ผู้ที่เปลี่ยน | ค่า |
|---|---|---|---|
| **Active** | ตอนนี้ทำงานอยู่ไหม | `start` / `stop` | `active (running)`, `inactive`, `failed` |
| **Enabled** | จะเริ่มเองตอนบูตไหม | `enable` / `disable` | `enabled`, `disabled` |

กลไกของ `enable`: สร้าง **symlink** ใน `/etc/systemd/system/multi-user.target.wants/` ชี้ไปที่ unit file เมื่อ systemd ไปถึง target นั้นตอนบูต ก็จะเริ่มทุกบริการที่ลิงก์อยู่ใต้ target ดังนั้น `start` ไม่ได้ทำให้รอดหลังรีบูต แต่ `enable` ไม่ได้สั่งให้เริ่มทันที (จึงมี `enable --now` รวมสองอย่าง)

## 8. ความปลอดภัยของโฮสต์เบื้องต้น

### 8.1 ไฟร์วอลล์: default deny

ใน kernel มีระบบกรองแพ็กเก็ต (netfilter) **ufw** (Uncomplicated Firewall) คือส่วนหน้าสั่งงานง่ายๆ ที่สร้างกฎให้ (ตระกูล Red Hat ใช้ firewalld) หลักคิดคือ **default deny**: ปฏิเสธขาเข้าทั้งหมด แล้วอนุญาตเฉพาะที่จำเป็น เพราะ "อนุญาตทั้งหมดแล้วปิดทีละอย่าง" ลืมปิดข้อใดก็เปิดช่อง

**กับดักล็อกตัวเองออก:** ถ้าคุณจัดการเครื่องผ่าน SSH (พอร์ต 22) แล้วเปิดไฟร์วอลล์ที่ปฏิเสธขาเข้าทั้งหมด *ก่อน* อนุญาตพอร์ต 22 การเชื่อมต่อจะถูกตัดทันทีและเข้าใหม่ไม่ได้ ลองทั้งสองลำดับ

::ufw-lockout
::

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh          # ต้องทำก่อนเปิดไฟร์วอลล์
sudo ufw enable
sudo ufw status verbose
```

### 8.2 SSH: ประตูหน้าของเซิร์ฟเวอร์

เซิร์ฟเวอร์ที่เปิด SSH ออกอินเทอร์เน็ตจะถูกบอตสแกนเดารหัสผ่านตลอดเวลา (ดูบรรทัด Failed password ใน journalctl ข้างบน) มาตรการเรียงตามความคุ้มค่า

| มาตรการ | การตั้งค่า | ทำไมได้ผล |
|---|---|---|
| ใช้คู่กุญแจแทนรหัสผ่าน | `PasswordAuthentication no` ใน `/etc/ssh/sshd_config` | กุญแจส่วนตัวไม่ผ่านเครือข่าย และเดาไม่ได้ในทางปฏิบัติ (ต่างจากรหัสผ่านที่เดาได้) |
| ห้าม root ล็อกอินตรงๆ | `PermitRootLogin no` | ผู้โจมตีต้องเดาทั้งชื่อผู้ใช้และรหัส และมีบันทึกรายบุคคลผ่าน sudo |
| จำกัดผู้ที่เข้าได้ | `AllowUsers sysadmin` | ลดบัญชีที่เป็นเป้าหมาย |
| บล็อกผู้เดาซ้ำ | fail2ban หรือ rate limit (`ufw limit ssh`) | ทำให้เดาได้ช้าลงมาก |
| ลดผู้เห็นพอร์ต | จำกัด IP ที่เข้าได้ที่ไฟร์วอลล์ | ผู้ที่ไม่ได้รับอนุญาตไม่เห็นบริการเลย |

> **ข้อควรระวังในการแก้:** เปลี่ยนพอร์ตของ SSH (เช่น จาก 22 เป็นอื่น) แค่ลดสัญญาณรบกวนในล็อก ไม่ใช่มาตรการความปลอดภัยจริง การป้องกันที่แท้จริงคือกุญแจและการจำกัดสิทธิ์ และก่อน **restart sshd** หลังแก้ ให้เปิดเซสชัน SSH อีกอันค้างไว้ แล้วทดสอบเข้าด้วยเซสชันใหม่ก่อนปิดอันเดิม

### 8.3 แผนที่ภัยคุกคาม ↔ กลไก

| ภัย | ทำไมเกิดได้ | ป้องกันด้วย | ข้อจำกัด |
|---|---|---|---|
| เดารหัสผ่าน SSH | พอร์ต 22 เปิดสู่โลก และรหัสผ่านเดาได้ | คู่กุญแจ, ปิดรหัสผ่าน, fail2ban | ถ้ากุญแจส่วนตัวหลุด ก็เข้าได้ทันที ต้องเก็บ/ตั้งรหัสปกป้องกุญแจ |
| ช่องโหว่ที่รู้แล้ว | ไม่อัปเดต | `apt upgrade` ตั้ง `unattended-upgrades` | ช่องโหว่ใหม่ที่ยังไม่มีแพตช์ (zero-day) ป้องกันด้วยการลดพื้นผิวโจมตี |
| บริการที่ไม่จำเป็นเปิดอยู่ | ติดตั้งมาตั้งต้นแล้วลืม | `systemctl disable --now`, ตรวจด้วย `ss -tlnp` | |
| คนขโมยแล็ปท็อป/ดิสก์ | ข้อมูลไม่ได้เข้ารหัส | LUKS (เข้ารหัสทั้งดิสก์ตอนติดตั้ง) | ต้องจำ/เก็บรหัสปลดล็อก และมีผลเมื่อเครื่องปิดอยู่ |
| แพ็กเกจปลอม | คลังไม่น่าเชื่อถือ | ใช้คลังทางการ ตรวจลายเซ็น (หัวข้อ 6.3) | เพิ่มคลังบุคคลที่สามคือยอมเชื่อเขา |
| ใช้ root ตลอด | พิมพ์ผิดคำสั่งเดียวพังทั้งระบบ | ผู้ใช้ปกติ + sudo | |

| `netplan apply` ฟ้อง error | มี Tab หรือเยื้องผิดใน YAML | ตรวจช่องว่าง ใช้ `netplan try` |
| ping IP ได้ แต่ ping ชื่อเว็บไม่ได้ | DNS ไม่ถูกตั้งหรือเข้าถึงไม่ได้ (เครือข่ายปกติ) | `resolvectl status`; แก้ `nameservers` |
| `apt install` ว่าหาแพ็กเกจไม่เจอ | รายการยังเก่า ไม่ได้ `apt update` หรือคลังไม่ได้เปิด | `sudo apt update` |
| `Could not get lock /var/lib/dpkg/lock` | มี apt/dpkg อื่นกำลังทำงาน (เช่น อัปเดตอัตโนมัติ) ล็อกกันเขียนชนกัน | รอให้เสร็จ อย่าลบไฟล์ล็อกมั่วๆ |
| ตั้งบริการแล้วรีบูตหาย | ใช้ `start` ไม่ได้ `enable` | `systemctl enable --now <บริการ>` |
| เข้า SSH ไม่ได้หลังเปิดไฟร์วอลล์ | ไม่ได้ `ufw allow ssh` ก่อน (default deny) | เข้าผ่านคอนโซล VM/คลาวด์แล้ว `ufw allow ssh` |
| `Connection refused` เทียบกับ `Connection timed out` ตอน SSH | refused = เครื่องปลายทางตอบปฏิเสธ (ไม่มีบริการฟังพอร์ตนั้น) ส่วน timed out = ไม่มีการตอบ (มักไฟร์วอลล์ทิ้งแพ็กเก็ต หรือเครื่องไม่ถึง) | refused → ตรวจว่า sshd ทำงานและฟังพอร์ต (`ss -tlnp`) ส่วน timeout → ตรวจไฟร์วอลล์/security group/เส้นทาง |

## 10. ฝึกทำ: แล็บบน VM

ฝึกบนเครื่องเสมือน (VirtualBox หรือ VMware) ปลอดภัยเพราะพังแล้วลบทิ้งได้

1. สร้าง VM: 2 คอร์, RAM 2048 MB, ดิสก์เสมือน 20 GB; ต่อ ISO ของ Ubuntu Server หรือ Debian
2. เดินตามตัวติดตั้ง แบ่งพาร์ทิชันเอง: `/boot/efi` 512 MB (FAT32), swap 2 GB, ที่เหลือ `/` (ext4); hostname `lab-node-01`, ผู้ดูแล `sysadmin`, ติ๊ก **OpenSSH server** แล้วรีบูต
3. ล็อกอิน แล้วรัน `lsblk -f` และ `cat /etc/fstab` เทียบ UUID ที่เห็นกับที่ fstab ใช้
4. รัน `df -h /` และ `df -i /` แล้วคำนวณจำนวน inode ที่ควรมีจากขนาดพาร์ทิชัน เทียบกับที่ได้
5. รัน `ip -br addr`, `ip route`, `resolvectl status` แล้วระบุ IP, gateway, DNS ของเครื่อง
6. `sudo apt update && sudo apt upgrade -y` แล้ว `sudo apt install -y tree`
7. `sudo systemctl status ssh` และ `journalctl -u ssh -n 5`
8. **ตั้งไฟร์วอลล์:** `sudo ufw allow ssh` ก่อน แล้ว `sudo ufw enable` จากนั้นรัน `ss -tlnp`
9. (ท้าทาย) ตั้ง SSH ใช้กุญแจ: สร้างคู่กุญแจจากเครื่องหลัก (`ssh-keygen -t ed25519`), `ssh-copy-id sysadmin@<IP>`, ทดสอบเข้าด้วยกุญแจ แล้วจึงตั้ง `PasswordAuthentication no` โดยเปิดเซสชันสำรองค้างไว้

::reveal{question="แนวคำตอบข้อ 3 และ 4"}
**ข้อ 3:** UUID ใน `lsblk -f` ควรตรงกับ UUID ที่ปรากฏใน `/etc/fstab` ของพาร์ทิชันเดียวกัน (swap, root, EFI) ถ้าติดตั้งอัตโนมัติ fstab จะใช้ UUID เสมอ
**ข้อ 4:** ถ้าพาร์ทิชัน root ประมาณ 17.5 GiB จำนวน inode ≈ 17.5 × 2³⁰ ÷ 16,384 ≈ 1.15 ล้าน (ค่าประมาณ ค่าจริงขึ้นกับการตั้งค่า mkfs ของแต่ละรุ่น) ใช้ `df -i` เทียบ
::

## 11. โจทย์คำนวณ

::reveal{question="โจทย์ 1: พาร์ทิชัน ext4 ขนาด 200 GiB ใช้ค่า 1 inode ต่อ 16 KiB จะมีกี่ inode และถ้าทุกไฟล์เล็กกว่า 4 KiB จะใส่ไฟล์ได้อย่างมากกี่ไฟล์"}
200 × 2³⁰ ÷ 16,384 = 200 × 65,536 = 13,107,200 inode จึงมีไฟล์ได้อย่างมาก ~13.1 ล้านไฟล์ (ไม่ว่าเล็กแค่ไหน) ตัวอย่างนี้ทำให้เห็นว่าไฟล์ขนาด 1 ไบต์สิบสามล้านไฟล์ใช้พื้นที่ข้อมูลน้อยมาก แต่ทำให้ inode หมดได้
::

::reveal{question="โจทย์ 2: ดิสก์ ext4 ขนาด 2 TB (2×10¹² ไบต์) กัน 5% ให้ root ผู้ใช้ทั่วไปใช้ได้เท่าใดโดยประมาณ"}
สำรอง 5% = 0.05 × 2×10¹² = 10¹¹ ไบต์ = 100 GB ผู้ใช้ทั่วไปใช้ได้ราว 1.9 TB (ยังไม่รวม metadata ของระบบไฟล์ ซึ่งเป็นค่าประมาณ) ถ้าเป็นดิสก์ข้อมูลล้วนที่ไม่ใช่ root อาจลดสำรองเหลือ 1% ด้วย tune2fs -m 1
::

::reveal{question="โจทย์ 3: ตั้ง IP 10.0.4.130/26 วงนี้มีกี่ที่อยู่ ใช้เป็นเครื่องได้กี่เครื่อง และที่อยู่เครือข่ายคืออะไร"}
/26 เหลือ 32 − 26 = 6 บิตสำหรับเครื่อง → 2⁶ = 64 ที่อยู่ ใช้ได้ 62 เครื่อง บล็อกขนาด 64 เริ่มที่ 0, 64, 128, 192 ใน octet สุดท้าย 130 อยู่ในบล็อก 128–191 ดังนั้นที่อยู่เครือข่ายคือ 10.0.4.128 และ broadcast คือ 10.0.4.191 เครื่องที่ใช้ได้คือ .129 ถึง .190
::

::reveal{question="โจทย์ 4: รหัสผ่านสุ่ม 10 ตัวอักษรจากชุด 62 ตัว (a-z, A-Z, 0-9) มีกี่บิต และสุ่ม 16 ตัวจากชุดเดียวกันต่างอย่างไร"}
10 ตัว: 62¹⁰ ≈ 8.4 × 10¹⁷ → log₂ ≈ 59.5 บิต ส่วน 16 ตัว: log₂(62¹⁶) ≈ 95.3 บิต ต่างกัน 95.3 − 59.5 ≈ 35.8 บิต หรือราว 2³⁶ ≈ 6.9 หมื่นล้านเท่า แปลว่าความยาวเพิ่มความยากเร็วกว่าความซับซ้อนของชุดอักขระ (ใช้ได้เมื่อรหัสสุ่มจริง)
::

## ตรวจความเข้าใจ

::reveal{question="ทำไมต้องมี initramfs ทั้งที่ kernel มีไดรเวอร์อยู่แล้ว"}
ไม่จำเป็นต้องมีไดรเวอร์ทุกตัวในตัว kernel (เพื่อให้ kernel เล็กและยืดหยุ่น) ไดรเวอร์ส่วนใหญ่เป็นโมดูลที่เก็บใน /lib/modules บน root แต่การอ่าน root ก็ต้องใช้ไดรเวอร์ จึงเป็นปัญหาไก่กับไข่ initramfs ถูกโหลดลง RAM พร้อม kernel และมีโมดูลที่จำเป็น (ดิสก์ RAID LVM การเข้ารหัส) เพื่อหา root จริงแล้วสลับไปใช้
::

::reveal{question="ทำไม fstab ควรใช้ UUID แทน /dev/sdb1"}
เพราะชื่อ sdX กำหนดตามลำดับที่ kernel พบอุปกรณ์ ซึ่งเปลี่ยนได้เมื่อเสียบอุปกรณ์เพิ่มหรือสลับสาย ทำให้เมาท์ผิดดิสก์ UUID เก็บอยู่ในระบบไฟล์เอง จึงชี้ไปที่ดิสก์ที่ตั้งใจเสมอ
::

::reveal{question="df -h บอกว่าเหลือพื้นที่ แต่สร้างไฟล์ใหม่ไม่ได้ เกิดอะไรขึ้น และตรวจอย่างไร"}
น่าจะ inode หมด ext4 กำหนดจำนวน inode ตอน format และทุกไฟล์ใช้ 1 inode ไม่ว่าเล็กแค่ไหน ไฟล์เล็กจำนวนล้านไฟล์ทำให้ inode หมดก่อนพื้นที่ ตรวจด้วย df -i ดูคอลัมน์ IUse% แก้โดยลบไฟล์เล็กที่ไม่จำเป็น หรือ format ใหม่ด้วยอัตรา inode ที่สูงกว่า
::

::reveal{question="start กับ enable ต่างกันอย่างไร และ enable --now ทำอะไร"}
start สั่งให้บริการทำงานตอนนี้ แต่ไม่ได้บันทึกว่าต้องเริ่มตอนบูต จึงหายหลังรีบูต enable สร้าง symlink ใน target.wants ให้บริการเริ่มทุกครั้งที่ถึง target นั้นตอนบูต แต่ไม่ได้เริ่มทันที enable --now รวมทั้งสองอย่าง
::

::reveal{question="apt ป้องกันแพ็กเกจปลอมหรือถูกแก้ระหว่างทางอย่างไร"}
เป็นห่วงโซ่แฮช: ลายเซ็น GPG ยืนยันไฟล์ Release (ตรวจด้วยกุญแจที่ติดตั้งไว้แล้ว) Release มีแฮชของไฟล์ Packages ซึ่งมีแฮชของแต่ละ .deb ถ้าชั้นใดไม่ตรง apt ปฏิเสธ แต่ไม่ได้รับประกันว่าแพ็กเกจไม่มีช่องโหว่ และคลังบุคคลที่สามที่เราเพิ่มเองคือการยอมเชื่อเขา
::

::reveal{question="จะเกิดอะไรขึ้นถ้ารัน ufw enable บนเซิร์ฟเวอร์ระยะไกลโดยไม่ได้ ufw allow ssh ก่อน และจะแก้อย่างไร"}
ค่าเริ่มต้นปฏิเสธขาเข้าทั้งหมดรวมพอร์ต 22 การเชื่อมต่อ SSH ที่เปิดอยู่อาจถูกตัด และเข้าใหม่ไม่ได้ ต้องแก้ผ่านคอนโซลของเครื่อง/ผู้ให้บริการคลาวด์ด้วย ufw allow ssh การป้องกันคือสั่ง allow ก่อน enable เสมอ
::

::reveal{question="SSH ขึ้นว่า Connection refused กับ Connection timed out ต่างกันอย่างไร และบอกอะไรเรา"}
refused หมายความว่าแพ็กเกจไปถึงเครื่องปลายทางแล้ว แต่ไม่มีโปรแกรมฟังพอร์ตนั้น (หรือถูกปฏิเสธอย่างชัดเจน) ควรตรวจว่า sshd ทำงานและฟังพอร์ตอยู่ไหม ส่วน timed out คือไม่มีใครตอบเลย มักเกิดจากไฟร์วอลล์ทิ้งแพ็กเกจ หรือเครื่อง/เส้นทางไม่ถึง ควรตรวจไฟร์วอลล์ security group และเส้นทางเครือข่าย
::

::reveal{question="ทำไมส่วนใหญ่ไม่ล็อกอินเป็น root ตรงๆ และใช้ sudo แทน"}
เพื่อหลักสิทธิ์น้อยที่สุด ผู้ใช้ปกติยกระดับสิทธิ์เฉพาะคำสั่งที่จำเป็น มีบันทึกว่าใครทำอะไร (ตรวจสอบย้อนหลังได้ เทียบกับ root ที่ใครก็ใช้รหัสเดียวกัน) และผู้โจมตีที่เดาได้ต้องเดาชื่อผู้ใช้ด้วย ไม่ใช่แค่รหัสของ root ที่ทุกคนรู้ว่ามีชื่อนี้
::

## สรุป

- **Kernel + เครื่องมือ = distribution** ตระกูล Debian (apt) และ Red Hat (dnf) ใช้แนวคิดเดียวกัน
- **ลำดับบูต:** UEFI → GRUB → kernel + initramfs (แก้ปัญหาไก่กับไข่ของไดรเวอร์) → mount root → systemd (PID 1) → บริการและหน้าล็อกอิน
- **ต้นไม้เดียว** ต่อดิสก์ด้วย mount ตาม **fstab (ใช้ UUID)**; ext4/xfs มี journal; inode, พื้นที่สำรอง 5%, swap ล้วนคำนวณได้และอธิบายอาการ "ดิสก์เต็มแต่ยังว่าง"
- **ตัวตน:** UID, แฮชรหัสผ่านใน shadow (มี salt), ใช้ผู้ใช้ปกติ + sudo ตามสิทธิ์น้อยที่สุด
- **เครือข่าย:** IP/CIDR → gateway → DNS ไล่ตรวจทีละชั้น; Netplan ห้าม Tab และใช้ `netplan try` กันล็อกตัวเอง
- **ซอฟต์แวร์:** apt ตรวจห่วงโซ่ลายเซ็น → Release → Packages → .deb
- **systemd:** active ≠ enabled; `enable --now` ทำทั้งสอง
- **ป้องกัน:** ไฟร์วอลล์ default deny **อนุญาต SSH ก่อนเปิดเสมอ**; SSH ใช้กุญแจ ปิด root; ตรวจพื้นผิวด้วย `ss -tlnp`
- บทถัดไป: ใช้งานระบบผ่าน GUI และ CLI อย่างคล่อง
