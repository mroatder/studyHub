## วัตถุประสงค์การเรียนรู้

เมื่อจบบทนี้ คุณควรจะ

1. อธิบายความต่างของ **kernel** กับ **distribution** และบอกได้ว่าตระกูล Debian กับ Red Hat ต่างกันอย่างไร
2. อธิบายได้ว่าทำไม Linux ไม่มีตัวอักษรไดรฟ์ (C:) แต่ใช้ **ต้นไม้ไดเรกทอรี** และ **mount point** และอ่านชื่ออุปกรณ์อย่าง `/dev/sda1` กับ `/dev/nvme0n1p1` ได้
3. เล่าขั้นตอนของตัวติดตั้ง 5 ขั้น และลำดับการบูตตั้งแต่ UEFI → GRUB → kernel → systemd
4. ตั้งค่าเครือข่ายด้วย `ip` และ Netplan พร้อมรู้กับดักของ YAML
5. อัปเดตและติดตั้งโปรแกรมด้วย `apt` / `dnf` ได้ รู้ว่า `update` กับ `upgrade` ต่างกันอย่างไร
6. ควบคุมบริการด้วย `systemctl` และอ่านสถานะ `enabled` / `active` เป็น
7. ตั้งไฟร์วอลล์ `ufw` ถูกลำดับ ไม่ล็อกตัวเองออกจากเซิร์ฟเวอร์

## สรุปสั้น (TL;DR)

Linux คือ **kernel** ที่ถูกประกอบกับเครื่องมืออื่นๆ จนเป็นระบบที่ใช้งานได้เรียกว่า **distribution** การติดตั้งประกอบด้วยการแบ่งดิสก์ (EFI + root + swap), ตั้งชื่อเครื่องและผู้ใช้, เขียน bootloader (GRUB) หลังบูตครั้งแรกต้องตรวจเครือข่าย อัปเดตแพ็กเกจ ตั้งบริการด้วย `systemctl` และเปิดไฟร์วอลล์ แต่ต้อง **อนุญาต SSH ก่อนเปิดไฟร์วอลล์เสมอ**

## 1. Linux Distributions

### 1.1 Kernel กับ Distribution

**Kernel** คือแกนกลางของ Linux ทำหน้าที่คุมฮาร์ดแวร์ (CPU, หน่วยความจำ, ดิสก์) และให้โปรแกรมต่างๆ ใช้ทรัพยากรผ่านระบบเรียก (system call) แต่ kernel อย่างเดียวไม่มีหน้าจอ ไม่มีเครื่องมือจัดการ จึงต้องมีคนนำมาประกอบ ใครก็นำ kernel มาประกอบได้เพราะเป็นซอฟต์แวร์โอเพนซอร์ส กดทีละชั้นเพื่อดูว่า distribution ประกอบด้วยอะไรบ้าง

เมื่อรวมทุกชั้นแล้ว เรียกว่า **distribution** หรือ **distro** เหมือนรถหนึ่งรุ่น

## 2. พาร์ทิชันและต้นไม้ไดเรกทอรี

### 2.1 ทำไม Linux ไม่มี C: D:

Windows ให้แต่ละพาร์ทิชันมีตัวอักษรไดรฟ์ของตัวเอง Linux ออกแบบต่าง: มี **ต้นไม้เดียว** ที่ราก `/` ทุกอย่างทั้งดิสก์ พาร์ทิชัน แฟลชไดรฟ์ แม้แต่อุปกรณ์ ต้อง "ต่อ" (mount) เข้ากับโฟลเดอร์ใดโฟลเดอร์หนึ่งในต้นไม้นี้ จุดต่อเรียกว่า **mount point** ข้อดีคือโปรแกรมไม่ต้องรู้ว่าไฟล์อยู่ดิสก์ลูกไหน ย้ายโฟลเดอร์ใหญ่ไปดิสก์ใหม่ได้โดยแค่เปลี่ยนที่ต่อ

โครงสร้างโฟลเดอร์ใต้ `/` มีมาตรฐานเรียกว่า **FHS** (Filesystem Hierarchy Standard) ที่ควรรู้

| โฟลเดอร์ | เก็บอะไร |
|---|---|
| `/boot` | kernel และไฟล์ที่ใช้ตอนบูต (EFI อยู่ที่ `/boot/efi`) |
| `/etc` | ไฟล์ตั้งค่าของระบบและบริการ (เช่น `/etc/netplan/`) |
| `/home` | โฟลเดอร์ส่วนตัวของผู้ใช้แต่ละคน |
| `/var` | ข้อมูลที่เปลี่ยนตลอด เช่น บันทึก (`/var/log`) |
| `/usr` | โปรแกรมและไลบรารีส่วนใหญ่ |
| `/dev` | ไฟล์แทนอุปกรณ์ เช่น `sda` |
| `/tmp` | ไฟล์ชั่วคราว |

### 2.2 พาร์ทิชันหลัก 3 ก้อนและชื่ออุปกรณ์

การติดตั้งแบบทั่วไปแบ่งดิสก์เป็น 3 ก้อน ลองกดแต่ละก้อนเพื่อดูว่าไปต่อที่โฟลเดอร์ไหน และสลับชนิดดิสก์เพื่อดูการตั้งชื่อ

::linux-mounts
::

- **EFI System Partition** (ต่อที่ `/boot/efi`): เล็ก ราว 500 MB ถึง 1 GB เป็น FAT32 เฟิร์มแวร์ UEFI อ่านพาร์ทิชันนี้เพื่อหาบูตโหลดเดอร์ ถ้าไม่มี เครื่องบูตไม่ได้ (นี่คือคำตอบของคำถามท้ายบท)
- **Root** (ต่อที่ `/`): เก็บระบบปฏิบัติการ แอป บันทึก ใช้ระบบไฟล์ **ext4** หรือ **xfs**
- **Swap**: พื้นที่ล้นของ RAM

**ext4 และ xfs** ต่างจาก NTFS ตรงที่ออกแบบมาสำหรับ Linux ทั้งคู่มี journaling เหมือน NTFS (กู้ได้เมื่อไฟดับ) ext4 เป็นค่าเริ่มต้นของตระกูล Debian ส่วน xfs นิยมในตระกูล Red Hat เพราะรับไฟล์ใหญ่และดิสก์ขนาดมากได้ดี

**Swap ทำงานอย่างไร** เมื่อ RAM เต็ม kernel จะเลือกข้อมูลที่ไม่ได้ใช้นานย้ายไปไว้ใน swap เพื่อเอาที่ว่างให้โปรแกรมที่กำลังใช้ ดังนั้นแม้มี RAM เยอะก็ยังใช้ swap เพราะ kernel นำหน่วยความจำที่ว่างไปทำแคชไฟล์ และย้ายข้อมูลที่ไม่ค่อยใช้ออกเพื่อรักษาประสิทธิภาพ แต่ถ้าต้องใช้ swap มากๆ ระบบจะช้าลงมากเพราะดิสก์ช้ากว่า RAM หลายเท่า (ดูแอนิเมชัน RAM ↔ swap ในบทที่ 1) นอกจากนี้ swap ยังเป็นที่เก็บเมื่อจะ hibernate

> ชื่ออุปกรณ์: ดิสก์ SATA เป็น `/dev/sda` พาร์ทิชันแรกเป็น `/dev/sda1` ส่วน NVMe เป็น `/dev/nvme0n1` และพาร์ทิชันแรกเป็น `/dev/nvme0n1p1` (มี `p` คั่น เพราะชื่อดิสก์ลงท้ายด้วยตัวเลข)

### 4.1 ตั้ง IP แบบคงที่ด้วย Netplan

DHCP แจกที่อยู่ให้อัตโนมัติ แต่เซิร์ฟเวอร์ควรมี IP **คงที่** เพื่อให้คนและระบบอื่นหาเจอเสมอ บน Ubuntu/Debian รุ่นใหม่ใช้ **Netplan** ซึ่งอ่านไฟล์ YAML จาก `/etc/netplan/`

```yaml
# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp3s0:
      dhcp4: no
      addresses:
        - 192.168.1.50/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [1.1.1.1, 8.8.8.8]
```

| บรรทัด | ความหมาย |
|---|---|
| `renderer: networkd` | ให้ systemd-networkd เป็นตัวปรับค่าเครือข่ายจริง |
| `dhcp4: no` | ปิดการรับ IP อัตโนมัติ |
| `addresses` | IP และขนาดเครือข่าย (CIDR) ของเครื่องนี้ |
| `routes ... via` | gateway ที่ใช้ออกไปเครือข่ายอื่น |
| `nameservers` | เซิร์ฟเวอร์ DNS ที่ใช้แปลงชื่อเป็น IP |

สั่งให้มีผลด้วย `sudo netplan apply` (ไม่ต้องรีบูต)

> **กับดัก:** YAML ใช้ **ช่องว่าง (space) เท่านั้น ห้ามใช้ Tab** ถ้ามี Tab แม้ตัวเดียว `netplan apply` จะปฏิเสธไฟล์ และอินเทอร์เฟซจะไม่ถูกตั้งค่า ถ้าทำบนเซิร์ฟเวอร์ที่เข้าทางไกลอยู่ อาจขาดการเชื่อมต่อ ควรใช้ `sudo netplan try` ที่จะย้อนค่าเดิมเองถ้าไม่ยืนยันภายในเวลาที่กำหนด

## 6. ตั้งค่าบริการด้วย systemd

**systemd** คือโปรเซสแรกที่ kernel เรียกตอนบูต (PID 1) และเป็นผู้เริ่มและดูแลบริการ (service/daemon) ทั้งหมด เช่น SSH, เว็บเซิร์ฟเวอร์ สั่งงานด้วย `systemctl` สถานะของบริการมี **สองมิติ** ที่ไม่เหมือนกัน

| มิติ | คำถามที่ตอบ | ค่า |
|---|---|---|
| Active | ตอนนี้ทำงานอยู่ไหม | `active (running)` / `inactive` / `failed` |
| Enabled | จะเริ่มเองตอนบูตไหม | `enabled` / `disabled` |

ดังนั้นบริการอาจ "กำลังทำงานแต่ไม่ถูก enable" (รันอยู่แต่รีบูตแล้วหาย) หรือ "enabled แต่ไม่ได้ทำงานตอนนี้" ลองกดสั่งงาน

## 7. ความปลอดภัยของโฮสต์เบื้องต้น

เครื่องที่เพิ่งติดตั้งอาจเปิดพอร์ตให้ทั้งเครือข่ายเข้าถึงได้ ก่อนใช้งานต้องกำหนดขอบเขต Ubuntu/Debian มี **ufw** (Uncomplicated Firewall) ซึ่งเป็นตัวสั่งงานง่ายๆ ของระบบกรองแพ็กเก็ตใน kernel (netfilter, สร้างกฎผ่าน iptables/nftables)

**หลัก default deny:** ปฏิเสธขาเข้าทั้งหมด แล้วอนุญาตเฉพาะที่จำเป็น (อนุญาตขาออกไว้) เพราะการตั้งแบบอนุญาตทุกอย่างแล้วค่อยปิดทีละอย่างจะลืมปิดง่ายและผิดหลักปลอดภัย

### 7.1 กับดักที่ทำให้ล็อกตัวเองออก

ถ้าคุณกำลังจัดการเซิร์ฟเวอร์ผ่าน SSH (พอร์ต 22) แล้วเปิดไฟร์วอลล์ที่ปฏิเสธขาเข้าทั้งหมดก่อนอนุญาตพอร์ต 22 การเชื่อมต่อของคุณจะถูกตัดทันที ลองทั้งสองลำดับ

::ufw-lockout
::

คำสั่งที่ถูกต้องตามลำดับ

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh          # ต้องทำก่อนเปิดไฟร์วอลล์
sudo ufw enable
sudo ufw status verbose     # ตรวจกฎ
```

## มุมมองด้าน Security

- **หลักสิทธิ์น้อยที่สุด:** ใช้ผู้ใช้ปกติ + `sudo` ไม่ล็อกอินเป็น root และตรวจ log การใช้ sudo ได้ที่ `/var/log/auth.log`
- **SSH คือประตูหลักของเซิร์ฟเวอร์:** บอทบนอินเทอร์เน็ตสแกนพอร์ต 22 ตลอดเวลา แนวทางเสริมที่พบทั่วไป คือใช้คู่กุญแจ (key-based authentication) แทนรหัสผ่าน ปิดการล็อกอิน root ผ่าน SSH และใช้เครื่องมืออย่าง fail2ban บล็อก IP ที่ลองรหัสผ่านผิดซ้ำ
- **อัปเดตเสมอ:** ช่องโหว่ที่รู้แล้วคือเส้นทางโจมตีที่พบมากที่สุด ตั้ง `unattended-upgrades` ให้แพตช์ความปลอดภัยลงเองได้
- **ลดพื้นผิวโจมตี:** ติดตั้งเฉพาะที่ต้องใช้ ปิดบริการที่ไม่ใช้ (`systemctl disable --now`) และดูพอร์ตที่เปิดด้วย `ss -tlnp`
- **ติดตั้งจากภาพทางการ:** ตรวจ checksum (SHA-256) และลายเซ็นของไฟล์ ISO ก่อนเขียนลง USB
- **เข้ารหัสดิสก์:** ตัวติดตั้งหลายตัวเสนอ LUKS (เข้ารหัสทั้งดิสก์) ควรเปิดบนแล็ปท็อปที่อาจหาย
- **สำรองก่อนแก้ระบบเครือข่าย/ไฟร์วอลล์:** เพราะความผิดพลาดตรงนี้ทำให้เข้าเครื่องทางไกลไม่ได้ ดังที่เห็นในแอนิเมชัน

## ฝึกทำ: แล็บบน VM

ต้นฉบับแนะนำให้ฝึกบนเครื่องเสมือน (VirtualBox หรือ VMware) ซึ่งปลอดภัยเพราะพังแล้วลบทิ้งได้ ทำตามลำดับนี้

1. สร้าง VM: CPU 2 คอร์, RAM 2048 MB, ดิสก์เสมือน 20 GB
2. ต่อไฟล์ ISO ของ Ubuntu Server หรือ Debian เข้ากับซีดีไดรฟ์เสมือน
3. บูตและเดินตามตัวติดตั้ง แบ่งพาร์ทิชันเอง: `/boot/efi` 512 MB (FAT32), swap 2 GB, ที่เหลือเป็น `/` (ext4) ตั้ง hostname `lab-node-01` ผู้ดูแล `sysadmin` และติ๊ก **OpenSSH server** แล้วรีบูต
4. ล็อกอินด้วย `sysadmin` รัน `ip -br addr` ดู IP และชื่ออินเทอร์เฟซ
5. รัน `sudo apt update && sudo apt install -y tree`
6. ตรวจ SSH ด้วย `sudo systemctl status ssh`
7. เปิด ufw โดย **อนุญาตพอร์ต 22 ก่อน**
8. (เพิ่มเติม) ลองใช้ `tree -L 1 /` ดูโครงสร้างระดับแรกของต้นไม้ เทียบกับตารางโฟลเดอร์ด้านบน

## ตรวจความเข้าใจ

คิดคำตอบในใจก่อน แล้วกดดูเฉลย (สี่ข้อแรกเป็นคำถามท้ายบทต้นฉบับ)

::reveal{question="apt update กับ apt upgrade ต่างกันอย่างไร"}
`apt update` ดาวน์โหลดรายการแพ็กเกจและเวอร์ชันล่าสุดจากคลังมาเก็บในเครื่อง ไม่ได้ติดตั้งหรือเปลี่ยนโปรแกรมใดๆ ส่วน `apt upgrade` เอาเวอร์ชันที่ติดตั้งไปเทียบกับรายการนั้น แล้วดาวน์โหลดและติดตั้งรุ่นใหม่ ต้องรัน update ก่อนเสมอเพื่อให้ upgrade รู้ว่ามีอะไรใหม่
::

::reveal{question="ทำไม Linux ในฮาร์ดแวร์ยุคใหม่ต้องมีพาร์ทิชัน EFI แยก"}
เพราะเฟิร์มแวร์ UEFI ไม่ได้อ่านระบบไฟล์ของ Linux (ext4) ได้ มันอ่านได้แค่ FAT32 จึงต้องมีพาร์ทิชัน EFI ขนาดเล็กแบบ FAT32 ที่เก็บบูตโหลดเดอร์ (GRUB) ให้เฟิร์มแวร์หาเจอแล้วส่งต่อให้โหลด kernel
::

::reveal{question="จะเกิดอะไรขึ้นถ้ารัน ufw enable บนเซิร์ฟเวอร์ระยะไกลโดยไม่ได้ ufw allow ssh ก่อน"}
ค่าเริ่มต้นคือปฏิเสธขาเข้าทั้งหมด รวมพอร์ต 22 ที่ SSH ใช้ การเชื่อมต่อที่เปิดอยู่จะถูกตัด และเข้าใหม่ไม่ได้ ต้องเข้าผ่านคอนโซลของเครื่อง/ผู้ให้บริการคลาวด์เพื่อแก้
::

::reveal{question="ถ้ามี RAM จริงอยู่แล้ว ทำไม Linux ยังใช้ swap"}
เมื่อ RAM เต็ม kernel ย้ายข้อมูลที่ไม่ค่อยใช้ออกไป swap เพื่อให้โปรแกรมที่กำลังทำงานมีที่ว่าง และ kernel ยังใช้ RAM ที่ว่างไปทำแคชไฟล์เพื่อให้เร็วขึ้น swap ช่วยไม่ให้โปรแกรมถูกฆ่าเมื่อหน่วยความจำไม่พอ และใช้เป็นที่เก็บเมื่อ hibernate แต่ถ้าใช้มากระบบจะช้า
::

::reveal{question="โจทย์: ติดตั้ง Nginx แล้วต้องการให้เริ่มทำงานตอนนี้และทุกครั้งที่รีบูต ใช้คำสั่งใด"}
`sudo systemctl enable --now nginx` เพราะ `--now` สั่งเริ่มทันที ส่วน `enable` ตั้งให้เริ่มทุกครั้งที่บูต ถ้าใช้ `start` อย่างเดียวจะหายเมื่อรีบูต ส่วน `reload` สั่งให้โหลดการตั้งค่าใหม่ และ `status` แค่ดูสถานะ
::

::reveal{question="ดิสก์ NVMe ตัวแรกพาร์ทิชันแรกชื่ออะไร และต่างจาก SATA อย่างไร"}
`/dev/nvme0n1p1` ส่วน SATA เป็น `/dev/sda1` NVMe มีตัว `p` คั่นก่อนเลขพาร์ทิชันเพราะชื่อดิสก์ลงท้ายด้วยตัวเลข (`n1`) ถ้าไม่คั่นจะแยกเลขดิสก์กับเลขพาร์ทิชันไม่ออก
::

::reveal{question="ทำไมส่วนใหญ่ติดตั้ง Linux แล้วไม่เปิดให้ล็อกอิน root โดยตรง"}
เพื่อให้ทำตามหลักสิทธิ์น้อยที่สุด ผู้ใช้ปกติยกระดับสิทธิ์ด้วย sudo เฉพาะคำสั่งที่จำเป็นพร้อมใส่รหัสผ่านของตนเอง ระบบบันทึกว่าใครทำอะไร และไม่มีบัญชี root ที่โจมตีเดารหัสผ่านได้ตรงๆ
::

## สรุป

- **kernel** คือแกนกลาง **distribution** คือ kernel + เครื่องมือ มีสองตระกูลหลัก Debian (apt) และ Red Hat (dnf)
- Linux ใช้ **ต้นไม้เดียวที่ `/`** และ mount point ไม่มีตัวอักษรไดรฟ์ พาร์ทิชันหลักคือ EFI (FAT32, `/boot/efi`), root (`/`, ext4/xfs) และ swap
- ตัวติดตั้ง 5 ขั้น: ภาษา → เครือข่าย → ดิสก์ → ตัวตน (sudo) → ซอฟต์แวร์ฐาน แล้วเขียน GRUB ลง EFI
- หลังบูต: ตรวจเครือข่าย (`ip -br addr`, Netplan ห้ามใช้ Tab) → `apt update` แล้ว `upgrade` → ตั้งบริการด้วย `systemctl` → เปิด `ufw` โดย **allow ssh ก่อน**
- บทถัดไปคือการใช้งานระบบปฏิบัติการผ่านทั้งหน้าจอกราฟิก (GUI) และบรรทัดคำสั่ง (CLI)
