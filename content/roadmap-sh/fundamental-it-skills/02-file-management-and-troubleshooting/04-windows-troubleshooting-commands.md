## วัตถุประสงค์การเรียนรู้

เมื่อจบบทนี้ คุณควรจะ

1. อ่านผลลัพธ์ `ipconfig` และ `ipconfig /all` แล้วบอกได้ว่า IP, subnet mask, default gateway ปกติหรือไม่ และรู้จัก **APIPA (169.254.x.x)**
2. ใช้ `/release`, `/renew`, `/flushdns` ให้ตรงกับอาการ
3. ใช้ `tasklist` หา PID และ `taskkill` ปิดโปรเซสด้วย `/PID`, `/IM`, `/F`, `/T` อย่างรู้ผลข้างเคียง
4. อธิบายหน้าที่ของ `sfc /scannow` กับ `DISM` และลำดับที่ถูกต้องเมื่อซ่อมไม่สำเร็จ
5. แยกความต่างของ `chkdsk`, `/f`, `/r` และเข้าใจว่าทำไมไดรฟ์ที่ใช้อยู่ต้องรอรีสตาร์ต
6. ใช้ `systeminfo` กับ `findstr` ดึงข้อมูลที่ต้องการได้
7. เลือกคำสั่งแรกให้เหมาะกับอาการ และรู้ข้อควรระวังด้านความปลอดภัยของแต่ละคำสั่ง

## สรุปสั้น (TL;DR)

เมื่อหน้าจอกราฟิกค้างหรือช้า **บรรทัดคำสั่งยังเข้าถึงสภาพเครื่องได้โดยตรง** ชุดคำสั่งหลักคือ

| ปัญหา | คำสั่ง |
|---|---|
| เครือข่าย | `ipconfig`, `ipconfig /all`, `/release`, `/renew`, `/flushdns` |
| โปรแกรมค้าง/กินทรัพยากร | `tasklist`, `taskkill` |
| ไฟล์ระบบเสีย | `sfc /scannow` (ถ้าซ่อมไม่ได้ ให้ `DISM` ก่อน แล้ว `sfc` ใหม่) |
| ดิสก์/ระบบไฟล์ผิดพลาด | `chkdsk` (`/f` แก้โครงสร้าง, `/r` หาเซกเตอร์เสียด้วย) |
| ข้อมูลเครื่อง | `systeminfo` |

กฎเหล็ก: **ดูก่อน แก้ทีหลัง** คำสั่งโหมดอ่านอย่างเดียวมาก่อนเสมอ และ `taskkill /F`, `chkdsk /r` ต้องรู้ผลข้างเคียงก่อนกด

## เปรียบเทียบกับชีวิตจริง

นึกถึง **ช่างที่ตรวจรถด้วยเครื่องมือเฉพาะทาง** แทนการเดาจากเสียง

| ช่างรถ | คำสั่ง Windows |
|---|---|
| ดูป้ายทะเบียนและที่อยู่ ว่ารถวิ่งในเส้นทางไหน | `ipconfig` (เครื่องมีที่อยู่และทางออกหรือเปล่า) |
| ตรวจว่ามีงานอะไรกินเครื่องอยู่ แล้วสั่งดับงานที่ค้าง | `tasklist` / `taskkill` |
| สแกนชิ้นส่วนเครื่องยนต์เทียบกับอะไหล่แท้ แล้วเปลี่ยนชิ้นที่เสีย | `sfc /scannow` |
| ถ้าคลังอะไหล่เสียหาย ต้องซ่อมคลังก่อนจึงเปลี่ยนชิ้นได้ | `DISM` แล้วค่อย `sfc` |
| ตรวจสภาพถังและท่อน้ำมัน | `chkdsk` |
| อ่านสมุดรายการรถ (รุ่น ปีผลิต หมายเลขตัวถัง) | `systeminfo` |

## ภาพรวม

ต้นฉบับเริ่มจากสถานการณ์ที่เจอบ่อย เช่น เครื่องหาเครื่องพิมพ์ที่แชร์ไม่เจอ หรือเปิดโฟลเดอร์ใหญ่แล้วค้าง แล้วไล่คำสั่งเป็นกลุ่ม: เครือข่าย โปรเซส ไฟล์ระบบ ดิสก์ และข้อมูลระบบ เราจะเดินตามลำดับนั้น เสริมกลไกเบื้องหลังว่าแต่ละคำสั่งทำอะไรกับระบบ และเชื่อมกับวงจรแก้ปัญหา 6 ขั้นจากบทที่แล้ว

> **ก่อนเริ่ม:** เปิดหน้าต่าง Command Prompt แบบปกติสำหรับ `ipconfig`, `tasklist`, `systeminfo` ส่วน `sfc`, `DISM`, `chkdsk /f` ต้องเปิดแบบ **Run as administrator** (ค้นหา "cmd" แล้วคลิกขวา) ถ้าไม่ใช่จะขึ้นข้อความว่าต้องใช้สิทธิ์ผู้ดูแล

## 1. ตรวจเครือข่ายด้วย ipconfig

ปัญหาเชื่อมต่อส่วนใหญ่มาจากสามเรื่อง: ไม่ได้ IP, ไม่มีเกตเวย์ หรือแคชชื่อเก่า `ipconfig` (Internet Protocol Configuration) ใช้ดูและรีเซ็ตสถานะของการ์ดเครือข่าย (network adapter)

พิมพ์เฉยๆ จะได้สรุปของแต่ละอะแดปเตอร์ ค่าที่ต้องดูมี 3 ตัว

| ค่า | ความหมาย | ถ้าผิดปกติ |
|---|---|---|
| **IPv4 Address** | ที่อยู่ของเครื่องในเครือข่าย | ขึ้นต้น `169.254` = APIPA ไม่ได้ IP จริง |
| **Subnet Mask** | ขอบเขตของเครือข่ายเดียวกัน | ไม่ตรงกับเครือข่ายจริง = ตั้งค่าผิด |
| **Default Gateway** | ประตูออกสู่เครือข่ายอื่น (ปกติคือเราเตอร์) | ว่าง = ออกนอกวงไม่ได้ |

**APIPA (Automatic Private IP Addressing)** คือกลไกสำรองของ Windows: เมื่อเครื่องขอ IP จากเซิร์ฟเวอร์ DHCP แล้วไม่มีใครตอบ จะสุ่มหมายเลขช่วง `169.254.0.0/16` ให้ตัวเอง ทำให้คุยกับเครื่องที่ได้ช่วงเดียวกันบนสายเดียวกันได้ แต่ **ไม่มีเกตเวย์จึงออกอินเทอร์เน็ตไม่ได้** สัญญาณนี้ชี้ไปที่ DHCP/สาย/Wi-Fi ไม่ใช่ที่เว็บหรือ DNS

กดสลับสามสถานการณ์ แล้วกดแต่ละบรรทัดดูความหมายและข้อสรุป

### 1.1 /release, /renew และ /flushdns

DHCP ทำงานแบบ **เช่า IP**: เซิร์ฟเวอร์ให้เครื่องใช้ที่อยู่ชั่วระยะหนึ่ง (lease) แล้วต่อสัญญาเป็นช่วงๆ

| คำสั่ง | ทำอะไร | ใช้เมื่อ |
|---|---|---|
| `ipconfig /release` | คืน IP ที่เช่าอยู่ เครื่องไม่มีที่อยู่ชั่วคราว | ได้ IP ผิด/ซ้ำ ต้องการเริ่มขอใหม่ |
| `ipconfig /renew` | ขอ IP ใหม่จาก DHCP | ใช้ต่อจาก `/release` หรือเมื่อเพิ่งเสียบสาย/เปลี่ยนเครือข่าย |
| `ipconfig /flushdns` | ล้างแคชการแปลงชื่อเป็น IP | เข้าเว็บ/ระบบภายในไม่ได้ทั้งที่คนอื่นเข้าได้ |

> **ข้อควรระวัง (ส่วนเสริมจากผู้เขียน):** อย่าสั่ง `/release` ผ่านรีโมต (RDP/SSH) บนเครื่องที่คุณต่อเข้าไป เพราะ IP หายแล้วการเชื่อมต่อของคุณขาดทันที และเครื่องอาจไม่กลับมาให้เข้าถึง ถ้าไม่ได้ `/renew` ได้เอง

## 2. จัดการโปรเซสด้วย tasklist และ taskkill

เมื่อเครื่องช้าเพราะโปรแกรมใดกินทรัพยากร Task Manager แบบกราฟิกอาจค้างไปด้วย `tasklist` แสดงรายการโปรเซส (process: โปรแกรมที่กำลังรัน) จากบรรทัดคำสั่ง

::terminal-sim{title="หาโปรเซสที่กินหน่วยความจำ" prompt="C:⧵>" :commands='[{"cmd":"tasklist","out":"Image Name                     PID Session Name        Session#    Mem Usage⏎========================= ======== ================ =========== ============⏎System Idle Process              0 Services                   0          8 K⏎System                           4 Services                   0        140 K⏎explorer.exe                  3812 Console                    1    112,430 K⏎report_generator.exe          7104 Console                    1  1,845,120 K⏎cmd.exe                       5408 Console                    1      4,112 K","note":"report_generator.exe ใช้หน่วยความจำราว 1.8 GB สูงกว่าตัวอื่นมาก (เลขเป็นตัวอย่าง) จดค่า PID 7104 ไว้ใช้ต่อ"},{"cmd":"tasklist | findstr report","out":"report_generator.exe          7104 Console                    1  1,845,120 K","note":"กรองเฉพาะบรรทัดที่มีคำว่า report ด้วย findstr เหมาะกับรายการยาว (เครื่องจริงมีหลายร้อยบรรทัด)"}]'}
::

คอลัมน์ที่ใช้ตัดสิน

| คอลัมน์ | ความหมาย |
|---|---|
| **Image Name** | ชื่อไฟล์โปรแกรมที่รัน |
| **PID** | หมายเลขโปรเซสที่เคอร์เนลกำหนดให้ **ไม่ซ้ำกันขณะรัน** และเปลี่ยนทุกครั้งที่เปิดใหม่ |
| **Session Name** | `Services` = งานเบื้องหลังของระบบ, `Console` = ของผู้ใช้ที่ล็อกอินหน้าเครื่อง |
| **Mem Usage** | หน่วยความจำที่โปรเซสถืออยู่ตอนนี้ (หน่วย K = กิโลไบต์) |

> **เสริม:** `tasklist /FI "IMAGENAME eq notepad.exe"` กรองด้วยเงื่อนไขในตัวคำสั่ง และ `tasklist /SVC` แสดงว่าโปรเซสไหนรันบริการ (service) อะไร มีประโยชน์เมื่อชื่อโปรเซสอย่าง `svchost.exe` ไม่บอกอะไร

### 2.1 taskkill: ปิดโปรเซสที่ไม่ตอบสนอง

`taskkill` ปิดโปรเซสโดยระบุเลข PID (`/PID`) หรือชื่อไฟล์ (`/IM` = image name) ตัวเลือกที่ต้องรู้

| ตัวเลือก | ความหมาย |
|---|---|
| `/PID 7104` | ระบุด้วยหมายเลขโปรเซส ตรงตัวที่สุด ไม่พลาดตัวอื่น |
| `/IM name.exe` | ระบุด้วยชื่อ ปิด **ทุกโปรเซสที่ชื่อนี้** ซึ่งอาจมีหลายตัว |
| `/F` | บังคับยุติทันที (force) |
| `/T` | ปิดโปรเซสนั้นพร้อมโปรเซสลูกทั้งหมด (tree) |

ที่เบื้องหลัง คำสั่งแบบไม่มี `/F` คือการ **ขอ** ให้โปรแกรมปิดตัว (โปรแกรมมีโอกาสเซฟงานและคืนทรัพยากร) ส่วน `/F` คือให้ระบบ **ตัดจบ** โดยโปรแกรมไม่มีโอกาสตอบ ลองประกอบคำสั่งและดูว่าโปรเซสใดถูกปิด สังเกตโปรเซสลูกที่ค้างเมื่อไม่ใส่ `/T`

::taskkill-builder
::

> **กับดัก:** `taskkill /F` ไม่เซฟไฟล์และไม่ล้างแคช ข้อมูลที่ค้างในหน่วยความจำหายได้ ใช้ `/F` เมื่อการปิดตามปกติไม่ได้ผลเท่านั้น (ต้นฉบับย้ำจุดนี้) และปิดโปรเซสของระบบ (เช่น `csrss.exe`, `wininit.exe`) อาจทำให้เครื่องล้มทันที

::terminal-sim{title="ปิดโปรแกรมที่ค้าง" prompt="C:⧵>" :commands='[{"cmd":"taskkill /PID 7104","out":"ERROR: The process with PID 7104 could not be terminated.⏎Reason: This process can only be terminated forcefully (with /F option).","note":"ลองแบบสุภาพก่อน ข้อความนี้เกิดกับโปรเซสที่ไม่ยอมรับคำขอปิด (ข้อความจริงอาจต่างกันตามโปรแกรม)"},{"cmd":"taskkill /PID 7104 /F","out":"SUCCESS: The process with PID 7104 has been terminated.","note":"บังคับปิดตัวเดียว ตรงเป้าด้วย PID"},{"cmd":"taskkill /IM report_generator.exe /F /T","out":"SUCCESS: The process with PID 7188 child of PID 7104 has been terminated.⏎SUCCESS: The process with PID 7104 has been terminated.","note":"เลือกด้วยชื่อ และ /T ปิดลูกพร้อมกัน (ตัวอย่างสมมติหลังเปิดโปรแกรมใหม่) ระวังถ้ามีหลายตัวชื่อเดียวกัน จะถูกปิดหมด"}]'}
::

## 3. ซ่อมไฟล์ระบบด้วย sfc และ DISM

ไฟล์สำคัญของ Windows (DLL, ไดรเวอร์ ฯลฯ) อาจเสียเมื่อเครื่องดับกลางคัน อัปเดตไม่สมบูรณ์ หรือดิสก์มีปัญหา อาการคือแอปและเมนูตั้งค่าค้าง หรือ error ที่ชี้ไปยัง DLL

**System File Checker (`sfc`)** เทียบไฟล์ระบบที่ได้รับการป้องกันกับสำเนาต้นฉบับในแคชของระบบ (โฟลเดอร์ `WinSxS`) ตัวไหนเสียหรือหายก็คัดลอกตัวสะอาดมาแทน ต้องเปิดเป็นผู้ดูแล

```cmd
sfc /scannow
```

ปัญหาคือ ถ้า **แคชต้นฉบับนั้นเองเสียหาย** `sfc` ก็ไม่มีของดีไปเปลี่ยน จึงรายงานว่าพบไฟล์เสียแต่ซ่อมไม่ได้ ตรงนี้ใช้ **DISM (Deployment Image Servicing and Management)** ซ่อม "คลังอะไหล่" ก่อน แล้วค่อยรัน `sfc` ซ้ำ (โดยปกติ DISM ดึงไฟล์ดีจาก Windows Update จึงต้องต่ออินเทอร์เน็ต)

## 4. ตรวจดิสก์และระบบไฟล์ด้วย chkdsk

ปัญหาของดิสก์มีสองระดับ ระดับ **ตรรกะ** (ตารางไฟล์/ดัชนีโฟลเดอร์ผิดเพี้ยน) และระดับ **กายภาพ** (เซกเตอร์เสียบนผิวหรือชิป) `chkdsk` (Check Disk) ตรวจและซ่อมโครงสร้างของวอลลุ่ม (volume)

| คำสั่ง | ทำอะไร | ผลข้างเคียง |
|---|---|---|
| `chkdsk C:` | อ่านอย่างเดียว รายงานปัญหา ไม่แก้ | ปลอดภัย |
| `chkdsk C: /f` | แก้ข้อผิดพลาดของโครงสร้างระบบไฟล์ | ต้องล็อกวอลลุ่มระหว่างทำ |
| `chkdsk C: /r` | ทำ `/f` และ **สแกนทุกเซกเตอร์** หาจุดเสีย กู้ข้อมูลที่อ่านได้ ย้ายออกจากเซกเตอร์เสีย | ช้ามาก (ไล่ทั้งดิสก์) |

ต่างกันสั้นๆ: `/f` แก้ "สมุดสารบัญ" ที่ผิด ส่วน `/r` ไล่ตรวจ "ทุกหน้ากระดาษ" ด้วย (และรวม `/f` ไว้แล้ว)

::compare-cards{:items='[{"title":"chkdsk C: /f","subtitle":"แก้ตรรกะ","points":["แก้โครงสร้างระบบไฟล์ เช่น ตารางไฟล์ ดัชนีโฟลเดอร์","เร็วกว่ามาก","เหมาะเมื่อมีสัญญาณว่าไฟล์ระบบผิดเพี้ยน เช่น หลังเครื่องดับกลางคัน","ไม่ตรวจผิวดิสก์ทั้งหมด"]},{"title":"chkdsk C: /r","subtitle":"แก้ตรรกะ + สแกนกายภาพ","points":["รวมการทำงานของ /f","อ่านทุกเซกเตอร์ หาจุดเสียและย้ายข้อมูลที่กู้ได้","ใช้เวลานานมาก โดยเฉพาะดิสก์ใหญ่หรือ HDD ช้า","เหมาะเมื่อสงสัยดิสก์เสียทางกายภาพ"]}]'}
::

**ทำไมไดรฟ์ C: ต้องรอรีสตาร์ต:** ไดรฟ์ที่ระบบปฏิบัติการและโปรแกรมใช้อยู่ ถูกเปิดค้างไว้จึงล็อกให้ chkdsk เข้าไปแก้ไม่ได้ Windows จะถามว่าจะนัดตรวจตอนบูตครั้งหน้าหรือไม่

```text
Chkdsk cannot run because the volume is in use by another
process. Would you like to schedule this volume to be
checked the next time the system restarts? (Y/N)
```

ตอบ `Y` แล้วรีสตาร์ต การตรวจจะรันก่อนระบบขึ้นเต็มรูป ใช้เวลาตามขนาดดิสก์ จึงควรทำนอกเวลางาน

> **สัญญาณเตือน (เสริมจากผู้เขียน):** ถ้า `chkdsk` พบเซกเตอร์เสียซ้ำๆ หรือดิสก์ส่งเสียงผิดปกติ ให้ **สำรองข้อมูลก่อนทำอะไรต่อ** และเตรียมเปลี่ยนไดรฟ์ เพราะ chkdsk แค่เลี่ยงจุดเสีย ไม่ได้ทำให้ฮาร์ดแวร์ดีขึ้น

::terminal-sim{title="ตรวจดิสก์" prompt="C:⧵>" :commands='[{"cmd":"chkdsk C:","out":"The type of the file system is NTFS.⏎⏎Stage 1: Examining basic file system structure ...⏎Stage 2: Examining file name linkage ...⏎Stage 3: Examining security descriptors ...⏎⏎Windows has scanned the file system and found no problems.⏎No further action is required.","note":"โหมดอ่านอย่างเดียว ตัวอย่างผลที่ปกติ (ข้อความจริงยาวกว่านี้และมีสถิติพื้นที่)"},{"cmd":"chkdsk C: /f","out":"Chkdsk cannot run because the volume is in use by another⏎process. ## 5. ดูข้อมูลเครื่องด้วย systeminfo

`systeminfo` รวบรวมข้อมูลเครื่องไว้ที่เดียว: ชื่อและเวอร์ชัน OS, วันที่ติดตั้ง, เวลาบูตล่าสุด, รุ่นเมนบอร์ดและเวอร์ชัน BIOS, หน่วยความจำ, แพตช์ (hotfix) ที่ติดตั้ง และการ์ดเครือข่าย ใช้ตอนเปิด ticket เพื่อรู้ว่าเครื่องนี้คืออะไร หรือตอบคำถามเช่น "ติดตั้งแพตช์ล่าสุดแล้วหรือยัง" โดยไม่ต้องคลิกหาในหลายเมนู

เนื่องจากผลลัพธ์ยาว ให้ใช้ท่อ (`|`) ส่งต่อให้ `findstr` ซึ่งกรองบรรทัดที่ตรงกับข้อความ ตัวเลือก `/B` = ตรงต้นบรรทัด และ `/C:` = ใช้ข้อความทั้งก้อนรวมช่องว่าง

```cmd
systeminfo | findstr /B /C:"Total Physical Memory" /C:"Available Physical Memory"
Total Physical Memory:     16,142 MB
Available Physical Memory: 9,410 MB
```

ตัวอย่างอ่านผล: RAM รวมราว 16 GB เหลือว่างราว 9.4 GB หมายความว่ากำลังใช้ราวร้อยละ 42 ถ้าเหลือว่างน้อยมากแล้วเครื่องช้า ต้องไปดู `tasklist` ว่าโปรเซสใดกินหน่วยความจำ ซึ่งเชื่อมกลับไปหัวข้อ 2

::terminal-sim{title="ดึงข้อมูลที่ต้องการจาก systeminfo" prompt="C:⧵>" :commands='[{"cmd":"systeminfo | findstr /B /C:OS","out":"OS Name:                   Microsoft Windows 11 Pro⏎OS Version:                10.0.26200 N/A Build 26200⏎OS Manufacturer:           Microsoft Corporation⏎OS Configuration:          Member Workstation⏎OS Build Type:             Multiprocessor Free","note":"กรองบรรทัดที่ขึ้นต้นด้วย OS ใช้ระบุเวอร์ชันก่อนค้นหาวิธีแก้ ค่าเป็นตัวอย่าง"},{"cmd":"systeminfo | findstr /C:Memory","out":"Total Physical Memory:     16,142 MB⏎Available Physical Memory: 9,410 MB⏎Virtual Memory: Max Size:  18,574 MB⏎Virtual Memory: Available: 10,822 MB⏎Virtual Memory: In Use:    7,752 MB","note":"กรองด้วยคำเดียว (ไม่ใช้ /B) ได้ทั้งหน่วยความจำจริงและเสมือน ข้อมูลอ่านเข้ากับบทฮาร์ดแวร์เรื่อง RAM และ swap"}]'}

## มุมมองด้าน Security

- **ipconfig เป็นข้อมูลที่ผู้โจมตีอยากได้:** IP, MAC, DNS และ domain บอกโครงสร้างเครือข่าย ถ้าถ่ายภาพหน้าจอหรือแปะผลลัพธ์ลง ticket/แชตสาธารณะ ให้ปิดข้อมูลที่ไม่จำเป็น
- **`/flushdns` ไม่ได้ป้องกันการโจมตี:** แต่ช่วยหลังพบว่าแคชถูกวางข้อมูลปลอม (DNS cache poisoning) หรือไฟล์ `hosts` ถูกแก้ ควรตรวจไฟล์ `hosts` ด้วยเมื่อชื่อเว็บชี้ไปปลายทางที่ผิดโดยไม่มีเหตุผล
- **tasklist ช่วยหามัลแวร์เบื้องต้น:** ชื่อโปรเซสแปลก, ชื่อเลียนแบบของระบบ (เช่น `svch0st.exe`), กินหน่วยความจำ/CPU ผิดปกติ ควร **สอบสวนก่อนปิด** ถ้าสงสัยเป็นเหตุด้านความปลอดภัย ให้ escalate และรักษาหลักฐาน (ตามบทที่แล้ว) แทนการ `taskkill` แล้วลบทิ้งทันที
- **ปิดผิดโปรเซสเสียหายจริง:** `taskkill /F /IM` กับชื่อที่ซ้ำกันหลายตัว หรือโปรเซสระบบ ทำให้เครื่องล้ม งานผู้ใช้หาย ตรวจ PID ก่อนทุกครั้ง
- **sfc/DISM ต้องใช้สิทธิ์ผู้ดูแล:** รันเฉพาะเมื่อจำเป็น ปิดหน้าต่างเมื่อเสร็จ และถ้า `sfc` พบไฟล์ระบบเสียบ่อยโดยไม่มีเหตุผล (ไม่ได้ไฟดับ/อัปเดตค้าง) อาจเป็นสัญญาณมัลแวร์แก้ไฟล์ระบบ หรือดิสก์เสียหาย ควรตรวจต่อ
- **chkdsk /r อาจทำให้ข้อมูลเสียหายต่อถ้าดิสก์กำลังจะพัง:** สำรองข้อมูลก่อนเสมอ และระวังไม่รันกับดิสก์ที่มีข้อมูลสำคัญและไม่มีสำเนา
- **systeminfo เปิดเผยระดับแพตช์:** ผู้โจมตีใช้เทียบกับช่องโหว่ที่รู้จัก ในทางกลับกันผู้ดูแลใช้ตรวจว่ามีแพตช์ครบหรือไม่ ส่วนนี้เชื่อมกับเรื่องการจัดการแพตช์ในโมดูลหลัง

| findstr | ไฟนด์สตริง | คำสั่งกรองบรรทัดที่ตรงกับข้อความ |

## ตรวจความเข้าใจ

::reveal{question="เครื่องขึ้นสถานะต่อ Wi-Fi แล้ว แต่ ipconfig แสดง IPv4 Address เป็น 169.254.37.201 และ Default Gateway ว่าง หมายความว่าอย่างไร ควรทำอะไรต่อ"}
เครื่องขอ IP จากเซิร์ฟเวอร์ DHCP แล้วไม่มีใครตอบ Windows จึงตั้ง IP ชั่วคราวช่วง APIPA (169.254.x.x) ให้เอง ซึ่งไม่มีเกตเวย์จึงออกอินเทอร์เน็ตไม่ได้ ปัญหาอยู่ที่ขั้นขอ IP ไม่ใช่เว็บหรือ DNS ลอง `ipconfig /renew` ตรวจว่าเชื่อม Wi-Fi/สายจริง และดูว่าเราเตอร์/DHCP ทำงานอยู่ไหม เช่น เครื่องอื่นได้ IP ปกติหรือไม่
::

::reveal{question="ผู้ใช้เปิดเมนู Settings แล้วแอปค้างหลังไฟดับกลางคัน สงสัยไฟล์ระบบเสีย ควรรันคำสั่งใดก่อน และต้องเปิด Command Prompt แบบไหน"}
`sfc /scannow` ใน Command Prompt แบบผู้ดูแล (Run as administrator) เพราะ sfc ตรวจและแก้ไฟล์ระบบที่ได้รับการป้องกัน ไม่ใช่ `ipconfig` (เรื่องเครือข่าย) หรือ `taskkill` (ปิดโปรเซสไม่ได้ซ่อมไฟล์) ถ้ารายงานว่าพบแต่ซ่อมไม่ได้ ให้ใช้ `DISM /Online /Cleanup-Image /RestoreHealth` แล้วรัน sfc ซ้ำ
::

::reveal{question="ทำไมต้องรัน DISM ก่อน sfc ซ้ำ เมื่อ sfc ซ่อมไม่สำเร็จ"}
เพราะ sfc ซ่อมโดยคัดลอกไฟล์สะอาดจากแคชต้นฉบับ (component store) ถ้าแคชเองเสียหาย ก็ไม่มีไฟล์ดีให้เอาไปแทน DISM ซ่อมแคชต้นฉบับนั้น (ดึงไฟล์ดีมาแทน) เมื่อคลังสมบูรณ์แล้ว sfc จึงซ่อมไฟล์ที่ใช้งานอยู่ได้
::

::reveal{question="chkdsk C: /f ต่างจาก chkdsk C: /r อย่างไร และทำไมกับไดรฟ์ C: จึงมีคำถามให้รีสตาร์ต"}
`/f` แก้ข้อผิดพลาดของโครงสร้างระบบไฟล์ (ระดับตรรกะ) ส่วน `/r` ทำ `/f` และสแกนทุกเซกเตอร์เพื่อหาจุดเสียทางกายภาพ กู้ข้อมูลที่อ่านได้ ใช้เวลานานกว่ามาก ไดรฟ์ C: ถูกระบบและโปรแกรมใช้อยู่จึงล็อกไม่ได้ Windows ถามว่าจะนัดตรวจตอนเปิดเครื่องครั้งหน้าไหม
::

::reveal{question="ทำไม taskkill บางกรณีต้องใช้ /F และทำไมต้องระวัง"}
โปรเซสที่ค้างหรือไม่ตอบสนองจะไม่รับคำขอปิดแบบสุภาพ /F จึงบังคับยุติทันที ข้อควรระวังคือโปรแกรมไม่มีโอกาสเซฟงานหรือล้างแคช ข้อมูลที่ยังไม่บันทึกหายได้ และไม่ควรใช้กับโปรเซสระบบ ควรลองแบบไม่ใส่ /F ก่อน และแจ้งผู้ใช้ก่อนบังคับปิด
::

::reveal{question="ต้องการปิดโปรแกรมที่มีโปรเซสหลักและโปรเซสลูกหลายตัวพร้อมกัน ควรใช้ตัวเลือกใด และมีข้อควรระวังอะไรเมื่อระบุด้วยชื่อ (/IM)"}
ใช้ `/T` ปิดโปรเซสนั้นพร้อมลูกทั้งหมด ถ้าไม่ใส่ โปรเซสลูกอาจค้างกินทรัพยากรต่อ เมื่อระบุด้วย `/IM` จะปิดทุกโปรเซสที่ชื่อเดียวกัน ซึ่งอาจรวมของผู้ใช้อื่นหรือหลาย instance ที่ไม่ได้ตั้งใจ ถ้าต้องการตรงตัวให้ใช้ `/PID` หลังตรวจด้วย `tasklist`
::

::reveal{question="ต้องการดูเฉพาะ RAM รวมและ RAM ที่ว่างของเครื่องด้วยคำสั่งเดียว ทำอย่างไร"}
ใช้ท่อส่งผลจาก systeminfo ให้ findstr กรอง เช่น `systeminfo | findstr /B /C:"Total Physical Memory" /C:"Available Physical Memory"` (`/B` ตรงต้นบรรทัด, `/C:` ใช้ข้อความรวมช่องว่าง)
::

::reveal{question="ผู้ใช้เจอโปรเซสชื่อ svch0st.exe (เลขศูนย์แทนตัว o) กินหน่วยความจำสูง ควรปิดทันทีด้วย taskkill /F หรือไม่ เพราะอะไร"}
ไม่ควรปิดแล้วจบ ชื่อที่สะกดเลียนแบบ svchost.exe เป็นสัญญาณมัลแวร์ที่ปลอมตัวเป็นไฟล์ระบบ ให้บันทึกข้อมูล (PID, ตำแหน่งไฟล์, เวลา) แล้ว escalate ให้ทีม Security เพราะการปิดหรือลบทิ้งอาจทำลายหลักฐาน และมัลแวร์อาจกลับมาหรือมีส่วนอื่นซ่อนอยู่ ควรแยกเครื่องออกจากเครือข่ายตามขั้นตอนขององค์กร
::

## แบบฝึกหัด

ใช้เครื่อง Windows ของตัวเอง (คำสั่งโหมดอ่านอย่างเดียวปลอดภัย)

1. **ตรวจเครือข่าย:** รัน `ipconfig /all` หา MAC (Physical Address), IPv4, เกตเวย์, DHCP Server แล้วรัน `ipconfig /flushdns`
2. **จัดการโปรเซส:** เปิด Notepad (`notepad.exe`) รัน `tasklist | findstr notepad` เพื่อหา PID แล้วปิดด้วย `taskkill /PID <หมายเลข>` ลองทั้งแบบมีและไม่มี `/F` (ใช้กับโปรแกรมทดลองเท่านั้น)
3. **ตรวจไฟล์ระบบแบบไม่แก้:** เปิด Command Prompt แบบผู้ดูแล แล้วรัน `sfc /verifyonly`
4. **ตรวจ RAM:** ใช้ `systeminfo` กับ `findstr` ดูหน่วยความจำรวมและที่ว่าง คำนวณเปอร์เซ็นต์ที่ใช้
5. **เขียน ticket:** สมมติเครื่องได้ IP 169.254.x.x เขียน ticket 4 ส่วนตามบทที่แล้ว (อาการ สาเหตุที่ตรวจพบ ขั้นแก้ ผลลัพธ์)

::reveal{question="แนวคำตอบข้อ 2 (ปิด Notepad ด้วย PID)"}
เปิด Notepad แล้ว `tasklist | findstr notepad` จะได้บรรทัดที่มีหมายเลขในคอลัมน์ PID เช่น 5520 จากนั้น `taskkill /PID 5520` Notepad ที่ว่างเปล่าจะปิดไปเอง ถ้าพิมพ์ข้อความค้างไว้และยังไม่เซฟ อาจขึ้นกล่องถามให้เซฟ ถ้าใส่ `/F` จะถูกปิดทันทีโดยไม่ถาม (ข้อความที่พิมพ์ค้างไว้หายได้)
::

## สรุป

- `ipconfig` อ่านสภาพเครือข่าย: ดู IPv4, subnet mask, default gateway และระวัง APIPA (169.254.x.x) = ไม่ได้ IP จาก DHCP ใช้ `/release` `/renew` `/flushdns` ให้ตรงอาการ
- `tasklist` หา PID และดูโปรเซสที่กินทรัพยากร `taskkill` ปิดด้วย `/PID` หรือ `/IM` ใช้ `/F` เมื่อจำเป็นและ `/T` ปิดทั้งต้น โดยรู้ว่า `/F` ทำให้งานที่ไม่ได้เซฟหาย
- `sfc /scannow` ซ่อมไฟล์ระบบจากแคชต้นฉบับ ถ้าซ่อมไม่ได้ ให้ `DISM /Online /Cleanup-Image /RestoreHealth` ก่อนแล้ว `sfc` ซ้ำ ทั้งสองต้องใช้สิทธิ์ผู้ดูแล
- `chkdsk` อ่านอย่างเดียวโดยปกติ `/f` แก้ตรรกะ `/r` สแกนกายภาพ (ช้า) ไดรฟ์ที่ใช้อยู่ต้องรอรีสตาร์ต และควรสำรองข้อมูลก่อน
- `systeminfo` + `findstr` ดึงข้อมูลเครื่องและหน่วยความจำได้เร็ว
- เลือกคำสั่งตามอาการ เริ่มจากโหมดอ่านอย่างเดียว บันทึกลง ticket และระวังเรื่องข้อมูลที่เปิดเผย โปรเซสที่น่าสงสัย และการทำลายหลักฐาน
