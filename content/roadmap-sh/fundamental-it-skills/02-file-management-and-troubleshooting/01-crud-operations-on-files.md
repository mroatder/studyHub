## วัตถุประสงค์การเรียนรู้

เมื่อจบบทนี้ คุณควรจะ

1. อธิบายความหมายของ **CRUD** และบอกได้ว่าไฟล์หนึ่งไฟล์ประกอบด้วย **ชื่อ + ข้อมูล + ข้อมูลกำกับ (metadata)** ที่เก็บคนละที่
2. สร้างโฟลเดอร์และไฟล์ได้ทั้ง PowerShell และ Bash และรู้กับดักของ `New-Item -Force`, `touch` และ `>`
3. อ่านไฟล์ได้ถูกวิธีตามขนาดและเป้าหมาย (`Get-Content`, `cat`, `less`, `head`, `tail`) รวมถึงการ "ตามดู" log สดๆ
4. แยก **`>` (ทับ)** กับ **`>>` (ต่อท้าย)** ได้ และอธิบายเรื่อง stdout/stderr, encoding, และ `sudo` กับ redirect
5. อธิบายได้ว่าทำไม **เปลี่ยนชื่อกับย้ายไฟล์ใช้คำสั่งเดียวกัน** และทำไมย้ายข้ามดิสก์ช้ากว่า
6. คัดลอกไฟล์/โฟลเดอร์ (`-Recurse`, `-r`) โดยไม่โดนกับดักโฟลเดอร์ปลายทางมีอยู่แล้ว
7. ลบอย่างปลอดภัย: รู้ว่าการลบทำอะไรกับดิสก์จริง ใช้ `-WhatIf`, `rm -i`, ตรวจด้วย `ls` ก่อน
8. อ่านข้อความ error ที่พบบ่อย (Permission denied, Directory not empty, Is a directory ฯลฯ) แล้วแก้ได้

## สรุปสั้น (TL;DR)

**CRUD = Create, Read, Update, Delete** คือสี่การกระทำพื้นฐานกับข้อมูล บนไฟล์คือ สร้าง (`New-Item` / `mkdir` / `touch`), อ่าน (`Get-Content` / `cat` / `less` / `head` / `tail`), แก้ไข (`>` ทับ, `>>` ต่อท้าย, `Move-Item`/`mv`, `Copy-Item`/`cp`) และลบ (`Remove-Item` / `rm`) กฎที่ต้องจำ: **`>` ทำลายเนื้อหาเดิมทันที**, **ย้ายกับเปลี่ยนชื่อคือการแก้ชื่อในไดเรกทอรี**, **การลบในเทอร์มินัลไม่มีถังขยะ** และ **ซ้อมก่อนลบเสมอ** ด้วย `ls`, `-WhatIf`, `rm -i`

## เปรียบเทียบกับชีวิตจริง

นึกถึง **ห้องสมุด**

| ห้องสมุด | ไฟล์ในคอมพิวเตอร์ | ข้อสังเกต |
|---|---|---|
| ลงทะเบียนหนังสือเล่มใหม่ | Create | เพิ่มบัตรรายการ ส่วนเนื้อหาข้างในค่อยเขียนทีหลังได้ |
| ยืมมาอ่านโดยไม่แก้ | Read | อ่านได้ไม่ทำให้หนังสือเปลี่ยน |
| ต่อท้ายบันทึก / ลบทั้งเล่มแล้วเขียนใหม่ | Update: `>>` / `>` | ต่อท้ายปลอดภัย ลบเขียนใหม่เสียของเก่า |
| เปลี่ยนป้ายชื่อ หรือย้ายไปชั้นอื่น | rename / move | แก้แค่บัตรรายการ หนังสือเล่มเดิมไม่ถูกแตะ |
| ถ่ายเอกสารทั้งเล่ม | copy | ได้เล่มใหม่เป็นอิสระ ใช้พื้นที่เพิ่ม |
| ฉีกบัตรรายการทิ้ง | delete | หนังสือยังอยู่บนชั้นจนกว่าจะมีเล่มใหม่มาวางทับ แต่ใครก็หาไม่เจอแล้ว |

อุปมานี้จะเป็นกุญแจให้เข้าใจกลไกเบื้องหลังในหัวข้อ 1

## ภาพรวม

ต้นฉบับแบ่งบทนี้ตามตัวอักษรของ CRUD คือ **สร้าง**, **อ่าน**, **แก้ไข** (เนื้อหา ย้าย/เปลี่ยนชื่อ คัดลอก), **ลบ** แล้วสรุปเป็นตารางเทียบคำสั่ง มีแบบฝึกหัด 2 ชุดและคำถามท้ายบท เราจะเดินตามลำดับนี้ แล้วเสริมสิ่งที่งานจริงต้องใช้ แต่ต้นฉบับพูดสั้นหรือไม่ได้พูด เช่น กลไกเบื้องหลัง, stdout/stderr, encoding, กับดักของ `sudo`, และเครื่องมือซ้อมก่อนลบ

## 1. ก่อนลงมือ: ไฟล์คืออะไรกันแน่

เมื่อสร้างไฟล์ ระบบไฟล์ต้องจดบันทึกว่ามีไฟล์ชื่ออะไร และข้อมูลอยู่ตรงไหนของดิสก์ ต้นฉบับเรียกที่จดนี้ว่า "ตารางของระบบไฟล์ (file system table)" ในความเป็นจริงมี 3 ส่วนที่เก็บแยกกัน

- **ข้อมูลของไฟล์ (data blocks)** เนื้อหาจริง เก็บเป็นก้อนเล็กๆ ที่เรียกว่า **บล็อก** กระจายบนดิสก์
- **ข้อมูลกำกับ (metadata)** ขนาด เวลาที่สร้าง/แก้ล่าสุด เจ้าของ สิทธิ์ และ "บล็อกไหนเป็นของไฟล์นี้" บน NTFS ของ Windows อยู่ในระเบียนของ **MFT (Master File Table)** บน ext4 ของ Linux อยู่ใน **inode**
- **ชื่อไฟล์** บน Linux ชื่อไม่ได้อยู่กับ inode แต่อยู่ใน **ไดเรกทอรี** ซึ่งก็คือไฟล์พิเศษชนิดหนึ่งที่เป็นรายการ "ชื่อ → ไฟล์ตัวนี้"

เมื่อเข้าใจโครงนี้ จะเห็นว่าคำสั่งแต่ละตัวแตะส่วนไหนต่างกัน กดเลือกคำสั่งดูว่ารายการในไดเรกทอรีกับบล็อกบนดิสก์เปลี่ยนอย่างไร (ก่อน เทียบกับ หลัง)

::fs-ops-lab
::

สิ่งที่ควรสังเกตจากแบบจำลอง

- **เปลี่ยนชื่อ/ย้ายในดิสก์เดียวกัน** บล็อกไม่ขยับเลย จึงเสร็จทันทีไม่ว่าไฟล์ใหญ่แค่ไหน
- **ย้ายข้ามดิสก์** ต้องคัดลอกข้อมูลก่อนแล้วลบต้นฉบับ จึงช้าและต้องมีที่ว่างพอ
- **ลบ** คือเอารายการออกและบอกว่าบล็อกว่างแล้ว ข้อมูลเดิมไม่ได้ถูกล้าง (เส้นประในภาพ) นี่คือเหตุที่โปรแกรมกู้ข้อมูลทำงานได้ และเหตุที่ "ลบแล้ว" ไม่เท่ากับ "ลบจริง"

## 2. Create: สร้างไฟล์และโฟลเดอร์

### 2.1 บน Windows (PowerShell)

ต้นฉบับใช้ cmdlet **`New-Item`** สร้างทั้งโฟลเดอร์และไฟล์ ต่างกันที่ `-ItemType`

```powershell
New-Item -ItemType Directory -Path "C:\logs"
New-Item -ItemType File -Path "C:\logs\app.log"
```

อีกวิธีคือเขียนข้อความลงไฟล์ทันทีด้วยตัวดำเนินการ **redirection** (`>`) ถ้าไฟล์ยังไม่มีก็สร้างให้

```powershell
"Application started" > "C:\logs\app.log"
```

### 2.2 บน Linux (Bash)

```bash
mkdir /var/log/app                       # สร้างโฟลเดอร์
touch /var/log/app/app.log               # สร้างไฟล์ว่าง
echo "Application started" > /var/log/app/app.log   # สร้างพร้อมข้อความ
```

ต้นฉบับอธิบายว่า `touch` ถูกออกแบบมาเพื่อ **อัปเดตเวลา (timestamp)** ของไฟล์ แต่ถ้าไฟล์ไม่มี ก็จะสร้างไฟล์ว่างให้ ผลข้างเคียงคือ `touch` กับไฟล์ที่มีอยู่แล้ว **ไม่ทำลายเนื้อหา** เปลี่ยนแค่เวลา

### 2.3 สิ่งที่ควรรู้เพิ่ม

- **สร้างโฟลเดอร์ซ้อนหลายชั้น:** `mkdir -p /tmp/a/b/c` ใน Linux สร้างโฟลเดอร์แม่ที่ยังไม่มีให้พร้อมกัน ถ้าไม่ใส่ `-p` จะ error `No such file or directory` ส่วน `mkdir` ใน PowerShell (ฟังก์ชันที่เรียก `New-Item`) สร้างโฟลเดอร์แม่ให้เองโดยไม่ต้องบอก
- **กับดัก `New-Item -Force`:** ถ้าไฟล์มีอยู่แล้ว `New-Item -ItemType File` จะ error แต่ถ้าเติม `-Force` มันจะ **สร้างทับจนไฟล์ว่าง** ตามความรู้ของผู้เขียน ควรลองกับไฟล์ทดสอบก่อน จึงห้ามเติม `-Force` โดยไม่คิด
- **ไฟล์ว่างจาก `echo "" > file`:** ไม่ใช่ไฟล์ว่างจริง มี 1 บรรทัดว่าง (ตัวขึ้นบรรทัดใหม่) ถ้าต้องการว่างจริงใน Bash ใช้ `: > file` หรือ `touch file`
- **สิทธิ์ของไฟล์ที่เพิ่งสร้าง:** ไฟล์ใหม่บน Linux ได้สิทธิ์เริ่มต้นตามค่า `umask` (ทั่วไปเป็น `-rw-r--r--` คือเจ้าของแก้ได้ คนอื่นอ่านได้) เราจะลงลึกเรื่องนี้ในบทถัดไป
- **ตัวเข้ารหัสอักษร (encoding) ของ PowerShell:** ใน **Windows PowerShell 5.1** ตัว `>` เขียนไฟล์เป็น **UTF-16** ส่วน PowerShell 7 เขียนเป็น UTF-8 ถ้าส่งไฟล์ไปให้เครื่องมืออื่น (เช่น สคริปต์ Linux) แล้วอ่านเป็นตัวอักษรเพี้ยน มักเป็นเพราะเหตุนี้ แก้ด้วย `Out-File -Encoding utf8` หรือ `Set-Content -Encoding utf8` ตามที่ต้องการ

## 3. Read: อ่านไฟล์

การอ่านคือเปิดไฟล์เป็นสายของไบต์แล้วแสดงออกหน้าจอ **โดยไม่แก้ไฟล์** จึงเป็นการกระทำที่ปลอดภัยที่สุดใน CRUD ควรใช้ก่อนเสมอเมื่อต้องตรวจสอบ

### 3.1 บน Windows (PowerShell)

```powershell
Get-Content -Path "C:\logs\app.log"                 # ทั้งไฟล์
Get-Content -Path "C:\logs\app.log" -Tail 10        # 10 บรรทัดสุดท้าย
Get-Content -Path "C:\logs\app.log" -Tail 10 -Wait  # ตามดูบรรทัดใหม่ที่ถูกเขียนเพิ่ม
Get-Content -Path "C:\logs\app.log" -TotalCount 10  # 10 บรรทัดแรก
```

### 3.2 บน Linux (Bash)

| ต้องการ | คำสั่ง | หมายเหตุ |
|---|---|---|
| พิมพ์ทั้งไฟล์ | `cat file` | ไฟล์ยาวจะเลื่อนผ่านหน้าจอเร็วจนอ่านไม่ทัน |
| เลื่อนอ่านทีละหน้า | `less file` | Space = หน้าถัดไป, `b` = ย้อน, `/คำ` = ค้นหา, `q` = ออก |
| 10 บรรทัดแรก | `head file` | ระบุจำนวนด้วย `head -n 20 file` |
| 10 บรรทัดสุดท้าย | `tail file` | ระบุจำนวนด้วย `tail -n 20 file` |
| ตามดูบรรทัดใหม่ | `tail -f file` | กด Ctrl + C เพื่อหยุด |

ลองรันชุดคำสั่งอ่านไฟล์ (ข้อมูลเป็นตัวอย่าง) ในเทอร์มินัลจำลอง

### 3.3 สิ่งที่ควรรู้เพิ่ม

- **เลือกเครื่องมือตามเป้าหมาย:** ดูเหตุการณ์ล่าสุดใช้ `tail`, ดูหัวไฟล์ใช้ `head`, อ่านเอกสารยาวใช้ `less`, ตามดูสดใช้ `tail -f` / `-Wait` ข้อควรระวังเรื่องประสิทธิภาพ: `cat` ไม่ได้โหลดทั้งไฟล์เข้า RAM (มันส่งออกเป็นก้อนๆ) ปัญหาของ `cat` กับไฟล์ใหญ่คือ **ท่วมหน้าจอ** ไม่ใช่หน่วยความจำ แต่ใน PowerShell ถ้าเก็บผลเป็นตัวแปร (`$x = Get-Content ใหญ่`) จะโหลดทั้งไฟล์เข้าหน่วยความจำ จึงนิยมใช้ `-Tail` / `-TotalCount`
- **หมุนเวียน log (log rotation):** ระบบมักเปลี่ยนชื่อ log เก่าแล้วเริ่มไฟล์ใหม่ `tail -f` ติดตาม "ไฟล์เดิม" ที่ถูกเปลี่ยนชื่อ จึงเงียบไป ใช้ `tail -F` (F ใหญ่) เพื่อให้ติดตามตามชื่อไฟล์
- **กรองเฉพาะที่สนใจด้วย pipe (`|`):** pipe ส่งผลลัพธ์ของคำสั่งหนึ่งเข้าอีกคำสั่ง เช่น `tail -n 200 app.log | grep failed` (Linux) หรือ `Get-Content app.log -Tail 200 | Select-String failed` (PowerShell) นี่คือพื้นฐานของการวิเคราะห์ log ในบทเรื่อง troubleshooting
- **นับบรรทัด:** `wc -l file` (Linux) หรือ `(Get-Content file).Count` / `Get-Content file | Measure-Object -Line` (PowerShell)

## 4. Update: แก้ไข

"Update" ในต้นฉบับครอบคลุมสามเรื่อง คือ แก้เนื้อหา, ย้าย/เปลี่ยนชื่อ, และคัดลอก

### 4.1 แก้เนื้อหา: `>` กับ `>>`

- **`>`** ตัดไฟล์ให้ว่างก่อน (truncate) แล้วค่อยเขียนข้อความใหม่ **เนื้อหาเดิมหายทันที**
- **`>>`** เปิดไฟล์แล้วเขียนต่อท้าย เนื้อหาเดิมอยู่ครบ

ทั้งสองทำงานเหมือนกันใน PowerShell และ Bash ลองกดทั้งสองปุ่มสลับกัน แล้วดูว่าเนื้อหาเดิมไปไหน

::redirect-lab
::

หลักจำง่ายๆ คือ **จะเก็บสะสม ใช้สองตัว (`>>`) จะเริ่มใหม่ ใช้ตัวเดียว (`>`)** ตัวอักษรเดียวต่างกัน แต่เป็นความผิดพลาดที่ทำให้ log หลายวันหายได้

เมื่อไม่ต้องการแก้ทั้งไฟล์ ให้เปิดตัวแก้ไขข้อความ

- Windows: `notepad C:\logs\app.log` เปิดโปรแกรมกราฟิก
- Linux เซิร์ฟเวอร์ไม่มีหน้าจอกราฟิก จึงแก้ในเทอร์มินัลด้วย **nano** (แนะนำสำหรับมือใหม่: Ctrl + O บันทึก, Ctrl + X ออก) หรือ **vim** (ทรงพลังแต่เรียนรู้ยาก: `i` เริ่มพิมพ์, Esc หยุดพิมพ์, `:wq` บันทึกแล้วออก, `:q!` ออกทิ้งการแก้)

#### สิ่งที่ควรรู้เพิ่ม: stdout, stderr และ redirection

โปรแกรมมีช่องส่งข้อความออกสองช่อง คือ **stdout** (ผลลัพธ์ปกติ) กับ **stderr** (ข้อผิดพลาด) `>` ส่งเฉพาะ stdout ลงไฟล์ ข้อความ error ยังโผล่หน้าจอ

| ต้องการ | Bash | PowerShell |
|---|---|---|
| เก็บ stdout | `cmd > out.txt` | `cmd > out.txt` |
| เก็บ stderr | `cmd 2> err.txt` | `cmd 2> err.txt` |
| รวมสองช่องลงไฟล์เดียว | `cmd > all.txt 2>&1` | `cmd *> all.txt` |
| ทิ้งข้อความ error | `cmd 2> /dev/null` | `cmd 2> $null` |

`/dev/null` คือ "หลุมดำ" ของ Linux ส่งอะไรเข้าไปก็หายหมด

#### กับดัก `sudo` กับ redirect

คำสั่งนี้ **ล้มเหลว** แม้ใส่ `sudo`:

```bash
sudo echo debug=true > /opt/app.conf     # Permission denied
```

เพราะการเปิดไฟล์ด้วย `>` ทำโดย **เชลล์ของคุณ** (สิทธิ์ผู้ใช้ปกติ) ก่อนที่ `sudo` จะทำงาน sudo ครอบเฉพาะ `echo` ซึ่งไม่ได้เขียนไฟล์เอง วิธีแก้คือให้โปรแกรมที่รันด้วย sudo เป็นคนเขียนไฟล์ เช่น `tee`

```bash
echo debug=true | sudo tee -a /opt/app.conf     # -a คือต่อท้าย (เหมือน >>) ถ้าไม่ใส่จะทับ
```

#### สิ่งที่ควรรู้เพิ่ม: ตัวขึ้นบรรทัดใหม่ (line ending)

Windows ใช้ตัวขึ้นบรรทัดใหม่แบบ **CRLF** (2 ตัวอักษร) ส่วน Linux ใช้ **LF** (1 ตัวอักษร) ไฟล์สคริปต์ที่เขียนบน Windows แล้วส่งไปรันบน Linux อาจ error ว่า `bad interpreter: /bin/bash^M` เพราะมีอักขระ CR (`^M`) ติดมาท้ายบรรทัด แก้ด้วย `dos2unix script.sh` (ถ้าติดตั้งไว้) หรือ `sed -i 's/\r$//' script.sh`

### 4.2 ย้ายและเปลี่ยนชื่อ

ต้นฉบับชี้ว่า **เปลี่ยนชื่อ กับ ย้าย ใช้กลไกเดียวกัน** (ดูภาพในหัวข้อ 1) เพราะชื่ออยู่ในรายการของไดเรกทอรี การ "เปลี่ยนชื่อ" คือแก้ชื่อในรายการนั้น และการ "ย้าย" คือเอารายการไปไว้ในไดเรกทอรีอื่น บล็อกข้อมูลไม่ต้องขยับ

```powershell
# PowerShell
Move-Item -Path "C:\logs\app.log" -Destination "C:\logs\app-old.log"   # เปลี่ยนชื่อ
Move-Item -Path "C:\logs\app-old.log" -Destination "C:\archive\"       # ย้าย
```

```bash
# Bash
mv /var/log/app/app.log /var/log/app/app-old.log    # เปลี่ยนชื่อ
mv /var/log/app/app-old.log /var/archive/           # ย้าย
```

ระดับระบบเรียก: บน Linux การ `mv` ในระบบไฟล์เดียวกันเรียก **`rename()`** ตรงๆ ส่วนบน Windows ใช้ `MoveFileEx` ถ้าปลายทางคนละดิสก์ ทั้งสองระบบ (หรือคำสั่งเอง) ต้องทำ **คัดลอกแล้วลบ** แทน (ข้อมูลส่วนนี้มาจากความรู้ของผู้เขียน ไม่ได้มาจากต้นฉบับ)

PowerShell ยังมี `Rename-Item` ไว้เปลี่ยนชื่ออย่างเดียว (`Rename-Item app.log app-old.log`)

### 4.3 คัดลอก

คัดลอกคืออ่านข้อมูลต้นฉบับแล้วเขียนเป็นข้อมูลใหม่ในบล็อกใหม่ จึงได้ไฟล์อิสระ แก้ต้นฉบับแล้วสำเนาไม่เปลี่ยน

```powershell
# PowerShell
Copy-Item -Path "C:\logs\app.log" -Destination "C:\backup\app.log"
Copy-Item -Path "C:\logs\" -Destination "C:\backup\logs\" -Recurse     # โฟลเดอร์ทั้งก้อน
```

```bash
# Bash
cp /var/log/app/app.log /var/backup/app.log
cp -r /var/log/app /var/backup/logs                                    # โฟลเดอร์ทั้งก้อน
```

**`-Recurse` / `-r`** แปลว่าลงไปทุกชั้นย่อย ถ้าลืมใส่ `-r` กับโฟลเดอร์ `cp` จะปฏิเสธ (`omitting directory`) ส่วน `Copy-Item` ไม่ใส่ `-Recurse` จะคัดลอกได้แค่ตัวโฟลเดอร์เปล่าๆ ไม่ได้ไฟล์ข้างใน

#### กับดักโฟลเดอร์ปลายทางมีอยู่แล้ว

ถ้าโฟลเดอร์ปลายทางมีอยู่ ทั้ง `cp -r logs backup` และ `Copy-Item logs backup -Recurse` จะสร้าง **`backup/logs`** ซ้อนอีกชั้น แทนที่จะรวมเนื้อหาเข้ากับ `backup` ผลคือได้โครงสร้างซ้อนกันที่ไม่ได้ตั้งใจ ตรวจด้วย `ls` / `dir` ทุกครั้งหลังคัดลอกโฟลเดอร์

#### ระวังการทับโดยไม่ถาม

ต้นฉบับเตือนว่า `Move-Item` / `Copy-Item` และ `mv` / `cp` จะ **ทับไฟล์ปลายทางที่มีชื่อซ้ำ** ถ้าไม่ระวังจะเสียไฟล์ ตัวช่วยบน Linux: `cp -i` / `mv -i` ถามก่อนทับ และ `cp -n` / `mv -n` ไม่ทับเลย นอกจากนี้ `cp -a` คัดลอกโดยรักษาสิทธิ์ เจ้าของ และเวลาไว้ (เหมาะกับงานสำรองข้อมูล)

## 5. Delete: ลบ

ต้นฉบับอธิบายว่า การลบคือการบอกระบบไฟล์ว่า **บล็อกที่ไฟล์ใช้ว่างแล้ว** พร้อมให้ถูกเขียนทับ ดังที่เห็นในภาพหัวข้อ 1 (เส้นประ)

### 5.1 บน Windows (PowerShell)

```powershell
Remove-Item -Path "C:\logs\app.log"                      # ลบไฟล์
Remove-Item -Path "C:\logs\" -Recurse -Force             # ลบโฟลเดอร์พร้อมเนื้อหาทั้งหมด
```

ถ้าลบโฟลเดอร์ที่ไม่ว่างโดยไม่ใส่ `-Recurse` PowerShell จะ **ถามยืนยัน** (ไม่ใช่ error) `-Force` เพิ่มความสามารถลบไฟล์ที่ซ่อนหรืออ่านอย่างเดียว

**ข้อสำคัญ:** `Remove-Item` **ไม่ผ่านถังขยะ (Recycle Bin)** ต่างจากการกด Delete ใน File Explorer

### 5.2 บน Linux (Bash)

```bash
rm /var/log/app/app.log          # ลบไฟล์
rmdir /var/log/app               # ลบโฟลเดอร์ที่ว่างเท่านั้น (ถ้าไม่ว่างจะปฏิเสธ)
rm -rf /var/log/app              # ลบโฟลเดอร์พร้อมทุกอย่างข้างใน
```

`-r` (recursive) ลงลึกทุกชั้น และ `-f` (force) ไม่ถาม และข้ามข้อผิดพลาด การรวมสองตัวนี้คือชุดที่อันตรายที่สุด `rm` **ไม่มีถังขยะและไม่ถามยืนยัน** (ตามที่ต้นฉบับเตือน)

### 5.4 ชุดเครื่องมือซ้อมก่อนลบ (ที่ควรรู้)

| เครื่องมือ | ทำอะไร | ตัวอย่าง |
|---|---|---|
| `ls` / `dir` ด้วย pattern เดียวกัน | ดูขอบเขตก่อนใช้ `rm` | `ls /tmp/*.log` แล้วค่อยเปลี่ยนเป็น `rm` |
| `-WhatIf` (PowerShell) | แสดงว่าจะทำอะไรแต่ยังไม่ทำจริง | `Remove-Item C:\logs\* -Recurse -WhatIf` |
| `-Confirm` (PowerShell) | ถามทีละรายการ | `Remove-Item C:\logs\* -Confirm` |
| `rm -i` / `rm -I` (Bash) | `-i` ถามทีละไฟล์ `-I` ถามครั้งเดียวเมื่อลบมาก | `rm -ri old_logs` |
| `find ... ` ก่อน `-delete` | ดูรายการที่ตรงเงื่อนไขก่อน | `find /tmp/logs -name '*.old' -type f` แล้วต่อด้วย `-delete` |
| สำรองก่อน | เผื่อพลาด | `cp -a data data.bak` |

(`-WhatIf` เป็นความสามารถของ cmdlet ที่เปลี่ยนแปลงระบบ ในบางครั้งต้นฉบับไม่ได้พูดถึง แต่เป็นเครื่องมือหลักของผู้ดูแลระบบ Windows)

### 5.5 สิ่งที่ควรรู้เพิ่มเกี่ยวกับการลบ

- **ลบไฟล์ต้องมีสิทธิ์เขียน "ที่โฟลเดอร์แม่"** ไม่ใช่ที่ตัวไฟล์ เพราะการลบคือการแก้รายการในไดเรกทอรี (ตรงกับกลไกในหัวข้อ 1) จึงลบไฟล์ที่ตัวเองอ่านอย่างเดียวได้ถ้าเขียนโฟลเดอร์ได้ และกลับกัน
- **ไฟล์ที่เปิดอยู่:** Windows มักไม่ยอมให้ลบไฟล์ที่โปรแกรมเปิดอยู่ (error "in use") ส่วน Linux ลบได้ ชื่อหายไปทันที แต่ข้อมูลยังอยู่จนโปรแกรมปิดไฟล์ ปรากฏการณ์ "ลบ log ที่ใหญ่มากแล้วพื้นที่ดิสก์ไม่คืน" บน Linux มักเพราะโปรเซสยังเปิดไฟล์นั้นอยู่
- **กู้คืน:** ไฟล์ที่ลบจากเทอร์มินัลไม่เข้าถังขยะ ทางเดียวที่เชื่อถือได้คือ **สำรองข้อมูล** ส่วนโปรแกรมกู้ข้อมูลอาศัยที่ข้อมูลยังไม่ถูกทับ จึงอย่าเขียนอะไรลงดิสก์ต่อถ้าอยากกู้ และกับ **SSD ที่ใช้ TRIM** ข้อมูลมักถูกล้างเร็ว กู้ยากกว่าฮาร์ดดิสก์มาก
- **ลบแล้วไม่ใช่ลบจริง:** ถ้าต้องกำจัดข้อมูลลับ การลบธรรมดาไม่พอ ต้องใช้เครื่องมือเขียนทับหรือเข้ารหัสดิสก์ล่วงหน้า (หัวข้อนี้อยู่นอกขอบเขตบท)

## มุมมองด้าน Security

- **ล้างหรือแก้ log คือร่องรอยของผู้บุกรุก:** ผู้โจมตีมักลบ/ตัดไฟล์ log เพื่อลบหลักฐาน (`> /var/log/auth.log` ทำให้ log ว่างทันที) ฝ่ายป้องกันจึงส่ง log ไปเก็บที่เครื่องอื่นแบบ **ต่อท้ายอย่างเดียว** (append-only) และตั้งสิทธิ์ไฟล์ log ให้เขียนได้เฉพาะระบบ
- **`>` ผิดตัวเดียวคือเหตุการณ์ข้อมูลหายที่พบบ่อย** ทั้งโดยบังเอิญและโดยสคริปต์ที่เขียนไม่ดี ใน production ควรทดสอบสคริปต์บนข้อมูลจำลองก่อน
- **หลักสิทธิ์น้อยที่สุด:** ไม่ใช้บัญชี root/Administrator ทำงานประจำ เพราะสิทธิ์สูงทำให้ระบบไม่ปฏิเสธการลบผิดที่ ใช้ `sudo` เฉพาะคำสั่งที่จำเป็น และรู้ว่า `sudo` ไม่ครอบ redirect
- **ครอบตัวแปรด้วยเครื่องหมายคำพูดเสมอในสคริปต์:** ถ้า `f="My Old Files"` แล้วเขียน `rm $f` เชลล์จะแยกเป็น 3 ชื่อ (`My`, `Old`, `Files`) และลบทั้งสามชื่อที่อาจมีอยู่จริง ต้องเขียน `rm "$f"` (เกี่ยวกับ path จากผู้ใช้: ถ้าสคริปต์รับชื่อไฟล์จากภายนอกมาต่อเป็นพาธ ต้องกัน `../` ตามที่เรียนในบทที่แล้ว)
- **ลบไม่ใช่ลบจริง:** ข้อมูลลับต้องจัดการเมื่อทิ้งดิสก์ (เขียนทับหรือเข้ารหัสดิสก์ตั้งแต่ต้น) การลบธรรมดาไม่พอ
- **สำรองข้อมูลคือเกราะสุดท้ายของทุกความผิดพลาดใน CRUD** (ทั้งพิมพ์ผิดและมัลแวร์เรียกค่าไถ่) ควรมีสำเนาที่ถูกตัดขาดจากเครื่องที่ใช้งาน

::

::reveal{question="ทำไมการลบไฟล์ในเทอร์มินัลอันตรายกว่าการลบด้วย GUI"}
GUI ปกติย้ายไฟล์ไปถังขยะก่อนและมักมีกล่องยืนยัน ขอบเขตก็เห็นได้ชัด ส่วน `rm` / `Remove-Item` ไม่ผ่านถังขยะ ไม่ถามเมื่อเป็นไฟล์เดี่ยว และเมื่อใช้ `-r`/`-Recurse` หรือ wildcard ครั้งเดียวกินขอบเขตกว้างมาก ความผิดพลาดเล็กๆ เช่น เว้นวรรคเกินจึงลามเป็นการลบทั้งโฟลเดอร์ ป้องกันด้วยการซ้อมด้วย `ls`, `-WhatIf`, `rm -i` และมีสำรองข้อมูล
::

::reveal{question="head กับ tail ต่างกันอย่างไรเมื่อใช้ดู log"}
`head` แสดงบรรทัดแรกของไฟล์ (ค่าเริ่มต้น 10 บรรทัด) เหมาะกับดูหัวไฟล์ ส่วน `tail` แสดงบรรทัดสุดท้าย ซึ่งใน log คือเหตุการณ์ล่าสุด และมี `-f` ไว้ตามดูบรรทัดที่ถูกเขียนเพิ่มแบบสด (`head` ไม่มีความสามารถนี้) ใน PowerShell เทียบได้กับ `-TotalCount` และ `-Tail` / `-Wait`
::

::reveal{question="ทำไมการเปลี่ยนชื่อกับการย้ายไฟล์ใช้คำสั่งเดียวกัน (Move-Item / mv)"}
เพราะชื่อไฟล์ไม่ได้อยู่ในตัวข้อมูล แต่อยู่ในรายการของไดเรกทอรี การเปลี่ยนชื่อคือแก้ชื่อในรายการ และการย้ายคือนำรายการไปไว้ในไดเรกทอรีอื่น ในระบบไฟล์เดียวกันบล็อกข้อมูลไม่ต้องขยับ ทั้งสองจึงเป็นการแก้รายการเหมือนกัน (ถ้าย้ายข้ามดิสก์ต้องคัดลอกแล้วลบ จึงช้ากว่า)
::

::reveal{question="รัน sudo echo debug=true > /opt/app.conf แล้ว Permission denied ทั้งที่ใช้ sudo เกิดจากอะไร และแก้อย่างไร"}
การเปิดไฟล์ปลายทางของ `>` ทำโดยเชลล์ของผู้ใช้ปกติก่อนที่ `sudo` จะรัน `echo` ซึ่ง sudo ครอบแค่ `echo` ไม่ได้ครอบการเขียนไฟล์ แก้โดยให้โปรแกรมที่รันด้วย sudo เป็นผู้เขียน เช่น `echo debug=true | sudo tee -a /opt/app.conf` (`-a` คือต่อท้าย)
::

::reveal{question="พิมพ์ cp -r logs backup เมื่อมีโฟลเดอร์ backup อยู่แล้ว จะได้โครงสร้างแบบไหน"}
จะได้ `backup/logs` ซ้อนอีกชั้น เพราะเมื่อปลายทางเป็นโฟลเดอร์ที่มีอยู่แล้ว ตัวต้นฉบับถูกวางไว้ข้างในมัน (Copy-Item -Recurse ก็ทำแบบเดียวกัน) ควรตรวจด้วย `ls` หลังคัดลอกเสมอ
::

::reveal{question="ลบไฟล์ log ขนาดใหญ่บน Linux แล้ว df ยังบอกว่าดิสก์เต็ม เกิดจากอะไร"}
ชื่อไฟล์ถูกลบออกจากไดเรกทอรีแล้ว แต่ถ้ามีโปรเซสยังเปิดไฟล์นั้นอยู่ ระบบจะยังไม่คืนบล็อกจนกว่าโปรเซสจะปิดไฟล์ ใช้ `lsof` หาโปรเซสที่เปิดไฟล์ที่ถูกลบ แล้วรีสตาร์ตบริการนั้น สำหรับครั้งต่อไป การตัดไฟล์ให้ว่างด้วย `: > file` แทนการลบ จะคืนพื้นที่ทันทีโดยไม่ต้องรีสตาร์ตโปรเซส
::

## แบบฝึกหัด

ทำในโฟลเดอร์ทดลองเท่านั้น (Windows: `$env:TEMP`, Linux: `/tmp`) และตรวจพาธทุกครั้งก่อนลบ

**ชุด Windows (PowerShell)**

1. `Set-Location $env:TEMP` แล้วสร้างโฟลเดอร์ `lab_test` และเข้าไป
2. สร้าง `notes.txt` ข้อความ `Build 101` ด้วย `>` จากนั้นต่อบรรทัด `Passed QC` ด้วย `>>`
3. `Get-Content notes.txt` ตรวจว่ามีสองบรรทัด
4. เปลี่ยนชื่อเป็น `report.txt`
5. ถอยออกมาหนึ่งชั้น แล้วลบ `lab_test` ทั้งโฟลเดอร์ (ลอง `-WhatIf` ก่อนลบจริง)

**ชุด Linux (Bash)**

1. `cd /tmp` แล้ว `mkdir lab_test` และเข้าไป
2. สร้าง `service.log` ข้อความ `Service started` แล้วต่อ `Worker thread active`
3. ดูบรรทัดแรกด้วย `head -n 1` และบรรทัดสุดท้ายด้วย `tail -n 1`
4. คัดลอกเป็น `backup.log` แล้ว `ls -l` เทียบขนาด
5. ถอยออกมาแล้วลบ `lab_test` (ลอง `ls lab_test` ดูข้างในก่อน)

**โจทย์เสริม (ควรรู้)**

- ลองใช้ `>` แทน `>>` ในข้อสอง แล้วสังเกตว่าอะไรหาย
- ในชุด Linux ลอง `cat nofile 2> err.txt` แล้ว `cat err.txt` ดูว่าข้อความ error ไปอยู่ที่ไหน
- ลองคัดลอกโฟลเดอร์สองรอบด้วยคำสั่งเดิม (`cp -r lab_test copy`) แล้วดูโครงสร้างที่ได้ด้วย `ls -R`

## สรุป

- **CRUD** = Create, Read, Update, Delete ไฟล์ = ชื่อ (ในไดเรกทอรี) + metadata + บล็อกข้อมูล
- สร้าง: `New-Item` / `mkdir` / `touch` / `>` ระวัง `-Force` และ `>` ที่ทับไฟล์เดิม
- อ่าน: `Get-Content` / `cat`, `less`, `head`, `tail`, ตามดูสดด้วย `-Wait` / `-f`
- แก้: `>>` ต่อท้าย (ปลอดภัย) `>` ทับ (ทำลาย) เปลี่ยนชื่อ/ย้ายเป็นการแก้ไดเรกทอรี คัดลอกสร้างข้อมูลใหม่
- ลบ: ไม่มีถังขยะ ซ้อมก่อนด้วย `ls`, `-WhatIf`, `rm -i` และมีสำรอง
- เรื่องที่ต้องระวังเพิ่ม: `sudo` กับ redirect, encoding UTF-16, CRLF กับ LF, alias ของ PowerShell ที่หน้าตาเหมือนคำสั่ง Linux แต่แฟลกต่างกัน
